# 오브제 범위 수정 작업 기록

2026-09-21. 공개 가능한 정제 기록. 고객 원문·실제 경로·개인 식별자는 포함하지 않는다.

사용자는 현재 세션의 객체만 정리하는 것이 기본이어야 한다고 확정하고 바로 구현을 지시했다.
구현 도중 다른 세션의 일도 명시적으로 맡기면 함께 처리할 수 있어야 한다고 추가 지시했다.
따라서 다른 세션 금지가 아니라 기본 범위와 명시적 위임을 분리했다.

계획: 합성 두 세션 재현 → 공통 선택 계약 → 세 writer와 고정된 재개 집합 → 부분 업로드 포기 → 사용 안내·회귀 검사.
기존 운영 문서가 있는 checkout을 보존하고 최신 main에서 별도 작업공간을 만들었다.

수정: 현재 세션 기본, 특정 세션·정확한 객체 목록·단건·전체 명시 선택, 선택 집합의 계획 지문/재개 기록 바인딩.
일반 finalize로 부분 효과를 무효과 처리하지 않고, 인증된 원래 클레임과 체크포인트를 대조하여 효과 보존 포기를 추가했다.
원격 사본을 지우지 않으며 좁힌 새 계획에서 원격 동일성을 다시 검사한다.

범위 한계: 세션 자동 선택은 기록에 남은 capture 연결에 한정된다. 오래된 출처 미연결 객체와 단순 조회 객체의 소유를 추정하지 않는다.
필요하면 사용자가 위임한 정확한 목록을 쓴다. 공유 반입은 독점 소유권으로 보고하지 않는다.

검증 중 교정: 과거 전체 아카이브 테스트는 전체 선택을 명시하도록 갱신했다. 선택을 계획 지문에도 포함하여 같은 객체 집합이라도 다른 선택 계약의 재개 기록과 충돌하지 않게 했다.
전송 객체 수와 마지막 목록 투영 단계를 포함한 전체 처리 단계 수를 분리해서 표시한다.
별도 AI 검토 없이 작성자가 자체 검토했다. 고객 데이터·클라우드 자산에 접근하거나 변경하지 않았다.

검증: 저장 기능·새 범위·직전 버전 회귀·출시 문서 90개 통과. 런타임 안내/설치/리소스 검사 40개 중 39개 통과·플랫폼 조건 1개 생략.
부분 전송 중단 시험은 원격 저장소 대역에서 일부만 전송한 뒤 나머지를 실패시키고, 효과 보존 포기→좁힌 새 계획까지 확인했다.
공개 링크·한국어·개인정보·런타임 안내·writer-session coverage 5개 검사와 패키지 리소스 동기화가 통과했다.
로컬 개발 wheel을 빌드하고 별도 설치 대상의 새 프로세스에서 세 명령 선택 옵션·패키지 안내 파일을 확인했다. 설치본 실제 클라우드 종단 시험은 아니다.
이 wheel은 기존 버전 번호의 개발 빌드이며 공개 자산을 교체하지 않았다. 고객에게 배포하지 않는다.
최종 소스의 통합 로컬 실행: 130개 검사, 실패 0개, 플랫폼 조건으로 1개 생략, 나머지 129개 통과. 전체 CI·공개출시·고객 사용 확인은 별도 상태다.

CI 후속 교정: 첫 후보의 안내 원본 두 파일에 CRLF가 남아 로컬에서 만든 리소스 지문과 Git에 저장된 LF 바이트가 달랐다. CI 두 gate가 같은 manifest 불일치로 실패했다. 원본·미러를 기존 LF 규칙으로 맞추고 manifest를 재생성했다. 앞으로 이 후보 검증은 작업 폴더뿐 아니라 Git에 저장되는 원본 바이트와 manifest를 직접 대조한다.

배포 준비 재개: 사용자는 중간 보고 뒤 매번 재지시해야 하는 중단을 교정하고 고객에게 전달 가능한 배포까지 이어가라고 요청했다. v0.4.37로 메타데이터·공급 잠금·설치 안내·현재 릴리스 계약을 갱신한다. 개발 운영 자동화의 완료를 주장하지 않는다. 첫 후보 CI에서 발견된 안내 단어 수 초과, 리소스 목록 누락, 테스트 모듈 탐색 경로를 수정했다. 역사적 릴리스 내용은 보존하고 현재 버전을 확인하는 검사만 갱신했다.
