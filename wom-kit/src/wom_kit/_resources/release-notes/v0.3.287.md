# WOM-kit v0.3.287: Read-Only Notion Locator Evidence Plan

Release date: 2026-07-30

## One More Safety Rung Before Restoration

v0.3.287 adds:

```text
archive notion-import-locator-evidence-plan
```

This CLI-only planner validates a human-reviewed private JSONL evidence batch
against the exact current bytes of canonical Notion-import zets. It determines
whether explicit source URL occurrences align to current
`[source locator omitted]` markers.

It does not restore a URL.

## Why Counts Are Not Enough

The earlier locator-loss census can prove that a zet contains two omission
markers and that import metadata declared two omissions. It cannot prove which
of two source URLs belongs at the first marker.

The new evidence schema records both:

- the occurrence ordinal in the reviewed source snapshot; and
- the marker ordinal in the current canonical body.

A row aligns only when both ordinal sets are complete and unique, all three
counts agree, the private source-page join selects one current canonical zet,
and the expected canonical SHA-256 matches its exact bytes.

## Private Evidence Boundary

Evidence must be an archive-relative `.jsonl` file under:

```text
.wom-scratch/notion-locator-evidence/
```

The planner enforces bounded file, line, row, canonical-file, and total-byte
limits. It rejects traversal, drive-qualified, UNC, symlink, junction, reparse,
invalid UTF-8, invalid JSON, duplicate-key, unsupported-field, and excessive
nesting inputs without echoing private data.

The only join authority is `facets.source_page_id`. Dashed and compact UUID
forms can match; arbitrary identifiers remain case-sensitive. Titles,
filenames, `index`, external ids, other page-reference facets, and body text
never become fallback joins.

## Content-Free Result

The result can contain safe row numbers, status and blocker codes, counts, the
whole evidence-file SHA-256, and one binding `plan_digest`.

It does not return:

- source page ids or fingerprints;
- locators or locator fingerprints;
- zet ids, filenames, or paths;
- titles, body text, or surrounding context; or
- tokens, account ids, or secret values.

The planner distinguishes batch coverage from alignment quality. A fully
aligned small batch may still report `coverage_complete: false`; that means
more affected zets exist, not that their locators are permanently lost.

## Explicit Non-Goals

v0.3.287 adds no:

- canonical zet or locator writer;
- receipt or recovery executor;
- Notion API, provider, model, or network call;
- MCP tool;
- raw `recordMap`, `pages.index.jsonl`, or `properties['비고']` adapter;
- title, filename, date, or body inference;
- automatic corpus migration; or
- beta archive write.

## Verification

Release verification is planned against:

- exact source/package evidence-schema parity;
- private join authority with no title, filename, `index`, or external-id
  fallback;
- canonical SHA drift and fan-out ambiguity;
- complete unique source and marker ordinal mappings;
- BOM canonical input and one-snapshot hash/parse behavior;
- bounded path, file, line, row, URL, and JSON failure handling;
- absence of private ids, locators, aliases, titles, bodies, context, and
  paths from every result;
- output-cap aggregate completeness and archive byte-for-byte immutability;
- explicit absence from MCP; and
- complete CLI, documentation, resource, and wheel regressions.

No test count, wheel SHA-256, remote CI result, tag, GitHub release, public
artifact result, or beta archive validation is claimed before those later
steps produce their own evidence.
