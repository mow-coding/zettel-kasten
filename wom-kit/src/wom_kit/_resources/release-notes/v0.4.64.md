# WOM-kit v0.4.64 — closing out empty folders, and saying what is actually left

This answers beta letter 183. The v0.4.63 hard-link cleanup worked: five PDFs under ten paths were removed. The run still ended as partial, because the folders held thousands of empty subfolders, and the guidance read as if files were unfinished. Installing the tool alone does not change a customer archive.

## Empty folders

A request can now select no files and only close out folders.

- Use `"items": []` with `remove_empty_directory_trees` naming the exact activity folders. Use a new `activity_id`.
- Every folder of the tree is recorded at preview time. On approval, folders are removed deepest first, each only if it is the same folder and empty.
- A folder that holds a file, a link or a junction stays, together with its parent folders. That is a finished state, not a failure.
- A folder that changed or appeared after the preview is not removed.
- No file is uploaded, moved, restored or deleted.

## A `.git` with nothing in it

After an earlier cleanup removed every file of a `.git` folder, only empty folders remained, and that blocked every later preview. A `.git` without any file is no longer treated as a Git repository. If anything is left inside, the Git protections apply as before.

## What is left

The result answers three questions separately: are the selected files done, do the folders contain no files, and are the folders themselves gone. When every file is finished and only folder removal is left, the result and the recovery guidance say exactly that. Files kept on purpose, such as a protected secret configuration, are counted as kept on purpose.

The result also lists, in sentences, how long the run waited for approval and how long it processed.

## Approval windows

A preview now shows whether the process carries the conversation's three session refs. If a window opens because they are missing, the result says so. This does not mean a grant expired.

## Boundaries

Verified with synthetic files and the real command on Windows, and on Linux for the planning parts. The customer's folders are not verified. The first run's duration in letter 183 is not explained by this release.

## Install after publication

Use the exact public release asset after its hash and size are reported:

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0464-$womBootstrapNonce"
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.64/wom_kit-0.4.64-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require `archive 0.4.64` from a new process, then follow the reviewed `project-version-update` flow for an existing project.
