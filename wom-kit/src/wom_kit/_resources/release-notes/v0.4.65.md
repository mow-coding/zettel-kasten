# WOM-kit v0.4.65 — what a conversation's Git backup preview covers

This is the first part of the answer to beta letter 184. After one conversation registered 21 objets and wrote 43 zettel-objet links, the Git backup preview for that conversation said two outputs were selected and nothing more. A second preview ran for over ten minutes without saying how far it was. Installing the tool alone does not change a customer archive.

## What the preview now says

A conversation's Git backup selects a file only when an authenticated record proves the whole file is that conversation's output. The preview now explains the result in `session_backup_coverage`:

- what was selected, by kind;
- what kinds of files Git currently sees as changed, counted by role and never by name;
- which of this conversation's own approved operations are outside the selection, with counts. Objet registration and zettel-objet links are in this group today. Their changes stay uncommitted and untouched. That is not an error and nothing is lost;
- that the objet ledger is one file shared by every conversation and is left out by design;
- that the only official route for those changes is the archive-wide backup, which includes every conversation's pending changes and needs the person's agreement;
- that objet bytes are never part of a Git backup, and which commands report their remote preservation.

A small selected count is not a backup of the whole conversation.

## Long previews

The two long stages now report `current` and `total` in their progress lines. Each original is authenticated once per preview instead of twice. The preview also states that it is read-only, that interrupting it has no effects, and that there is nothing to resume.

## Not in this release

Proving that the zettels changed by this conversation's links are its own, so they can be selected, follows in the next release. The cause of the customer's 634-second second preview is not established.

## Install after publication

Use the exact public release asset after its hash and size are reported:

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0465-$womBootstrapNonce"
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.65/wom_kit-0.4.65-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require `archive 0.4.65` from a new process, then follow the reviewed `project-version-update` flow for an existing project.
