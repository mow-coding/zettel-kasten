# WOM-kit v0.4.44 — Superseded IMAP chain removed, Notion location recovery revived, grants until released

Three owner decisions of 2026-09-25. A feature replaced by a better one is removed, not kept closed; a broken feature with no replacement is revived; and a session grant that skips approval windows lasts until it is released. Installing the tool alone does not change a customer archive; use the reviewed `project-version-update` flow for a project.

## Removed: the superseded IMAP planning chain

The v0.3.19 to v0.3.72 IMAP commands prepared a future adapter step by step. They covered source planning, operation requests, readiness, selection, the manifest, audits, preflight, the execution contract, the header scan, material selection and capture approval. The live header scan was closed since v0.4.0 and the capture step was never built. `imap-mailbox-message-fetch` (v0.4.42) together with `source-intake-batch` now does that whole job, so 18 commands, their 33 aliases and 7 MCP previews are removed. Receipts written by them stay readable as plain JSON.

For email: `add-source --type imap_mailbox`, then `imap-mailbox-message-fetch --dry-run` and `--approve`, then `source-intake-batch --manifest <written request>`. See `wom-kit/docs/imap-mailbox-source.md`.

## Revived: `notion-recover` (Notion parent locations)

`notion-recover` restores the missing parent locations of nested Notion pages in the reviewed tree fixture. Nothing current did that: page recovery fetches only the bodies of listed pages. The command runs again with the adopted Notion credential, which is the `credential-lifecycle` default or `--credential-id`.

- `--dry-run` plans the parent-link reads and prints a `plan_sha256`. It reads no credential value and calls no provider.
- `--approve` runs after one exact approval: a dialog, or none under a valid session grant.
- It reads only parent links (object kind, id, parent and trash flags), never titles, bodies, comments or media.
- The token exists only in a spawned child process.
- Output: `workbench/notion-ancestor-result.live.json` (never overwritten) and a receipt. `notion-ancestor-merge-plan` previews where the pages belong.
- The old token options (`--credential-ref`, `--yes`, `--platform`, `--notion-version`, `--timeout-seconds`, `--source`) are gone.

## Session grants last until released

A `limited` or `allow_all` grant set with `work-session --action set-permission-mode --approve` no longer expires after 8 hours. It lasts until you release it with `set-permission-mode manual` or `recover`, or until the session is paused, handed off or completed. A request can still name `grant_hours` (1 to 24) for a time-boxed grant. The grant still works only in the conversation that received its approve result.

## Still closed

Six commands stay fixed closed: the five ZET sharing and ownership commands planned for v0.5 (`delegate-zet`, `transfer-ownership`, `quarantine-foreign-block`, `record-quarantine-decision`, `github-repo`), plus cancelling an operation with `operation-control`. `wom-kit/docs/closed-command-tracker.md` lists them. Validation used synthetic data and a fake Notion; a customer's own run must be confirmed separately.

## Install after publication

Use the exact public release asset after its hash and size are reported:

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0444-$womBootstrapNonce"
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.44/wom_kit-0.4.44-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require `archive 0.4.44` from a new process, then follow the reviewed `project-version-update` flow for an existing project. A bootstrap installation alone does not update its pinned runtime.
