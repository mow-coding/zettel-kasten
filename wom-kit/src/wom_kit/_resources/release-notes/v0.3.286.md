# WOM-kit v0.3.286: Manual-Only `format_variant` Edge Activation

Release date: 2026-07-30

## One Narrow Relationship-Model Activation

v0.3.286 activates one WOM-local base link type:

```text
format_variant
Zettel -> Zettel | OriginalObject
```

Use it only after a human reviews both records and decides that the target is
an alternate format or rendition of the same intellectual content as the
source anchor.

This is a vocabulary and manual-write activation, not an automatic matching
feature. The existing connection edge intelligence surface can now report
`format_variant` as an active mapping, but it does not recommend or create
that relation from metadata.

## Direction Means Review Anchor, Not Historical Priority

The source is simply the record that the reviewer chose as the review anchor.
The stored direction does not claim that the source is:

- older;
- the original;
- canonical; or
- more authoritative than the target.

WOM's `format_variant` is conceptually close to DCMI
[`hasFormat`](https://www.dublincore.org/specifications/dublin-core/dcmi-terms/terms/hasFormat/)
and
[`isFormatOf`](https://www.dublincore.org/specifications/dublin-core/dcmi-terms/terms/isFormatOf/).
It is deliberately not declared to be an exact mapping to either directional
property. DCMI's pair distinguishes direction through the pre-existing
described resource, while the evidence available to this WOM workflow does
not establish that historical fact.

One reviewed source-to-target assertion is enough. Do not add a second
reciprocal edge automatically.

## Archive Adoption

An archive with no local `zettel-kasten/types.yml` already inherits the
installed WOM-kit base vocabulary. It needs no migration.

An archive that vendors its own `zettel-kasten/types.yml` shadows the base and
must explicitly adopt missing base records through the existing sync:

```powershell
archive migrate <archive-root> `
  --target base-link-types `
  --dry-run --format json
```

Review `appended_link_type_ids` and `present_not_overwritten`. If the preview
is correct:

```powershell
archive migrate <archive-root> `
  --target base-link-types `
  --approve `
  --reviewed-by <safe-reviewer-id> `
  --format json
```

The adoption contract remains:

- append every missing base link-type record;
- never remove, rename, reorder, or overwrite an existing same-id record;
- report an existing same-id record under `present_not_overwritten`;
- write no edge and edit no zet;
- perform a safe no-op when no local `types.yml` exists or nothing is missing;
  and
- provide no `base-link-types` revert.

The approved sync normalizes the full YAML document through the existing
serializer. Comments, anchors, flow style, and key ordering can therefore
change even though existing records remain equal by value. Review the
preview, result, and repository diff before committing the private archive.

The narrower recommended-9 `link-types-v0.3` migration and its receipt-backed
revert remain unchanged. `format_variant` is adopted through
`base-link-types`, not by expanding or retroactively changing that older
recommended set.

## Existing Manual Edge Flow

Preview one human-selected pair through the existing single-edge writer:

```powershell
archive zettel-edge <archive-root> `
  --from-zettel <review-anchor-zet> `
  --target <alternate-zet-or-objet> `
  --edge-type format_variant `
  --visibility private `
  --dry-run `
  --format json
```

After a human verifies both records, the relationship meaning, the target,
the visibility, and the chosen direction, approve the current operation:

```powershell
archive zettel-edge <archive-root> `
  --from-zettel <review-anchor-zet> `
  --target <alternate-zet-or-objet> `
  --edge-type format_variant `
  --visibility private `
  --approve `
  --reviewed-by <safe-reviewer-id> `
  --format json
```

The existing writer still records exactly one typed edge in the source
zettel, updates that zettel's `updated_at`, and writes one immutable
`receipts/edges/*.zettel-edge.json` receipt. Duplicate `type + target` edges
remain blocked.

The policy-batch writer cannot bypass pair-level review. A
`zettel-edge-batch` row whose type is `format_variant` is always returned in
`human_review_queue` with `manual_single_edge_review_required`, even when the
policy lists it under `auto_write_edge_types`, gives it high confidence, and
does not set `requires_human_review`. The batch dry-run and approval paths do
not write that row.

No new edge writer is introduced in this release.

## Existing Revert And Read Paths

The existing receipt-backed compensation path applies without special
`format_variant` behavior:

```powershell
archive revert-edge <archive-root> `
  --receipt receipts/edges/<edge>.zettel-edge.json `
  --dry-run `
  --format json
```

After reviewing the preview, use the same command with
`--approve --reviewed-by <safe-reviewer-id>`. The revert preserves the
original write receipt and creates a separate immutable revert receipt.

The generated index remains the disposable read model. Once it is current,
the existing bidirectional reader can find a `Zettel -> Zettel` relation from
either zettel endpoint:

```powershell
archive related-zets <archive-root> `
  --zettel-id <zet-id> `
  --edge-type format_variant
```

That bidirectional query does not mean two reciprocal canonical assertions
were written. It is a read convenience over one reviewed stored edge.

`related-zets` takes a zettel id. When a `format_variant` edge targets an
`OriginalObject`, this release does not make that object id a query subject;
object-endpoint lookup is outside this activation.

## Compatibility And Explicit Non-Goals

Existing zets, edges, receipts, and local type customizations remain
authoritative and untouched unless an operator explicitly approves an
existing write path.

This release does not:

- infer `format_variant` from a title, filename, extension, node category,
  object kind, provider mechanism, model output, or body similarity;
- reclassify an existing `references`, `semantic`, `derived`, `embed`, or
  other edge;
- scan or migrate an existing corpus;
- create an automatic reciprocal edge;
- assert which resource is older, original, canonical, or historically
  pre-existing;
- map the WOM-local direction exactly to DCMI `hasFormat` or `isFormatOf`;
- read a Notion export, provider mirror, remote API, or object body to decide
  the relation;
- call a provider, model, network, or credential store;
- add a source-specific parser or provider-specific edge rule;
- write to a beta tester's private archive as part of release construction;
  or
- add an MCP edge writer.

Human review remains the only authority that activates one concrete
`format_variant` assertion.

## Verification

Release verification is planned against:

- source, fake-archive, and packaged-resource type-model parity;
- `Zettel -> Zettel | OriginalObject` type shape and policy notes;
- active connection-meaning classification without an inference rule;
- manual single-edge dry-run and approval behavior;
- absence of an automatic reciprocal edge;
- existing receipt-backed single-edge revert behavior;
- append-only `base-link-types` adoption and custom same-id preservation;
- unchanged recommended-9 `link-types-v0.3` behavior;
- generated-index-backed bidirectional `related-zets` behavior for
  `Zettel -> Zettel` edges, without object-endpoint query claims;
- package version, release-note, and resource-manifest consistency; and
- full CLI regression behavior.

No test count, wheel SHA-256, remote CI result, tag, GitHub release, or beta
archive validation is claimed before those later steps produce their own
evidence.
