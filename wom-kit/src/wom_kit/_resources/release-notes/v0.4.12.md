# WOM-kit v0.4.12 — Generation-Bound Link Authority and Honest Index Lifecycles

v0.4.12 replaces repeated whole-archive link discovery with one generated,
generation-bound authority and makes supported writers keep that authority
truthful. A fast result is accepted only when it preserves the same identity,
duplicate, path-safety, manifest, approval, and Windows stable-point checks as
the earlier bounded resolver.

## What changed

- **`zettel-objet-link` uses a generation-bound authority projection.** The
  current SQLite index binds the exact live zet path/stat set, strict zet IDs,
  exact manifest descriptor generation and SHA-256, and only the matching
  manifest rows needed by the reviewed target. Planning fails closed if the
  index, live tree, manifest, duplicate-ID proof, or Windows watcher evidence
  drifts. The public result remains content-free.
- **`already_present` is deterministic.** An exact existing link returns the
  fixed `already_present` state repeatedly without opening approval or writing
  canonical, snapshot, receipt, manifest, checkpoint, or index bytes. It does
  not mean that a merely similar or semantically related link exists.
- **Supported indexed writers use one same-generation delta-or-dirty
  lifecycle.** After approval and target/CAS revalidation, the writer commits
  one durable dirty intent before the first canonical zet or Objet-manifest
  write. A successful single or batch operation applies its exact row, edge,
  facet, or manifest-projection delta and seals that same generation only after
  live-tree and manifest revalidation. Interruption, partial durable effects,
  or delta failure remains `dirty` and returns
  `archive_index_rebuild_required`; it is never reported as success. Resume
  may continue only against the same dirty generation, and an exact rollback
  reseals only when the complete live state proves the rollback.
- **`current` is a stable-point observation, not a source freeze.** A clean
  watcher close is the authority linearization point: it proves the indexed
  sources at that instant. It does not claim that another process cannot edit
  those sources after that point or before the command response is delivered.
  Every authority-dependent consumer therefore runs a fresh
  `require_current_zettel_index` check before it relies on `current`.
- **Missing or stale authority blocks before write.** An indexed zet or
  manifest writer with neither a current index nor a resumable same-generation
  dirty index stops before native approval, canonical or manifest mutation,
  execution locator, checkpoint, or final receipt. WOM does not silently fall
  back to a whole-tree write path.
- **The public parser and runtime authority agree.** The current command
  inventory has `315` canonical parser paths: `47` approval-available, `67`
  approval-fixed-closed, and `201` approval-not-exposed. Nine of the 47
  available paths are conditional exact-authority paths. Parser, help,
  structured status, runtime dispatch, and fixed-close tests use the same
  truth; a useful read-only preview still does not imply a writer exists.

## Exact Windows performance evidence gate

The v0.4.12 tag and GitHub Release are created only after the public
[Windows reference evidence](https://github.com/mow-coding/zettel-kasten/blob/v0.4.12/wom-kit/docs/evidence/v0.4.12-link-index-windows-reference.json)
has schema `wom-kit/v0412-link-index-benchmark/v0.2` and is regenerated from
the final release candidate. The superseded v0.1 callback-timing result is not
release authority.

The v0.2 benchmark still uses `8,616` zets, `22,441` Objets, and a
`38,797,312`-byte (`37.0 MiB`) manifest. In addition to cold and warm p95, it:

- captures the actual serialized stderr progress stream rather than timing the
  formatter callback;
- measures the first non-empty stream `write`, its first `flush`, and the
  maximum gap between flushed progress events;
- scans that captured stream and the final JSON for the private sentinel, zet
  IDs, Objet IDs, and absolute paths without publishing the private values;
- binds the result to SHA-256 values for the package source tree, Git commit
  object, benchmark script, exact wheel bytes, and wheel package tree; and
- executes an exact captured benchmark driver and imports production modules
  only from a private runtime materialized from the captured wheel bytes;
- accepts full-profile release evidence only when the source tree and benchmark
  script match the recorded commit and the wheel package tree exactly matches
  the measured source tree; and
- recomputes the complete provenance document after the measurements so a
  source, commit, script, or wheel change during the run fails the gate.

The final v0.2 evidence must also show `0` legacy full-zet resolver calls, `0`
full-manifest JSON parser calls, exactly one target manifest row returned and
two target-bound membership JSON parses per plan, first serialized write and
flush no later than two seconds,
and a maximum serialized flush gap no longer than ten seconds. The generated
evidence, rather than a prose claim or the retired v0.1 numbers, is the
benchmark authority.

## Human and AI operating boundary

Publishing or installing v0.4.12 does not open, index, recover, or otherwise
modify a client archive. Release development and performance verification use
synthetic archives and isolated installed-wheel checks. No provider call or
client-data recovery is performed by the release itself.

After the intended project has been updated to the verified v0.4.12 wheel, the
AI uses that project's `.zettel-kasten/bin/archive.cmd` launcher and performs
the existing explicit index lifecycle before retrying an indexed write:

```powershell
.\.zettel-kasten\bin\archive.cmd index <archive-root> --progress --format json
.\.zettel-kasten\bin\archive.cmd index-health <archive-root> --dry-run --progress --format json
```

WOM and the AI verify generation, counts, hashes, live-tree completeness,
manifest identity, and health output. The person does not count zets or Objets,
compare hashes, or reconstruct canonical state. The person is asked only for
the genuinely human decision presented by the exact approval surface after the
machine gates pass.

## Deliberate limits

The generated index remains a rebuildable projection, not the archive
canonical source. Fixed-closed commands remain fixed closed. In particular,
`zet-revision-restore-proposal-from-snapshot --approve` and the standalone
command path `derive-text capture --approve` stop before private inputs are
read. The paired derived-text handling inside the separately approved
`objet-capture-batch` route is not that command. Their dry-run previews do not
grant authority. v0.4.12 does not infer weak
links, merge ambiguous identities, automatically repair a client archive, call
an external provider, or treat a release URL, version string, read-only preview,
or `already_present` state as proof of unrelated work.

## Install contract

After the matching GitHub Release exists and lists the wheel, install that exact
public artifact in a temporary bootstrap or isolated tool environment:

```powershell
uv tool install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.12/wom_kit-0.4.12-py3-none-any.whl"
archive --version
```

The new process must report exactly `archive 0.4.12`. The URL and version alone
do not prove that the release asset exists or passed independent verification.
