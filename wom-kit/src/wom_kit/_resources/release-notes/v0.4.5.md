# WOM-kit v0.4.5 — Windows Native Approval Hotfix

v0.4.5 fixes a release-blocking defect found by exercising the public v0.4.4
wheel in a clean Windows project runtime. The machine verification completed,
but `TaskDialogIndirect` returned `E_INVALIDARG` before the approval window
could appear. No approval claim, checkpoint, receipt, or archive field was
written.

## What changed

- WOM now activates the Common Controls v6 side-by-side assembly on the calling
  thread before loading and invoking the task-dialog API.
- The `TASKDIALOG_BUTTON` and `TASKDIALOGCONFIG` ctypes definitions now use the
  one-byte packing required by `CommCtrl.h`. On 64-bit Windows the corrected
  sizes are 12 and 160 bytes; the former default alignment produced 16 and 176
  bytes and caused the native API to reject the configuration.
- The temporary activation manifest contains only the fixed Microsoft Common
  Controls assembly identity. WOM removes its source file immediately after
  `CreateActCtxW` parses it, then deactivates and releases the context after the
  dialog closes.
- Radio-button and verification-checkbox output pointers remain null because
  the human decision surface contains neither control.

Microsoft documents that Task Dialogs require `Comctl32.dll` version 6 and that
an activated context redirects the current thread to versioned window classes:
[TaskDialogIndirect](https://learn.microsoft.com/en-us/windows/win32/api/commctrl/nf-commctrl-taskdialogindirect),
[TASKDIALOGCONFIG](https://learn.microsoft.com/en-us/windows/win32/api/commctrl/ns-commctrl-taskdialogconfig),
and [ActivateActCtx](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-activateactctx).

## Human boundary remains unchanged

This hotfix does not restore the v0.4.3 verification checkbox or make the
person inspect counts, hashes, canonical state, or internal codes. WOM still
performs those checks. The person sees the plain operation effect and chooses
only the specific action button or safe cancel. Technical bindings stay under
collapsed details and in durable receipts.

The hotfix also does not mark Letter 138 resolved. Real client data remains
unchanged until the client runs the released project-scoped command or
explicitly delegates it, and completion still requires the durable receipt and
independent verification.

## Install contract

After the matching GitHub Release exists, install the exact public artifact in
an isolated tool or project runtime:

```powershell
uv tool install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.5/wom_kit-0.4.5-py3-none-any.whl"
archive --version
```

The version check must report `archive 0.4.5`. The versioned URL alone is not
proof that the release asset exists.
