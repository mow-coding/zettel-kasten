# WOM-kit v0.3.307

Exact-root, cross-platform legacy coordination preview with Windows-only
approved cleanup.

## Added

- added CLI-only `archive legacy-coordination-cleanup
  <absolute-workspace-root> --dry-run|--approve` for the direct
  `.mow-harness/` child of one human-selected workspace; dry-run is
  cross-platform and approved mutation is Windows-only in v0.3.307;
- added a content-bound plan whose dry-run output contains only aggregate file,
  directory, and byte counts plus `plan_sha256`, without filenames, contents, or
  absolute paths;
- added approval gates for the exact reviewed plan, safe reviewer,
  workspace-owner authority, external-writer quiescence, and explicit retired
  state disposal;
- added a separate backups-and-receipts disposal affirmation when those bytes
  are present;
- added fail-closed handling for unknown or case-drifted targets, tracked data,
  links, junctions, Windows reparse points, named alternate data streams,
  cross-mount entries, prior cleanup residue, unsafe Git environment, special
  or unreadable entries, bounded-scan exhaustion, and changed filesystem state;
- added checks against every ancestor Git index, with any nested `.git` entry in
  the target rejected without traversal;
- added Linux `mnt_id` cross-mount evidence and Windows in-place,
  retained-handle disposal for exact approved files and empty directories; and
- added Windows handles that retain every workspace ancestor and the root for
  the complete approved operation.

## Safety Boundary

- the command never searches for retired installations and is not called by
  Doctor, archive discovery, restore, installation, project update, or upgrade;
- `collab/` is never traversed or changed;
- POSIX dry-run writes nothing and reports `approval_platform_supported: false`
  plus `safe_to_cleanup: false`; POSIX approval blocks before lock acquisition or
  mutation because standard POSIX lacks atomic expected-inode deletion;
- approval changes only the exact unchanged direct-child tree reviewed in the
  dry-run and is available only on Windows in this release;
- WOM creates no backup or cleanup receipt and performs no automatic retry;
- WOM creates no new tombstone rename; an old tombstone remains a blocker;
- dry-run distinguishes `dry_run_ready`, `target_absent`, and `blocked`, while
  approved completion reports `cleanup_completed`;
- any partial or uncertain outcome after the first mutation reports
  `partial_cleanup_pending`, which is incomplete and must never be reported as
  success; WOM performs no automatic retry, resume, or rollback; and
- this is filesystem-entry cleanup, not secure media erasure.

The v0.3.306 retirement remains in force. v0.3.307 adds no external-tool
dependency, recommendation, activation, update path, MCP writer, receipt parser,
UI, provider/network call, archive migration, or zet/objet/index mutation.

## Compatibility

Additive CLI behavior. Existing v0.3.306 archives require no migration. The
defensive `/collab/` and `/.mow-harness/` quarantine rules remain active even
when the retired directory is absent.

and the [v0.3.307 decision](https://github.com/mow-coding/zettel-kasten/blob/main/wom-kit/docs/archive-infra-decision-log-2026-08-08-v03307-legacy-coordination-cleanup.md).
