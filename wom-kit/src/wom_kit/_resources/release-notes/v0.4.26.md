# WOM-kit v0.4.26 — Target Details Page Navigation

v0.4.26 is a hotfix for the native approval dialog's "대상 자세히 보기" button
(the count-first paged target preview of v0.4.20). On Windows 11 the button
closed the dialog instead of opening the read-only target list, and the
command then failed as `exact_human_approval_native_call_failed`, so the
person saw the window vanish and the AI client saw a native failure. Both
are reproduced on a real dialog and fixed here. No approval contract, plan
digest, receipt schema or journal schema changes.

Publishing or installing this release does not read or modify a client
archive. A client chooses when to run the exact public bootstrap and one
reviewed `project-version-update` to the public wheel
`wom_kit-0.4.26-py3-none-any.whl`. The release is not evidence that a client
result was repaired; that requires the client-run result and a new-process
verification.

## The defect

The paged target preview swaps the dialog's page with the Windows task
dialog's navigation call and, by design, trusts a page only after the dialog
confirms it (`TDN_NAVIGATED`); until then every button except cancel is
inert, so authority can never leak through a half-built page. v0.4.20
through v0.4.25 required that confirmation to arrive **inside** the
synchronous navigation call. On Windows 11 (build 26200 verified) the dialog
delivers the new page's construction notice inside the call but posts the
confirmation through the message loop afterwards; the code read the missing
confirmation as a failed navigation, cancelled the dialog itself and raised
`exact_human_approval_native_call_failed`. Every test used a fake dialog
that confirmed synchronously, so the real ordering was never exercised.

## The fix

A pending navigation is no longer a failure: the page stays inert for every
button except cancel until the confirmation arrives, and a click that lands
in that window is refused, not lost as an error. A dialog destroyed while a
navigation is pending is still a failure. Verified on a real dialog:
"대상 자세히 보기" opens the list page (`대상 자세히 보기 · 1/N`, `이전`,
`다음`, `승인 화면으로 돌아가기`), returning restores the approval page, and
approve and cancel behave as before. `tests/test_v0420_target_collection_preview.py`
now models both orderings (confirmation inside the call, confirmation
deferred) and the never-confirmed case.

## Observed, not changed

The approval dialog is owned by whatever window was in the foreground when
the command started (usually the AI client's window). Minimising that window
hides the dialog with it; restoring it brings the dialog back. Recorded for
a later release.
