# WOM-kit v0.4.42 — Keep whole mail messages with their attachments

Beta letters asked to keep whole mail, not only headers. The header scan could never run (its legacy approval receipt no longer exists) and would not have met the request. This release adds `imap-mailbox-message-fetch`, which keeps each selected message byte for byte, attachments included, under one exact approval: one native dialog, or none under a valid `limited`/`allow_all` session grant. Installing the tool alone does not change a customer archive; use the reviewed `project-version-update` flow for a project.

## IMAP full-message fetch

- Register the mailbox once with `add-source` (source type `imap_mailbox`), then put the account name and an app password in two environment variables.
- `imap-mailbox-message-fetch <archive> --source-id <source> --batch-id <id> --imap-host <host> --username-ref env:NAME --app-password-ref env:NAME --dry-run` prints a `plan_sha256`. It reads no credential and opens no connection.
- `--approve --reviewed-by <you>` fetches after one approval. The mailbox is opened read-only and bodies are fetched with `BODY.PEEK[]`, so no message is marked as read. Each message is written as `workbench/imap-fetch/<batch>/mail-NNNN.eml`, with a ready `source-intake-batch-request.json` and a content-free receipt under `receipts/imap-message-fetch/`.
- Next, `source-intake-batch <archive> --manifest <that request> --dry-run` captures the files as objets under its own approval.
- `--selection-rule newest_first|oldest_first|unread_first|since_days_window` and `--max-messages` (up to 1,000 per run) choose the messages. Headers, subjects, addresses, bodies, the host and the credential values are never printed.

## Still closed

Eight commands stay fixed closed: the five ZET sharing and ownership commands planned for v0.5, `imap-mailbox-header-metadata-scan` (superseded by the fetch; its removal waits for the owner), the legacy `notion-recover`, and `operation-control`. `wom-kit/docs/closed-command-tracker.md` lists each one. Validation used synthetic development data and a fake IMAP server; a customer update and successful use must be confirmed separately.

## Install after publication

Use the exact public release asset after its hash and size are reported:

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0442-$womBootstrapNonce"
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.42/wom_kit-0.4.42-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require `archive 0.4.42` from a new process, then follow the reviewed `project-version-update` flow for an existing project. A bootstrap installation alone does not update its pinned runtime.
