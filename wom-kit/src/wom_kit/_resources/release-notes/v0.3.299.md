# WOM-kit v0.3.299

Release date: 2026-08-04

## Observed source coverage and recorded storage evidence

- Added CLI-only, read-only
  `python -B -m wom_kit.archive_cli source-reference-coverage-audit
  <archive-root> --dry-run`. It traverses valid current `source_refs` rows and
  exact Notion `[source locator omitted]` markers in canonical files under
  `zettels/`.
- Kept observed-population completion separate from archive-wide
  completeness. The result always reports that an exhaustive archive-wide
  source population authority is unavailable and never promotes a complete
  observed scan into a zero-loss claim.
- Classified source-reference coverage and local recorded storage evidence on
  independent axes. Object-manifest identity is not byte proof; only an exact
  linked provider execution receipt accepted by the existing backup-evidence
  validator becomes recorded-time evidence.
- Added stable regular-file and directory traversal checks, duplicate zettel
  identity and manifest detection, deterministic bounded ordinal detail,
  exact full-population aggregates, and closed completion/incomplete/blocked
  exit semantics.
- Added a closed Draft 2020-12 result schema plus pure semantic invariants.
  The command consumes no generated-index row, opens no object bytes, writes
  no file, and calls no network, provider, credential store, external store,
  MCP tool, or UI.

## Claim boundary

This release audits only source occurrences that current public canonical WOM
can directly enumerate. It does not claim exhaustive knowledge of every
external source attachment, current local or remote byte availability, live
storage integrity, or whole-archive backup health.
