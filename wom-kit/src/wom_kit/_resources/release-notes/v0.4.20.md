# WOM-kit v0.4.20 — Session-Owned Writes And Draft Promotion

v0.4.20 gives archive writes a work-session identity, adds selective Git
backup of authenticated session outputs and whole canonical documents, and
fixes two v0.4.18 defects that left drafts unmintable. It does not open the
remaining approval-closed commands; the writer-session coverage gate now
reports exactly which paths are integrated, pending or exempt.

Publishing or installing this release does not read or modify a client
archive. A client chooses when to run the exact public bootstrap and one
reviewed `project-version-update` to the public wheel
`wom_kit-0.4.20-py3-none-any.whl`. The release is not evidence that a client
result was repaired; that requires the client-run result and a new-process
verification.

## Conditional public artifact contract

Use this bootstrap only after the exact GitHub Release exists and lists the
wheel. The versioned URL alone is not proof that the asset is public.

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0420-$womBootstrapNonce"
if (Test-Path -LiteralPath $womBootstrapRoot) {
  throw "WOM bootstrap path must be new."
}
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.20/wom_kit-0.4.20-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require exactly `archive 0.4.20` from a new process. Installing this external
bootstrap does not replace a shared PATH tool or silently update any project.

## Drafts stay mintable after WOM's own writes (letters 159 and 160)

- `zettel-edge` write and revert re-serialize a zettel with its exact body
  suffix, keeping the blank separator line that `create-draft` writes.
- The mint verifier treats a missing separator produced by an earlier rewrite
  as a normalization, not as `source_fidelity_draft_body_separator_invalid`;
  the approved body digest is unchanged and a damaged boundary still blocks.
- Linking the draft's declared fidelity source object as an asset is allowed:
  that one `assets[].object_id` is not private authority exposure. Any other
  spelling of the object id, and every source digest, still blocks mint.
- A blocked `create-draft --dry-run` returns null `approval_replay` values and
  stage `blocked`; a blocked text-mode `--approve` prints the fixed reason code
  and the bounded dry-run blockers instead of one opaque line.
- Blocked `zettel-edge` results carry a closed `detail_reason_code`.
- Exact `objet-capture-selection --approve` returns `selection_path` and
  `files_written` (a digest-named archive-internal receipt path).
- `--fidelity-source-object-id` documents its UTF-8 text requirement and the
  `source_fidelity_source_not_utf8` blocker carries `next_safe_actions`.

## Work sessions and session-owned writes

- `work-session` registers apps, creates, claims, pauses, resumes and hands
  off work sessions through exact native approval; every operation is an
  exact-manifest transaction with retained original context.
- `source-intake-record`, `source-intake-batch`, `zet-title-remap-write` and
  `git-backup-reconcile-plan` accept `--client-app-ref`, `--task-route-ref`
  and `--work-session-ref`. Session-owned writes keep a private control that
  binds the original plan, establishment, actor generation and native context;
  resume, explicit original review and completed replay reuse it without a
  new approval window. Unrelated app registration does not block resume.
- Session title recovery records whole canonical document preimages and
  postimages under the held writer lock; the file CAS refuses writes whose
  observed input or replacement bytes differ from the approved images.
- The `zet_title_remap_write` MCP tool joins the same session dispatcher
  (preview, apply, resume and explicit original review); MCP tool definitions
  increase from 136 to 137 with unchanged command spellings.
- `zet-title-remap-write --revert-recovery` with session refs compensates the
  session's completed title recovery as a new natively approved apply over the
  fields still at the approved value; later unrelated edits survive and a
  completed compensation reports `already_reverted`.
- Session decisions and local recovery approvals show a count-first paged
  target preview (20 items per page, current title or filename, no paths)
  with a live target-binding observer.

## Selective Git backup with authenticated ownership

- The session Git backup selects only changes it can attribute: the session's
  own authenticated completion receipts, completed intake outputs, and
  canonical zettel documents changed by a completed session title recovery.
- A modified document is owned only when the original recovery authenticates,
  HEAD holds the approved preimage, the worktree holds the approved postimage,
  the index equals one of them and the current file still matches. Later body
  edits, foreign index entries, renames, superseded recoveries and unknown
  files stay `ownership_unverified` and are excluded from the commit.
- Commit and push are non-force; the remote ref is verified independently;
  completed replay never creates a second commit.

## Writer-session coverage gate

`tools/check_writer_session_coverage.py` compares the parser's approval-available
paths with `docs/writer-session-coverage.json` on every release readiness run:
6 paths integrated, 21 pending with a train release target, 20 documented
legacy exceptions of 47. It fails on unclassified, stale or misclassified
paths and never reports all-writer coverage while paths are pending.

## Compatibility and privacy

- Existing controls, approvals, receipts and Git session scopes (v1/v2) keep
  their exact bytes and validators; the new Git scope schema v3 is used only
  when a document proof is present.
- The public projections of session results carry fixed names, counts and
  booleans, never private values or paths; the one new path field is the
  digest-named selection receipt of the exact selection command.
- No credential value, provider identifier, archive path, client label or
  target content is introduced into public tests or release artifacts.

## Not in this release

Session integration of the 21 pending approval paths, generic ownership of
locator/ledger/index outputs, one-approval intake chains (letter 160 ⑦),
draft discard and batch reopenings (v0.4.21), credential continuity
(v0.4.22), remote retention (v0.4.23) and cleanup/relations (v0.4.24).

## Verification boundary

The release candidate must pass the focused session, recovery, Git, fidelity,
privacy, package-resource, installed-wheel and full supported-platform CI
checks. The exact reviewed merge commit must be tagged, and the public wheel
must be downloaded anonymously, rehashed, installed in a fresh CPython 3.12
environment and checked in a new process. Those steps prove the public
release; they do not prove a client result.
