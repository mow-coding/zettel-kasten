# WOM-kit v0.3.313

Source fidelity and private verbatim preservation before AI-authored archive
writes.

Status: v0.3.313 implementation and release scope. The source implementation
and local focused tests are complete in this worktree. This note does not prove
merge, external CI, exact tag, GitHub Release, packaged wheel publication,
fresh installation, real-archive execution, external sharing, or human
acceptance.

## Added

- three closed source-fidelity modes for new AI drafts: `verbatim`,
  `faithful_summary`, and `sanitized_derivative`;
- one manifested local content-addressed objet as the durable source authority;
- dry-run body and source-fidelity plan digests, followed by an attributed
  human-approved exact replay before the first AI-authored draft write;
- a create-only private source-fidelity draft receipt containing the full local
  verification authority; and
- mint-time re-verification of the current source and raw draft body, bound to
  the current reviewed source-fidelity plan.

## CLI contract

New AI draft previews use these source-fidelity arguments in addition to the
existing title, body, abstract, facet, archive identity, and provenance inputs:

```text
--source-fidelity <verbatim|faithful_summary|sanitized_derivative>
--fidelity-audience <audience>
--fidelity-source-object-id <sha256:...>
--dry-run
```

The unchanged live replay also requires:

```text
--approve
--draft-approved-by <human-actor>
--expected-body-sha256 <sha256>
--expected-source-fidelity-plan-sha256 <sha256>
```

`mint-zet --dry-run` returns the current safe fidelity plan evidence. Its
approved replay requires the current
`--expected-source-fidelity-plan-sha256` together with the existing
`--reviewed-by` and `--approve` gates.

Existing AI drafts receive no inferred historical mode. Their compatibility
path is the attributed `--affirm legacy_source_fidelity_reviewed` mint review.
That affirmation does not claim retrospective verbatim proof.

## MCP contract

`create_draft_zettel` remains an AI-assisted dry-run by default. It accepts the
matching fields `source_fidelity_mode`, `source_fidelity_audience`,
`fidelity_source_object_id`, `approved`, `draft_approved_by`,
`expected_body_sha256`, and
`expected_source_fidelity_plan_sha256`. The MCP server binds its own AI runtime
identity and rejects a caller's attempt to spoof the human-written route.

The MCP `mint_zettel_check` surface remains preview-only. It can expose the safe
current plan digest but is not a live mint writer.

## Compatibility and intentional break

- Human-written legacy draft creation remains compatible.
- Every new AI-assisted or AI-generated draft now requires the explicit
  source-fidelity and human-approval replay. Older AI automation that performed
  a live create without those inputs intentionally fails closed.
- Declared AI `created_by`, `assisted_by`, or non-empty `local_ai_sessions`
  evidence cannot downgrade to a human or absent creation mode; it is rejected
  as `ai_provenance_requires_ai_creation_mode`.
- Existing zets, drafts, receipts, and objets are not migrated or rewritten.

## Private verbatim and secret boundary

`verbatim` is allowed only for a personal archive with `private_self` audience.
Its `utf8_newlines_lf` comparison converts CRLF and lone CR to LF and performs
no trimming, final-newline collapse, Unicode normalization, case change, or BOM
removal. Because newline conversion is possible, it is explicitly not
byte-exact.

Names, contact details, dates, and conversation order are private personal data
and are not silently masked under an explicit private verbatim request.
Credential secrets such as passwords, API keys, private keys, and bearer tokens
block before writing.

## Receipt and public projection

The private receipt retains the source object authority, source and transformed
digests, raw draft-body region, body digest, archive/draft identity, mode,
audience, and reviewed plan. Ordinary source-fidelity create and mint
frontmatter/results expose only a safe projection. They do not label or expose
the source object id, private source digest authority, private source path,
source excerpt, or raw exception. The required candidate-body approval digest
can naturally equal the normalized source digest when a bodyless verbatim
candidate consists only of that source; it is presented only as candidate
equality evidence, never as source authority.
Human reviewer attribution remains explicit in the approved draft and mint
evidence.

The private receipt records the replay-bound draft timestamp as
`candidate_created_at`; it does not mislabel that value as the wall-clock human
review time. Its separate review-binding digest binds reviewer, archive, draft,
candidate body, and reviewed creation plan.

Draft and receipt publication is create-only and idempotent. Conflicting bytes
are retained and blocked; no repair path overwrites or deletes them.

## No-share semantics

Audience is descriptive intent, not an ACL. None of the new draft or mint
arguments shares, exports, transports, publishes to an external service, calls
a provider, or grants disclosure permission. A client or public result remains
a separately reviewed `sanitized_derivative` plus a separately approved future
transport action.

## Evidence boundary

The reported shortening attempt was stopped before any draft or mint write.
Verified data loss is therefore zero.

Focused service, CLI, MCP, privacy, and synthetic create-to-mint tests verify
the local implementation without reading a real private source or contacting a
provider. They do not prove that the change is merged, tagged, released,
installed from a public wheel, exercised against a real archive, shared, or
accepted by a human.
