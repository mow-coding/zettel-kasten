# WOM-kit v0.4.31 — Beta letter 163 remainder: hints, edge warnings, explanations, preflight cause, index pre-announce

v0.4.31 finishes the letter-163 items that survived adversarial review:
`create-draft` names the options that identify an AI runtime and marks which
replay values to omit when null; the mint dry-run turns a discarded or
unknown edge target into a bound warning; the two body-wording warnings
explain what they saw (counts and line numbers, never the words); a
`project-version-update` failure without a fixed token still records its
exception family, and a dry-run blocked by an existing transaction describes
that transaction's shape and the recovery flag that applies; and the
`zettel-edge`, `revert-edge` and `source-intake-chain` dry-runs announce the
index fact up front with the rebuild commands.

Publishing or installing this release does not read or modify a client
archive. A client chooses when to run the exact public bootstrap and one
reviewed `project-version-update` to the public wheel
`wom_kit-0.4.31-py3-none-any.whl`. The release is not evidence that a client
result was repaired; that requires the client-run result and a new-process
verification.

## Conditional public artifact contract

Use this bootstrap only after the exact GitHub Release exists and lists the
wheel. The versioned URL alone is not proof that the asset is public.

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0431-$womBootstrapNonce"
if (Test-Path -LiteralPath $womBootstrapRoot) {
  throw "WOM bootstrap path must be new."
}
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.31/wom_kit-0.4.31-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require exactly `archive 0.4.31` from a new process. Installing this external
bootstrap does not replace a shared PATH tool or silently update any project.

## What changes

1. **`create-draft` hints (letter 163 ⑦a/⑦c).** The "must identify the
   assisting AI runtime" blocker keeps its sentence and adds the fixed code
   `ai_draft_assisted_by_required`; `next_safe_actions` names `--assisted-by
   ai_runtime:<name>`, `--supervised-by person:<id>` and `--creation-mode`.
   Every `approval_handoff` argument carries `omit_when_null`
   (`--expected-archive-id`, `--expected-type` and the new `--profile-id`
   entry set it); a blocked dry-run says its null replay values must not be
   forwarded; `--approve` with the literal value `None` on a replay option is
   refused before any archive read (`create_draft_replay_value_null_literal`).
2. **Edge-target warnings (item 11).** The v0.4.30 `edge_target_check` now
   splits an absent target into `discarded` (a discard receipt names it) or
   `missing`; non-zero counts become the bound warnings
   `edge_target_discarded` / `edge_target_missing`, so minting a draft with
   dangling edges needs `--allow-warnings` after review (batch plans:
   `policy.allow_warnings`).
3. **Warning explanations (⑪).** `quality_check.warning_explanations` lists,
   for each raised `internal_status_consistency_review_required` /
   `tool_execution_trace_review_required`, the detector, its fixed rule,
   marker-category counts and body line numbers; matched words never appear
   (`privacy_guards.matched_status_markers_echoed: false`). The mint receipt
   carries it; a pre-upgrade dry-run's `plan_sha256` changes once.
4. **`project-version-update` cause and existing transaction (②).** A
   failure without a fixed token records
   `project_version_update_failure_family_<family>` (`cause_code_source:
   exception_family`, journal stage) in the bound diagnostics and on stderr;
   broker wrappers keep the v0.4.22 allowlist. The terminal-cleanup,
   outcome-unknown and legacy-recovery gates add `existing_transaction`
   (`status` reserved / started / in_progress / terminal, `journal_state`,
   `verified_phase_count`, `last_verified_phase`, `abandon_applicable`,
   `applicable_recovery`), derived from the journal shape only and
   fail-quiet (`journal_state: unobserved`).
5. **Index pre-announce (⑧).** `zettel-edge`, `revert-edge` and
   `source-intake-chain` dry-runs carry `index_precheck` (`state` current /
   stale / unavailable, fixed `reason_codes`, live and indexed counts) and,
   when blocked, list `archive index` / `archive index-health` in
   `next_safe_actions`; a chain blocked at the capture step also records
   `capture_authority_refused`.

## Compatibility and privacy

- Additive keys only: `omit_when_null`, `index_precheck`,
  `existing_transaction`, `quality_check.warning_explanations`,
  `next_safe_actions` on blocked chain plans; new fixed codes
  `ai_draft_assisted_by_required`, `create_draft_replay_value_null_literal`,
  `edge_target_discarded`, `edge_target_missing`,
  `project_version_update_failure_family_*`. No new command, alias or
  schema file; the approval-handoff v0.1 schema gains one optional property.
- Behaviour changes to note: mints with dangling edges need
  `--allow-warnings`; mint `plan_sha256` values from earlier dry-runs are
  stale after the upgrade (rerun the dry-run).
- No path, label, reviewer id, draft content, marker text or archive content
  is introduced into results, receipts, tests or release artifacts.

## Verification boundary

The release candidate must pass the v0.4.31 and v0.4.30 test modules, the
mint, edge, create-draft and project-update cohorts, the pin sweep and the
full supported-platform CI. The exact reviewed merge commit must be tagged,
and the public wheel must be downloaded anonymously, rehashed, installed in
a fresh CPython 3.12 environment and checked in a new process. Those steps
prove the public artifact; they do not prove any client result.
