# WOM-kit v0.4.14 — Reference-Aware Local Recovery And Safer Decisions

v0.4.14 corrects a dangerous local-recovery assumption and makes native
decisions easier to understand without publishing private archive content.

## What changed

- **Historical omission markers are no longer restored blindly.** WOM replays
  the exact historical normalization transaction with the hash-bound reviewed
  reference bindings. A marker that became a verified zettel or Objet
  reference is classified as resolved instead of being written back over that
  reference.
- **Partial evidence stays partial.** When one historical row contains several
  omitted references and only some have exact replacement evidence, WOM records
  the proven resolved occurrences and leaves the remainder in an explicit
  review state. Weak evidence never becomes an automatic link or body rewrite.
- **Classification is an exact, reversible operation.** WOM discovers the
  complete fixed receipt inventory itself, verifies current canonical identity
  and bytes, and binds one private classification ledger to
  `ExactOperationManifest v1`, native approval, checkpoints, resume, independent
  verification, and exact revert. The person is not asked to count rows or
  compare hashes.
- **Title-source selection fails closed.** Identifier-title recovery accepts
  either the exact private Markdown mirror or its containing folder only when
  the required Markdown and index pair is unambiguous and safe. Missing,
  ambiguous, or mismatched evidence produces a fixed reason code rather than a
  guessed title.
- **Native decisions identify their target.** When the operation already binds
  the exact current zet bytes, the local Windows decision can show a bounded
  title, archive-relative file identity, role, endpoints, and short plain-text
  clue. Changed, redacted, path-like, locator-like, email-like, secret-like, or
  otherwise unsafe text is omitted. These clues never enter the machine plan,
  approval digest, receipt, or public output.
- **Human Markdown viewing is display-only.** Complete body-bearing CLI text
  output protects literal Korean range tildes and incomplete emphasis delimiters
  while preserving intentional markup and code. Canonical zet bytes, canonical
  hashes, and structured JSON/service/MCP body reads are unchanged. Incomplete
  bounded pages remain canonical source and explicitly defer projection until
  a viewer has assembled and hash-verified the complete body.
- **Large scans speak promptly.** Local recovery and locator-loss inspection
  emit a content-free start state before inventory work and continue with
  bounded heartbeats. Titles, bodies, identifiers, receipt names, and absolute
  paths are not emitted by progress.

## Human and client boundary

Publishing or installing v0.4.14 does not inspect, classify, or change a client
archive. It calls no provider and uses no client credential.

The intended client first updates that project's isolated WOM runtime. Its AI
then runs the complete dry-run and verifies inventory, identity, current bytes,
receipt lineage, and manifest stability. The person sees the plain operation
and chooses run or cancel in the native decision. Only that client-authorized
run may write the private classification ledger. Canonical body rewriting is
not part of the verified-reference classification path.

A public release and synthetic tests prove that the capability is shipped; they
do not prove that any particular client archive has completed it. Client
completion requires that run's approved receipt, checkpoint evidence,
independent post-state verification, and a later acceptance report.

## Install contract

After the matching GitHub Release exists and lists the exact asset, install it
in an isolated tool or project runtime:

```powershell
uv tool install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.14/wom_kit-0.4.14-py3-none-any.whl"
archive --version
```

Require exactly `archive 0.4.14` from a new process. The versioned URL alone is
not proof that the release or asset exists.
