# WOM-kit v0.3.285: Notion Manifest Index-Title Fallback

Release date: 2026-07-30

## One Narrow New-Import Repair

v0.3.285 prevents one known source of new identifier-shaped Notion draft
titles. When a new item comes from a Notion JSON/YAML manifest, WOM resolves
the ordinary primary title first. A normal human title always wins.

Only when that resolved title is identifier-shaped may WOM consider the exact
lowercase top-level string `index` on the same manifest item. The identifier
test removes spaces, dots, underscores, and hyphens and then checks for a
hexadecimal run of 16 or more characters.

This behavior is shared by file-backed and inline-content manifest items.

## Safe Fallback Gate

A present fallback candidate must:

- be a string;
- pass the shared title normalization and whitespace rules;
- be specific enough to serve as a title;
- not itself be identifier-shaped or another page-reference value;
- fit the existing 500-character importer ceiling;
- contain no blocked local path or provider locator; and
- contain no secret-like metadata.

An unsafe exact `index` blocks that item with a fixed content-free code. The
rejected value is not copied into the item-derived CLI projection, item
warning/error text, draft, or receipt item projection.

For a path-backed item with an explicit identifier-shaped primary title, WOM
runs this metadata gate before resolving or opening the item path. Item-path
and early file-discovery failures are also content-free. An unsafe value that
appears in both `index` and `path`, or a private `source_page_id` aliased by a
missing, empty, unsupported, or unreadable filename, therefore cannot escape
through an earlier path, file warning, or decode exception.

Manifest item paths remain strictly export-relative. POSIX absolute, UNC,
Windows drive-absolute, Windows drive-relative, parent-traversing, and
resolver-failure paths are rejected before reading; resolver exceptions,
including symlink-loop `RuntimeError`, use content-free error text.
The stored relative path is derived from the same guarded resolved root/path
pair, and an already blocked withheld target is not sent to a target-existence
filesystem probe.

Blocked fallback previews replace all user-derived item identity fields with
one content-free placeholder, including aliases through the primary title,
`external_id`, `id`, source path, source URL, zettel id, target path, or
content hash. Identifier matching uses the importer's effective string form,
so scalar ids such as numbers cannot bypass the match gate.

This is an item-projection boundary, not a byte-global coincidence scrubber.
The independently supplied `--export` path, target archive id, and
`--reviewed-by` value remain truthful operational/provenance metadata in the
existing result and receipt contract. Operators should supply them only with
the understanding that they are intentionally recorded.

If the exact key is absent, legacy title selection remains in force. A normal
human primary title is never replaced by `index`.

The existing private `facets.source_page_id` value is also withheld from
preview and receipt fields when another public field would repeat it. If that
private value would become either an explicit or deterministic generated
zettel id and therefore a public target filename, the Notion import fails
closed with
`source_page_id_aliases_public_target_path`; it does not write a file with a
privacy-unsafe public path.

## One Frozen Approved-Call Projection

An approved `import-external` call discovers the manifest once and uses that
frozen projection for its plan and writes. A manifest edit during the same
call therefore cannot select a different title beneath the already selected
zettel id and receipt path.

This is a same-call consistency guarantee, not cross-invocation approval
binding. A later separately approved CLI invocation is not digest-bound to an
earlier dry-run. The operator must review the current preview and source
export before approval.

## Compatibility And Explicit Non-Goals

No archive migration is required. Existing inbox drafts and canonical zettels
are untouched.

The fallback applies only to new Notion JSON/YAML manifest item objects. It
does not apply to:

```text
Google Drive
directory-only Markdown imports
Index
properties.index
properties.Index
rich-text arrays
```

This release does not:

- read or join `pages.index.jsonl`;
- read a provider mirror, database, or Notion API;
- use `facets.source_page_id` for fallback selection;
- create `facets.index` or `source_index_path`;
- project a new facet or improve a generated search index;
- repair, retitle, or otherwise rewrite any existing zet;
- add a new MCP writer, schema, provider call, or network dependency; or
- claim cross-invocation dry-run digest binding.

Existing safe `source_page_id` facet preservation continues independently and
is neither title evidence nor title authority.

## Existing Operator Flow

Preview remains:

```powershell
archive import-external <archive-root> `
  --source notion `
  --export <manifest.json-or-yaml> `
  --dry-run --format json
```

After reviewing the current source and preview, approval remains:

```powershell
archive import-external <archive-root> `
  --source notion `
  --export <manifest.json-or-yaml> `
  --approve --reviewed-by <safe-reviewer-id> --format json
```

MCP continues to expose only the existing read-only
`external_import_plan`; no MCP import writer is added.

## Verification

Release verification is planned against:

- Notion file-backed and inline-content manifest items;
- human-title precedence and identifier-shaped-title fallback;
- exact lowercase top-level key handling;
- invalid shape/value blocking without raw-value leakage;
- path-backed fallback validation before path resolution or file I/O;
- 301-character real-use titles and the existing 500-character ceiling;
- non-Notion, directory-only, differently cased, nested, and rich-text
  exclusions;
- absence of `facets.index`, `source_index_path`, mirror/API reads, and
  existing-zet mutation;
- one-discovery approved-call consistency; and
- existing external-import CLI, MCP no-write, privacy, package-resource, and
  full regression behavior.

No test count, wheel SHA-256, remote CI result, tag, or public release artifact
is claimed before those release steps produce their own evidence.
