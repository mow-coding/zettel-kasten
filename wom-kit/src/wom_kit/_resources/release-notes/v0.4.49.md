# WOM-kit v0.4.49 — review and remove exact remote temporary objects

This candidate adds `object-storage-cleanup` for files that were already uploaded to object storage. Its private inventory reads the actual remote list and verifies full bytes, including eligible files with older or missing receipts. WOM applies the reviewed exact-key plan only after checking current archive references and active work. It verifies absence after deletion, records uncertain outcomes for reconciliation, and refuses a later upload to a pending or deleted exact key. Another key with identical bytes remains available.

`object-storage-open` opens one verified remote object through a temporary read-only URL. The default lifetime is 900 seconds. The URL and credential values are not placed in the normal result, receipt, or zet body. The official command uses the existing credential references and session approval contract; a valid full-access grant does not gain a new exception.

These commands do not classify a file as disposable merely from its name or lack of references. An operator must inspect the evidence and submit a private exact request; uncertain or currently referenced objects remain untouched. `--dry-run` reviews without deletion or opening. `--approve` checks the fresh plan digest before acting, and `--resume` reconciles the cleanup's saved per-key outcome. Prefix-wide deletion and automatic deletion during upload are not part of this release. A deletion does not create a mandatory grace period or recovery copy.

Synthetic tests cover selected-key deletion, duplicate bytes under a different key, references added before the write, interrupted and uncertain remote responses, upload and restore fences, signed URL expiry, approval-key lifetime, and cancellation checkpoints. A separate installed-wheel test used WOM's isolated development R2 bucket and cleaned all its synthetic objects. It did not access a customer bucket. Actual customer acceptance remains unverified. Other outstanding feedback remains open.

After publication and public-install verification, install the exact release wheel in a new environment or use the official `project-version-update` flow for a pinned project. Installing the tool alone does not change a customer archive or delete remote data.
