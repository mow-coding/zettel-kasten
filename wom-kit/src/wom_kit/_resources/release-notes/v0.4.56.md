# WOM-kit v0.4.56 — reuse an existing R2 key file, Git backup and offload unblocked (letter 179)

This release answers beta letter 179, sent from public v0.4.54, which the customer installed and updated to successfully. Installing the tool alone does not change a customer archive; every write still goes through the reviewed approval path.

## An R2 connection made earlier is reused

`object-storage-credential-store <archive-root> --store-slug <slug> --from-file <existing key file> --access-key-field <name> --secret-access-key-field <name> --dry-run`, then `--approve --expected-request-sha256 <request_sha256> --reviewed-by <person:...>`, moves the two keys from the operator's existing key file (dotenv, INI such as rclone.conf with `section.key`, or JSON with a dotted path) into the Windows Credential Manager. One approval, or the session grant the person already gave, covers it. An isolated process reads the file; no key reaches the chat, the screen, argv or a receipt, and the file's path is never echoed. The original file is left unchanged. The result returns the two `credential-manager:` refs for `activity-cleanup --reconcile --rebind-...`.

## The Git backup preview no longer stops on Windows directory noise

On Windows a directory's reported size flips between 0 and its real size with no activity, and the preview compared it, so a several-minute preview on a large archive almost always ended with `receipt_inventory_drifted`. Reproduced with the real CLI and nothing writing. Directory size and permission bits are no longer compared; an added, removed or rewritten receipt is still caught. When drift is real, `receipt_context.drift` says what kind of change happened in which WOM category, never a path. The session heartbeat reports its own elapsed time per stage instead of repeating one value.

## Offload is unblocked and frees bytes that came back

A valid session-evidence draft receipt (which has no objet by contract) no longer counts as unreadable and no longer blocks every offload and remote cleanup; real corruption still blocks. Objects whose manifest says offloaded but whose verified bytes came back (a capture re-materialised them) are offloaded again under the same remote proof (`offloaded_bytes_reappeared_count`); different bytes are a conflict and stay.

## Also

- After a successful update, recommended `.gitignore` rules missing from the archive are named with `repair-gitignore` as the next step.
- `activity-cleanup --status` returns `completion_boundaries`: remote verification (past receipts only), original cleanup, local space, Git backup (not covered; next command named), closure and cost.
- Doctor no longer reports a false `doctor_cache_snapshot_stale` on Windows when a subdirectory changed just before it ran.

## Boundaries

Validated with synthetic archives, the real CLI on Windows for the Git preview, an injected window and a credential-store double. The customer's key file format, their Windows build and their own runs are not confirmed.

## Install after publication

Use the exact public release asset after its hash and size are reported:

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0456-$womBootstrapNonce"
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.56/wom_kit-0.4.56-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require `archive 0.4.56` from a new process, then follow the reviewed `project-version-update` flow for an existing project.
