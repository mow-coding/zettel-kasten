## Removal Contract

One request names one already-valid canonical event anchor and an ordered,
unique set of canonical member ids. The planner reads only those exact standard
canonical files. It infers no member from search, title, time, proximity,
edges, or the generated index.

Rows are `ready_to_remove`, `already_absent`, or `blocked`.

For a ready row, the candidate removes only the named anchor from
`facets.activity_group`:

- an exact scalar or one-item list loses the field;
- a list with other memberships keeps those ids in the same order and remains
  a list;
- another scalar, a list without the anchor, or a missing field is an exact
  no-op;
- an empty, duplicate, mixed, unsafe, mapping, or null current shape blocks.

The candidate preserves other memberships, other facets, body, `updated_at`,
UTF-8 BOM state, and newline convention.

## Evidence And Privacy

The review-plan SHA-256 binds the distinct removal schema, exact raw request
hash, current anchor hash, and every ordered row state/current/proposed hash.
Request/member order and exact-byte drift therefore require a fresh review.

The command is bounded to a 2 MiB request, 5,000 members, 16 MiB per canonical
file, and 256 MiB total canonical bytes. Output omits request paths, zettel
ids/paths/titles, facet values, bodies, provider locators, secrets, and
absolute local paths.

## Explicit Remaining Boundary

v0.3.282 writes and removes nothing. It has no `--approve` mode and creates no
receipt, journal, lock, snapshot, index, or MCP write surface.

The approval-gated removal writer and hard-interruption recovery remain a
separate release. Until then, preserve the private request and review digest
and do not edit canonical zets directly.
