# WOM-kit v0.4.68 — capture receipts are read where the approval really is

This answers beta letter 186. The v0.4.67 route for captures approved through a window found the approval but attributed none of its 21 objets. Installing the tool alone does not change a customer archive.

## What was wrong

A real objet-capture receipt keeps its approval reference one level deeper than the selector was reading. The selector therefore treated every real capture receipt as if it named no approval. This defect also meant that, since the session selector was written, no capture had ever been attributed to a conversation by its capture receipt; conversations were attributed their objets only through later note writes.

The v0.4.67 route was verified against a synthetic receipt whose shape never matched production. That was a verification gap on the developer side. This release was verified with receipts produced by the real capture writer.

## What changes

- The nested approval reference is read. `object-storage-scope-list --approval-id` now attributes the objets of a named capture approval, and `--this-session` attributes captures approved under a grant by their receipts.
- Every receipt or item that is not attributed is counted by a fixed reason (invalid envelope, missing reference, claim not found, context mismatch, claim not a succeeded capture, item not completed). The scope-list result shows, for the named approvals, how many receipts name them and the rejection counts; the session diagnosis shows the archive-wide counts. No id or object id is echoed.
- Nothing in the archive is rewritten. Rerun the same command.

## Boundaries

Verified with the real capture writer in a temporary archive. The customer's archive and run are not verified.

## Install after publication

Use the exact public release asset after its hash and size are reported:

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0468-$womBootstrapNonce"
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.68/wom_kit-0.4.68-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require `archive 0.4.68` from a new process, then follow the reviewed `project-version-update` flow for an existing project.
