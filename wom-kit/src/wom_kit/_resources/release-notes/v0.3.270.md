# WOM-kit v0.3.270

Release date: 2026-07-28

v0.3.270 adds archive-wide, read-only verification for the private receipts
and interruption evidence created by v0.3.269 title writes.

## What Changed

- Added CLI `archive zet-title-remap-receipt-audit --dry-run` and alias
  `title-remap-receipt-audit`.
- Completed receipts are checked against strict runtime allowlists,
  duplicate-key rejection, archive and filename binding, current canonical
  file/title/body hashes, and exact prior-byte object-manifest evidence.
- Retained transaction journals are checked against their strict schema,
  journal digest, archive/proposal/filename/final-receipt binding, snapshot
  evidence, and current participant hashes.
- Retained transactions are classified as `prepared`, `partially_applied`,
  `fully_applied_receipt_missing`, `divergent`, or `stale_completed`.
- The common title-remap write lock must match exactly one valid retained
  journal. Missing, mismatched, malformed, or orphaned lock evidence blocks.
- Bounded problems and transaction-case SHA-256 handles are returned without
  title text/hash/length, zet identity/path, evidence paths, reviewer,
  proposal SHA, provider values, or absolute local paths.
- The command writes and deletes nothing, calls no provider or model, reads no
  secret store or environment value, and exposes no MCP method.

## Command

```powershell
archive zet-title-remap-receipt-audit <archive-root> `
  --dry-run `
  --format json
```

Use `--max-receipts`, `--max-journals`, and `--max-problems` only when an
operator intentionally needs a lower bounded scan. An out-of-range value or
evidence count over the ceiling blocks instead of silently omitting evidence.

## Interruption Boundary

This release diagnoses retained title transaction evidence. It does not
delete a stale journal or lock, resume a partially applied batch, roll back a
batch, create a missing final receipt, or revert a completed receipt.

When attention is reported, retain every private receipt, journal, lock,
canonical participant, and prior-byte snapshot. Do not repair those files by
hand. A later approval-gated recovery release will consume the content-free
case handle and revalidate the complete evidence before any mutation.

## Compatibility

No archive-wide migration is required. Existing v0.3.269 receipts and
journals keep their v0.1 schemas and become auditable by this command. Older
WOM-kit versions can still read successfully changed canonical Markdown, but
they cannot run this evidence audit.

See [zet Title Remap Receipt And Interruption Audit](https://github.com/mow-coding/zettel-kasten/blob/main/wom-kit/docs/zet-title-remap-receipt-audit.md).
