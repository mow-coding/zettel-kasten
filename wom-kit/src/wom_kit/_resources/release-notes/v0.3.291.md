# WOM-kit v0.3.291: Runtime Version Alignment

Release date: 2026-07-30

## What Changed

v0.3.291 makes a confusing but common version split explicit.

A project's `.zettel-kasten/source` mirror and version pin can be current while
the `archive` command on `PATH` imports another Python checkout. The project
updater does not own that global installation, so “project update succeeded”
and “this console command now runs the target version” are different claims.

`archive version <project-or-archive-root> --format json` now reports a bounded
`runtime_alignment` decision and deterministic `next_safe_actions`.

## Shareable Version Metadata

Project version files and local Git tag names are untrusted metadata, not
arbitrary text output channels. Default JSON, text, and `runtime_alignment`
now project only exact stable version labels:

```text
v<major>.<minor>.<patch>
```

An invalid project pin, source `__version__`, pyproject version, running
checkout pyproject value, or local tag name is classified as invalid evidence
and exposed as `null` rather than copied into the result. Only exact stable
tags can populate `head_tag` or `latest_fetched_tag`. This remains true for a
conventional project-local `.git` directory as well as for the already
rejected linked/external Git-metadata cases.

## Project-Scoped Bridge

When all of the following agree:

- source-mirror package version;
- source-mirror `pyproject.toml` version;
- project installed-version pin; and
- the real `wom-kit/cli/archive.py` wrapper exists inside that mirror,

the report may classify a running-import mismatch as:

```text
project_scoped_bridge_available
```

Default output remains path-redacted. Under the existing explicit
`--no-redact-local-paths` option, trusted local diagnostics can receive an
exact structured `bridge_argv` using the current Python executable, the
interpreter's isolated `-I -S` mode, an in-memory bootstrap, and the inspected
root.

The bridge runs the verified project source for one invocation. It does not
replace the global `archive` command or update a Python installation.

`runtime_alignment.integrity` supplies the verification boundary. Executable
argv exists only when `runtime_alignment.integrity.verified` is `true`. The
bridge also requires:

- real non-symlink/reparse project, pin, and wrapper paths;
- a conventional project-local real `.git` directory with no linked-worktree
  pointer, alternate object store, graft, symlink, junction, or reparse route;
- an exact Git worktree root whose commit tree, stage-zero index, index flags,
  bounded raw bytes, and untracked paths agree, except the allowed untracked
  `installed-version.txt`;
- an untracked pin and a closed set of tracked runtime Python sources at
  `HEAD`;
- no `assume-unchanged` or `skip-worktree` flag on any runtime Python source,
  an index that exactly matches `HEAD`, and raw worktree source bytes that
  exactly match the corresponding `HEAD` blobs;
- no extra importable Python source, bytecode cache, or native extension in
  the selected source tree, with every inspected path component remaining a
  real non-reparse file or directory;
- the fixed `remote.origin.url` configuration key and valid `HEAD`, checked
  without reading the configured URL value;
- the exact annotated `v<source-version>` tag at that `HEAD`;
- matching package, pyproject, and root-shim versions inside the tag; and
- local evidence that the tag is reachable from `origin/main`.

The same gate verifies the manifest and all 103 synchronized source/package
runtime resources. The argv binds the expected commit, annotated tag, wrapper
blob, and resource blobs. Its in-memory bootstrap executes the verified wrapper
blob, repeats object and import-location checks, rejects an already loaded
external `wom_kit`, and permits only the read-only `version` command. It does
not add the project `wom-kit/src` directory to `sys.path`: project aliases are
purged and an exact-object-ID custom finder loads only `wom_kit`. A top-level
`yaml` or `sqlite3` shadow inserted after the gate therefore cannot execute
from the project source root. The bridge is never a general write-command
router. Repository attributes keep those verified Python files LF-stable on
Windows and POSIX checkouts.

Resource verification uses exactly three Git child processes independent of
manifest size: one bounded full-tree inventory at the bound commit, one strict
unique-object `cat-file --batch`, and one bounded full stage-zero index
inventory. The batch parser requires exact response order, object type, size,
body framing, separator, count, and Git object-ID rehash with no trailing
bytes. Manifest, source/package parity, SHA-256, exact tree/index modes and
OIDs, bounded real worktree files, and the packaged-resource closed world are
still checked. This removes the earlier per-resource subprocess multiplication
without weakening the gate or expanding path arguments.

`-S` blocks `site` initialization, executable `.pth` lines, and
`sitecustomize` before bootstrap. After the bootstrap verifies Git objects and
compiles the wrapper from verified memory, it appends only the standard
`purelib` and `platlib` paths reported by stdlib `sysconfig`; it does not ask
`site.py` to process those directories.

No network call or fetch runs, replacement objects and lazy fetch are disabled,
and no origin URL or credential value is read. These checks do not prove a
cryptographic tag signature or current remote freshness.

## Transition-Safe Project Update

The raw-byte bridge gate exposed a Windows transition case that status output
does not prove away. With `core.autocrlf=true`, an existing mirror can retain
CRLF bytes for an unchanged runtime `.py` file even though the target
attributes require LF.

After dry-run, the operator must pause editors, sync/backup clients, and every
other Git writer for the complete transaction. Every
`project-version-update --approve` must include the reviewer and
`--affirm-external-writers-quiescent`. WOM-kit then:

- reads the complete tracked file tree, modes, object IDs, and bounded blob
  bytes from the verified target commit;
- rejects cross-platform-unsafe paths, `.git` or reserved-name aliases,
  Unicode/case collisions, reparse components, and unsafe file/directory
  transitions before the first source write;
- manually removes only disappearing tracked files, creates needed
  directories, writes every exact target blob, restores executable modes,
  rebuilds the stage-zero index, and detaches `HEAD` without `git checkout`;
- directly rechecks the raw worktree, index, flags, complete runtime Python
  tree, and all synchronized runtime resources before writing pins;
- records attempted, succeeded, and target-integrity facts under
  `runtime_source_materialization` in the
  `wom-kit/project-version-update-receipt/v0.2` durable update receipt while
  preserving the v0.1 schema unchanged for existing receipts; and
- restores the complete original commit tree, branch/detached state, index,
  modes, and verified original EOL bytes before declaring rollback successful.

Branch restoration uses Git's own `check-ref-format --branch` contract, so
valid `+` and Unicode branch names are preserved instead of being rejected by
a narrower application regex. WOM reads the full symbolic ref and accepts
only an exact `refs/heads/<branch>` result; return code 1 alone means detached
`HEAD`. An abnormal command result, malformed output, or a symbolic ref
outside `refs/heads/` blocks before fetch or local mutation. Rollback validates
the exact branch ref again immediately before reattaching it.

Runtime source and Git metadata inventories stream `os.scandir` with fixed
caps. Even an ignored, noncolliding top-level shadow under `wom-kit/src` blocks
before updater mutation.

Git operations run with no-replace/no-lazy-fetch controls and with optional
locks, fsmonitor, hooks, attributes, and excludes disabled for bounded local
inspection. The updater does not call `git status`, so a configured clean or
process filter cannot execute during its snapshot. It compares the complete
raw worktree, index, flags, and untracked paths directly.

The approved fetch is protected by checkpointed digest comparisons. The digest
binds effective Git configuration plus only `GIT_ASKPASS`,
`GIT_PROXY_COMMAND`, `GIT_SSH`, and `GIT_SSH_COMMAND`. It does not bind the
selected Git executable, `PATH`, `HTTP_PROXY`, `HTTPS_PROXY`, `SSL_CERT_FILE`,
`CURL_CA_BUNDLE`, `SSH_AUTH_SOCK`, `HOME`, or other non-`GIT_*`
toolchain/transport environment; those must remain trusted and stable. The
update lock and final receipt still use exclusive `O_EXCL` creation, so those
reserved paths are not silently replaced.

Rollback covers ordinary failures and interrupts such as `KeyboardInterrupt`.
Checkpoint-detected drift preserves the owned lock and reports incomplete
rollback. If the bounded configuration digest changes immediately before
rollback, WOM skips source/pin restore, preserves the owned lock, and reports
the incomplete result.

This release does not provide atomic file compare-and-swap or a general
never-clobber guarantee for source and pin files. Directory-name stability and
checkpoint checks leave check/write windows. External editors, sync clients,
backup tools, and other Git writers must stay quiescent for the entire Windows
approval. The result makes that limitation explicit:

```text
write_boundary.external_writer_quiescence_required: true
write_boundary.external_writer_quiescence_affirmed: true
write_boundary.atomic_file_compare_and_swap: false
write_boundary.checkpointed_change_detection: true
```

The v0.2 receipt records
`external_writer_quiescence: {affirmed: true, scope:
complete_project_version_update_transaction}`. True
file-handle/descriptor-bound CAS is future work.

An already-targeted mirror and matching pins are `no_change` only when complete
worktree/index/flag and runtime-resource integrity is also verified. The
updater does not delete ignored shadow artifacts; it blocks until an operator
reviews them.

## Approval Platform Boundary

The v0.3.291 approved updater is Windows-only. Windows opens and retains
verified directory handles without `FILE_SHARE_DELETE` for the project,
source/`.git`, pin, lock, and receipt path chains. Those held directories
cannot be renamed, deleted, or swapped for junctions during the transaction.
When the receipt parent or `version-updates` root does not exist, WOM creates
and holds each level in order; the receipt helper refuses an unheld root.

POSIX still receives a useful read-only dry-run with
`status: preview_only_platform_unsupported`, a warning, and
`write_boundary.approval_platform_supported: false`. POSIX `--approve` is a
blocker and writes nothing. An open POSIX directory descriptor does not stop a
pathname rename, and this Git plus complete-tree transaction is not yet
descriptor-relative end to end.

## Fail-Closed Cases

No executable bridge argv is returned when:

- mirror package and pyproject versions disagree;
- the source mirror and project pin disagree;
- required version metadata is missing or malformed; malformed raw values and
  non-release local tag names are not echoed; or
- the project wrapper is missing or outside the verified mirror;
- the mirror is dirty, non-Git, uses non-local/linked/alternate/grafted Git
  metadata, is symlinked/reparse, untagged, lightweight tagged, or not at its
  version tag;
- a runtime source is missing, changed, index-hidden, index-divergent, has
  non-tag bytes, or the selected source tree contains extra importable code,
  bytecode, native extensions, unsafe path components, or divergent
  synchronized resources; or
- configured-origin or local `origin/main` ancestry evidence is missing.

The existing command remains read-only and keeps its mismatch exit behavior.
A present mirror that fails integrity is also a nonzero result.

## Corrected Operator Guidance

The packaged runtime Skill now:

- points source-checkout fallback commands at
  `wom-kit/cli/archive.py`, not the nonexistent `wom-kit/archive.py`;
- supplies the required `--target vX.Y.Z` in project-update previews; and
- separates the project-scoped source bridge, global Python tool lifecycle,
  and runtime Agent Skill lifecycle.

## Compatibility

No archive migration is required. This release changes no zet, objet, edge,
manifest, index, provider, MCP, or archive-write behavior.

The read-only version check does not:

- run pip, uv, pipx, Git fetch, or an updater;
- infer how a Python tool was installed;
- modify `PATH`, Python environments, project mirrors, pins, or receipts;
- restart an imported process;
- install or update an AI runtime Skill; or
- operate on a beta tester's private archive.

The separate existing `project-version-update` command still fetches and
writes only after explicit approval on Windows. POSIX retains the read-only
preview but cannot approve. The declared source/pin/receipt boundary now
includes complete commit-tree materialization and owned rollback evidence
above.

## Verification

Release verification is planned against:

- redacted JSON and text mismatch output;
- an exact opt-in project-scoped bridge argv;
- self-consistent, inconsistent, missing, and malformed mirror fixtures;
- dirty, non-Git, symlink/reparse, wrong/lightweight/not-at-HEAD tag,
  tagged-source mismatch, missing-origin, and origin-main ancestry fixtures;
- `assume-unchanged`, `skip-worktree`, index divergence, raw-byte mismatch,
  ignored bytecode, shadow-source, and extension-module fixtures;
- isolated `-I -S` argv, blocked `site`/`.pth`/`sitecustomize`, controlled
  stdlib-`sysconfig` dependency paths, hostile `PYTHONPATH`,
  preloaded/import-location, and fixed-key-only origin configuration probes;
- old-Windows CRLF-to-LF transition, same-target repair, exact-blob rollback,
  complete commit-tree file/directory transitions, interrupt-safe rollback,
  truthful `no_change`, and receipt-schema fixtures;
- local `.git` metadata, alternates/grafts, no-replace/no-lazy-fetch,
  hook/filter/fsmonitor non-execution, effective-config checkpoints, and
  lock/receipt ownership fixtures;
- exact four-variable Git-environment digest scope, stable external toolchain
  prerequisites, pre-rollback config-drift refusal, and explicit non-atomic
  checkpoint semantics;
- project-alias purge, exact-OID `wom_kit` finder, post-gate top-level
  dependency-shadow refusal, streaming capped scans, and ignored-shadow
  pre-mutation blocking;
- Windows no-`FILE_SHARE_DELETE` directory holds, sequential held receipt-root
  creation, POSIX preview-only status, and POSIX approval refusal;
- the 103-file synchronized runtime-resource contract;
- no global-tool or runtime-Skill replacement claim;
- the existing version and project-update regressions;
- corrected runtime Skill examples and packaged-resource synchronization;
- the complete source test suite; and
- an exact clean wheel with four entrypoints, onboarding, and strict Doctor.

No final test count, wheel SHA-256, remote CI result, tag, GitHub Release,
public artifact result, or beta validation is claimed before later evidence
exists.
