# v0.3.278 - AI Command-Path Routing

Date: 2026-07-28

WOM v0.3.278 makes official command routes part of the AI entry contract.

## Added

- `wom-kit/ai-command-path-routing/v0.1` in runtime-context,
  ai-start-here, operational-context, and canonical entrypoint output.
- Official read routes for archive entry, search, local version truth,
  saved-view inspection, and installed command discovery.
- Official preview/approval routes for draft creation, minting, typed edges,
  source capture, and operational-context updates.
- Markdown `ai-start-here` sections for official read and write paths.
- New-archive AGENTS templates that start with `ai-start-here` and forbid
  direct AI writes to `inbox/`.
- Matching packaged runtime-skill guidance.

## Corrected Boundaries

- `archive search --count-total --format json`, not raw grep or raw SQL, is
  the authoritative bounded WOM search surface.
- `archive create-draft`, not a direct Markdown write, is the AI draft route.
- Draft approval remains separate from mint approval.
- `archive version` proves local runtime/source/pin and already-fetched tag
  state; it does not prove remote release freshness.
- Saved-view recommendations remain read-only because a persistent saved-view
  writer is not implemented.

## Safety And Compatibility

- Routing output is read-only, provider-free, model-free, and path-redacted
  with the existing runtime defaults.
- It reads no zettel body or objet byte solely to produce the route table.
- It writes no existing archive instruction file.
- Existing `ai-start-here/v0.3` consumers remain compatible because the new
  route table has its own schema and is an additive field.

## Explicit Remaining Boundary

Existing archives are not silently migrated to the new AGENTS template.
v0.3.278 also does not detect or repair historical drafts that may have been
written outside `archive create-draft`. That is a separate conservative
read-only audit track.
