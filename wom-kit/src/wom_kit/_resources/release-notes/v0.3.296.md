# WOM-kit v0.3.296: Reviewed Private Objet Metadata Registration

Release date: 2026-08-01

## What Changed

v0.3.296 turns the v0.3.295 private filename contract into one
approval-gated local registration lifecycle:

```text
reviewed private intake
  -> deterministic content-free plan
  -> exact approval replay
  -> canonical append-only private row
  -> immutable private receipt
```

It adds five closed Draft 2020-12 schemas for intake, write plans, authority
chains, receipts, and journals, plus dependency-light runtime validation and
canonical byte/digest builders.

## CLI

Dry-run is content-free and creates no lock or artifact:

```powershell
archive objet-source-metadata-write <archive-root> `
  --intake <archive-relative-private-json> `
  --expected-intake-sha256 sha256:<64-lowercase-hex> `
  --dry-run `
  --format json
```

Approval requires the exact intake and plan digests, a closed safe operator
token, explicit private review, and a truthful all-other-writer quiescence
affirmation:

```powershell
archive objet-source-metadata-write <archive-root> `
  --intake <archive-relative-private-json> `
  --expected-intake-sha256 sha256:<64-lowercase-hex> `
  --expected-plan-sha256 sha256:<64-lowercase-hex> `
  --approve `
  --reviewed-by operator:<safe-token> `
  --affirm-private-metadata-reviewed `
  --affirm-external-writers-quiescent `
  --format json
```

MCP exposes no writer.

## Platform And Interruption Boundary

Approved mutation is supported only on Windows 10 version 1607 or newer and
Windows 11, on a local NTFS volume. Dry-run and read-only inspection remain
cross-platform. Unsupported mutation environments return one content-free
blocked result and never use a path-based simulation or fallback.

The writer retains and revalidates exact directory/file identities, acquires
the existing object-manifest lock before the private-manifest lock, rebuilds
the plan inside both locks, and uses the documented
`windows_ntfs_win32_process_interruption/v0.1` Win32 profile. The operator must
keep every other WOM and non-WOM archive writer stopped for the complete
approval. The locks are defense in depth and do not make a process that
violates that affirmation safe.

The profile has real process-interruption restart/recovery evidence. The word
“durable” in schema or record names does not claim verified sudden-power-loss
directory-entry or volume-metadata persistence.

In the abnormal Windows API state where terminal release of one retained raw
handle remains unproved after three consecutive close-and-validity cycles, the
writer fail-stops with process exit code 74 instead of returning a normal JSON
result. Run a fresh dry-run afterward to reclassify the current state; the
failed invocation does not claim whether the affected residue survived.

## Row, Authority Chain, And Receipt

The writer derives every normalized name, candidate, and canonical byte from
the reviewed intake through the exact v0.3.295 contract. It appends one
canonical LF-terminated row to
`objects/manifests/private-source-metadata.jsonl` only after the target objet
occurs exactly once in the current object manifest and every existing private
row/receipt prefix verifies.

One deterministic journal freezes the accepted append plan, exact
manifest-before/after states, receipt document, and owned artifacts. The
receipt basename derives from an evidence authority key rather than a private
filename, source id, reviewer name, timestamp, or random value. The immutable
receipt preserves the row's exact `private_archive` or `restricted`
classification and binds the original append plan, reviewer token, quiescence
fact, and closed no-call facts.

## Replay, Recovery, And Manual Hold

The state machine distinguishes `append`, `rollback_required`,
`recovery_required`, `already_applied`, `manual_hold`, and `blocked`.
Pre-manifest residue cleanup is a separate approved rollback and never
silently continues into an append. An exact appended row without its receipt
can recover only from its exact valid journal. Ambiguous, orphaned, collided,
changed, hard-linked, or otherwise unproved evidence is retained for human
inspection.

Exact replay returns the original immutable receipt without changing its
bytes, mtime, action, or first operator token.

An observation-time manual hold binds the exact current
`plan.action=manual_hold` plan when constructible. An execution-time hold keeps
the byte-identical accepted action plan and adds only a closed,
non-authoritative `hold_context` with failure stage, last verified authority
state, and cleanup state. It carries no path, private identifier, count, raw
byte, exception, or free text and authorizes no later mutation.

An uncoordinated process holding the current private manifest open can make
ordinary `FileRenameInfo` return `ERROR_ACCESS_DENIED` before replacement.
The writer then preserves the accepted before-state and returns a cleaned
execution-time `manual_hold`; after the reader releases the file, obtain and
approve a fresh dry-run. Atomic old-or-new reader observations are covered,
but wait-free progress through uncoordinated readers is not claimed.

## Privacy And Evidence Boundary

JSON and text output omit raw filenames, decoded/normalized names, source
record and attachment ids, intake paths, reviewer names/emails, provider
locators, absolute paths, raw evidence, secrets, and private exception text.
The closed `operator:<safe-token>` is persisted only where the private receipt
contract requires it.

The writer opens no objet bytes and performs no provider, network, credential
store, external local-store, database, or index call. Registration does not
prove byte availability, object existence, source coverage, provider state,
remote backup, or source-observed size agreement with stored bytes.

## Rediscovery And Compatibility

The existing rediscovery command and MCP tool remain read-only. Their
`private_original_name_metadata` layer now reports `unchecked` with
`private_metadata_rediscovery_not_checked`: the writer exists, but no
receipt-bound private index or private query exists, and no private index
freshness is proven. The layer remains non-complete and contributes nothing to
a negative absence claim.

This release adds exactly one top-level CLI command. It adds no MCP tool,
database schema, migration, private finder, public/restricted/private search
projection, object-byte operation, provider call, external-store scan, or UI.

## Package And Verification Boundary

The package resource manifest adds the five schemas and replaces the current
release note. Release verification requires:

- byte-identical source and packaged schema resources;
- exact CLI delta with unchanged MCP and database surfaces;
- cross-platform dry-run and fixed unsupported-approval evidence;
- unprivileged real-NTFS Win32 mutation, race, sharing, replay, rollback, and
  recovery probes;
- the full test suite and release-readiness 4/4; and
- a clean wheel, dependency-resolving fresh install, four entrypoints, exact
  MCP inventory, onboarding, Runtime Skill lifecycle, and strict Doctor.
