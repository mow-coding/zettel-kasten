# WOM-kit v0.3.289: Exact Wheel Resource Integrity

Release date: 2026-07-30

## What Changed

v0.3.289 strengthens the release-time check for the self-contained WOM-kit
wheel.

The earlier checker confirmed that the packaged resource manifest existed and
that its declared resource names appeared in the wheel. That was useful, but
it did not independently prove that the manifest was the reviewed one or that
each installed resource contained the reviewed bytes.

The checker now requires all four layers to agree:

1. the reviewed repository resource manifest;
2. the manifest packaged inside the wheel;
3. each resource member packaged inside the wheel; and
4. the repository packaged-resource mirror.

## Exact Manifest And Resource Set

The manifest inside the wheel must match the repository manifest byte for
byte. Its JSON is also parsed strictly:

- UTF-8 and JSON must be valid;
- duplicate object keys are rejected;
- the manifest schema and field types must be exact;
- `file_count` must match the number of declared files; and
- every declared path, byte count, and SHA-256 value must be valid.

The wheel must contain every declared packaged resource and no undeclared
resource under the packaged-resource root.

## ZIP Path And Duplicate Safety

Every ZIP member name is checked before resource verification. The checker
rejects:

- duplicate member names;
- absolute paths;
- backslashes;
- empty path segments;
- `.` or `..` path segments; and
- any other non-normalized member name.

This prevents an ambiguous archive from being treated as a unique installed
resource tree.

## Installed-Path Collision Safety

ZIP member names are not always the final installed paths.

On Windows, case variants can name the same destination. The standard Python
ZIP extraction behavior also maps the Win32-forbidden characters
`:`, `<`, `>`, `|`, `"`, `?`, and `*` to `_`. Win32 additionally treats
trailing dots/spaces and names such as `CON`, `PRN`, `AUX`, `NUL`,
`COM1..COM9`, and `LPT1..LPT9` as special; the COM/LPT superscript digits
`¹`, `²`, and `³` are reserved aliases too.

The checker rejects those member forms and rejects any pair of members that
has the same case-insensitive Windows destination key.

Wheel `.data` scheme members can also move at install time. In particular,
`*.data/purelib/...` or `*.data/platlib/...` can land on top of an otherwise
verified package resource on both POSIX and Windows. WOM-kit is a pure,
self-contained wheel and requires no `.data` scheme member, so this release
rejects every top-level `*.data/...` member before installation.

## Byte-For-Byte Verification

Each declared resource is streamed from the wheel. The checker compares:

- the manifest byte count;
- the ZIP member's declared size;
- the actual number of bytes read;
- the manifest SHA-256;
- the SHA-256 computed from the actual wheel bytes; and
- the exact bytes of the repository packaged mirror.

A mismatch at any layer rejects the wheel.

## Bounded Failure Contract

Malformed ZIP files, UTF-8 or JSON failures, invalid schemas, unsafe paths,
missing repository mirrors, and resource read failures are normalized to
`WheelCheckError`. The release checker reports one bounded failure instead of
printing a raw parser or ZIP traceback.

On success it reports the manifested resource count, verified resource count,
verified byte total, and wheel member count.

## What This Does Not Claim

This is a packaged-resource integrity check. It does not claim whole-wheel
reproducibility and does not compare ZIP compression method or ratio, member
order, timestamps, permissions, offsets, or other container metadata.

This release adds no:

- archive write or migration;
- runtime CLI or MCP behavior change;
- provider, model, credential-store, or network call;
- archive format or schema change; or
- beta-archive operation.

## Verification

Release verification is planned against:

- focused normal and adversarial wheel fixtures;
- malformed archive, UTF-8, JSON, schema, path, and duplicate cases;
- Windows extraction collision and wheel `.data` relocation aliases;
- exact manifest, resource-set, byte-count, digest, and mirror mismatch cases;
- release-readiness and deterministic resource checks;
- the complete source test suite; and
- a clean wheel with four entrypoints, onboarding, and strict Doctor.

No final test count, wheel SHA-256, remote CI result, tag, GitHub Release,
public artifact result, or beta validation is claimed before later evidence
exists.
