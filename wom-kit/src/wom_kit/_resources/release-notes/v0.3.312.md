# WOM-kit v0.3.312

Letters 120 and 123 current-index authority, bounded mint progress, and checked
operator-feedback bodies.

Status: v0.3.312 implementation and release scope. This source note does not
replace independent CI, exact-tag, GitHub Release, packaged-resource, wheel,
fresh-install, real-archive, or human-acceptance evidence.

## Added

- `mint-zet --progress` emits an immediate content-free start and bounded
  heartbeat/progress events to stderr while keeping stdout reserved for the one
  final preview or approval result;
- `view-zets` accepts structured status, origin, mint-time, sort, and dedupe
  controls instead of forcing callers to infer recent canonical WOM-native
  publication from filesystem path order;
- `operator-feedback-compose` gives a private six-section feedback request a
  write-free content-free plan and an exact reviewed create-only body/receipt
  replay; and
- `operator-feedback-body-check` verifies body structure, privacy, digest, and
  the existing lifecycle record's exact feedback-body reference without
  returning feedback prose.

## Changed

- index-backed zettel query and mint planning now share one fail-closed current
  index authority. Missing, legacy, incomplete, dirty, unsafe, or live-stat
  mismatched evidence returns `archive_index_rebuild_required`, zero protected
  query rows, and no mint decision;
- a blocked mint no longer silently falls back to an all-canonical body scan;
- current index schema metadata records an explicit state and generation, and
  zettel rows carry bounded duplicate keys plus structured publication fields;
- mint duplicate planning reads only the target and indexed candidates instead
  of selecting, statting twice, and parsing every canonical body; and
- supported mint and retirement lifecycles either apply the exact generated-
  index delta or leave the index explicitly dirty. Index update failure is not
  reported as a warning-success result.

## Operator action for existing indexes

Existing pre-v0.3.312 generated-index metadata is intentionally not migrated by
a hidden real-archive scan. Before protected query or mint use, run:

```powershell
archive index <archive-root> --progress --format json
archive index-health <archive-root> --dry-run --progress --format json
```

Then retry the original command. The index is generated and rebuildable; the
Markdown, receipts, and source artifacts remain the durable evidence.

## Progress privacy and transport

For JSON output, each progress line is one UTF-8 JSON object with only fixed
stage/event labels, safe counts, elapsed milliseconds, and the last completed
stage. Paths, ids, titles, bodies, queries, raw exceptions, and rejected values
are excluded. Progress rendering is observational and cannot change a mint
decision.

The final result remains on stdout. A start or heartbeat event is neither
approval nor completion evidence.

## Feedback-body boundary

The private request contains exactly `environment`, `task`,
`observed_failure`, `suspected_cause`, `requested_resolution`, and
`reproduction`. Planning never echoes their values. Approval creates one body
and one digest-bound receipt without overwrite; the metadata lifecycle binds it
as `feedback-body-sha256:<64 hex>`.

The new commands do not submit feedback externally, change delivery state, or
prove human receipt. A body without a matching lifecycle binding remains
incomplete evidence.

## Scope and evidence boundary

- The controlled Letter 123 reproduction used a temporary synthetic archive:
  8,599 canonical zets plus one inbox draft. A current index completed in 0.807
  seconds with no canonical-body parse; one stale mtime triggered the old
  17.964-second, two-stat-pass, 8,599-body fallback. The old CLI's first stdout
  byte arrived at 17.872 seconds of a 17.909-second run while stderr stayed
  empty.
- No beta archive was modified or automatically rebuilt while developing this
  release.
- Feedback-body privacy checks cover fixed known secret, provider, contact, and
  local-path shapes; they do not replace human review or claim complete DLP.
- Approved mint/promotion output paths require external-writer quiescence;
  cleanup rechecks its expected file identity and digest, and mismatch leaves
  the generated index dirty rather than adopting the replacement.
- SQLite atomicity covers the database transaction, not a separate Markdown
  file and receipt. Interrupted cross-file lifecycles therefore remain dirty
  and require reconciliation.
- Letter 121 reported an attempted AI shortening, but the beta tester confirmed
  that no draft or mint write occurred. Its separate source-to-draft fidelity
  modes and universal reviewed replay remain the next release scope.
