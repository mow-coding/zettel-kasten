# WOM-kit v0.3.311

Letters 118 and 119 credential continuity and reviewed Notion page recovery.

Status: v0.3.311 implementation and release scope. This source note does not
replace independent CI, exact-tag, GitHub Release, packaged-resource, wheel,
fresh-install, live-provider, or human-acceptance evidence.

## Added

- `credential-adopt` provides digest-bound planning and explicit approval for
  a Windows-native masked Notion credential intake. The secret is accepted
  only inside a fresh spawned worker and is never accepted through argv,
  environment variables, normal stdin, a plaintext file, chat, or clipboard;
- `credential-secure-list` distinguishes unauthenticated local metadata from
  authenticated receipt and lifecycle evidence without enumerating Windows
  Credential Manager;
- `credential-lifecycle` lets a human plan and approve one current/default
  credential for an exact provider/workspace scope while retaining other valid
  credentials as legacy or review-pending entries. WOM never deletes or
  revokes another credential automatically;
- `notion-page-recovery-plan` validates and digest-plans the complete reviewed
  Letter 118 request of two groups, 577 plus 43 items, from an ignored-local
  JSON file without reading a credential, calling Notion, or writing; and
- `notion-page-recovery` executes only an unchanged approved slice through an
  authenticated receipt-backed credential and a read-only Notion adapter,
  preserving exact enhanced-Markdown bytes as content-addressed objets with
  itemized resume, projection, and aggregate receipt evidence; and
- operator-feedback titles now allow descriptive security words such as
  `credential` and `token` while rejecting concrete secret, URL, e-mail-like,
  local-path, NUL, and multiline shapes with value-free outcomes. This release
  does not add the separate feedback-body contract requested in Letter 120.

## Credential authority and safety

- a safe label or legacy credential-reference row remains metadata only. It
  never proves encrypted-store presence and cannot authorize provider use;
- a durable credential id is issued only after an exact Generic Credential
  write and presence probe, Notion identity verification, one human-reviewed
  workspace anchor, and atomic authenticated receipt publication;
- the archive identity, public request digest, expiring one-use plan, current
  Windows user, exact store target, account/workspace fingerprints, purpose,
  capabilities, and receipt are bound and revalidated across the spawned
  worker boundary;
- mutable secret and derived-key buffers are wiped. A later exact-target value
  must still match the authenticated secret fingerprint before recovery can
  use it;
- failures use fixed value-free public outcomes. Rollback deletion failure is
  reported as unresolved local state rather than being mislabeled as absence;
- a launch failure proven before process start reports exact zero, while lost
  IPC or a crash after start reports unknown acceptance/persistence and durable
  state with a fixed same-plan reconciliation action; and
- the one-use claim is archive-bound, rejects reparse/path substitution, uses
  complete synced writes and atomic publication, and accepts only exact marker
  replay; authenticated list/lifecycle failures after archive-key access report
  OS/key-read counts as possibly nonzero; and
- duplicate valid credentials require explicit human lifecycle selection and
  are never automatically deleted or revoked.

## Reviewed Notion recovery boundary

- the release-facing request gate accepts the complete Letter 118 batch only:
  `zet_notion_db3` with 577 items and `zet_notion_db1` with 43 items, for 620
  unique reviewed page UUIDs. `--max-items` and `--offset` provide bounded
  pilot and continuation slices over that unchanged complete request;
- approval always authorizes the selected slice to perform credential reads,
  read-only provider GETs, and archive evidence writes. A verified local replay
  is an optimization, not a weaker authority contract;
- the adapter fixes `Notion-Version: 2026-03-11`, accepts only exact HTTP 200
  page/page-Markdown projections for the requested UUID, rejects redirects,
  bounds response bytes and retries, and never includes response bodies in
  public errors;
- page and returned unknown-block Markdown use the documented
  `/v1/pages/{page_or_block_id}/markdown` endpoint. At most 100 unknown block
  ids are accepted, and transcripts remain excluded;
- an accessible `in_trash: true` page may be classified as deleted. HTTP 404
  remains the combined `not_found_or_not_shared` outcome because the provider
  does not distinguish those cases;
- all provider GET attempts share an archive-local interprocess three-request-
  per-second coordinator. This does not claim connection-wide coordination
  across different archive roots that happen to use the same integration;
- exact Markdown bytes are stored once by object id in the central manifest;
  per-page authority stays in the private resume/projection ledgers. Existing
  conflicting or duplicate authority fails closed; and
- the approved archive id is rechecked before live access and every durable
  commit, credential revision/default authority is rechecked before every GET,
  and create/replace/append publication uses write-all plus exact byte
  verification while preserving already observed operation counts; and
- recovery never searches the workspace broadly, writes to Notion, opts into
  transcripts, downloads media bytes, creates or rewrites canonical zets,
  infers edges, or mints pages.

## Compatibility

Existing credential-reference inventory, connected-account, ancestor
`notion-recover`, objet, retrieval-ledger, and canonical-zettel behavior remain
available. Legacy credential rows are reported more honestly as
`presence: not_checked`; they are not silently promoted into the authenticated
registry. The new reviewed page-body lane is separate from ancestor recovery.

## Evidence boundary

Development and regression tests use injected masked UIs, native facades,
credential stores, clocks, and HTTP transports. They do not access a real PAT,
Windows vault entry, Notion workspace, or external source-archive state. Source and test
completion therefore do not prove that the two operator credentials have been
adopted or that any of the 620 pages have been recovered.

Letters 120 and 121 remain separate queued work and are not implemented by
this release.
