# WOM-kit v0.4.8 — Integrity Recovery Without Guesswork

v0.4.8 closes several cases where WOM could detect a problem but still leave
the operator with too much manual recovery work. The common rule is simple:
WOM proves the exact state and safe effect; the person chooses only whether to
run that clearly described operation or cancel.

## What changed

- **Interrupted work explains itself.** Exact operations report which effects
  were durably recorded, which are still pending, which have drifted, and
  whether a write may have happened before its checkpoint. Resume and revert
  can automatically find one unambiguous authenticated private control. WOM
  stops instead of guessing when controls are missing, corrupt, or ambiguous.
  Reverting an unfinished field recovery durably closes its parent apply, so
  the old apply cannot later resume over the restored state.
- **Title recovery uses the correct source.** A replacement title may come only
  from the corresponding source-index field. Body paragraphs are never used as
  a fallback title, and unavailable evidence stays in review.
- **Marker recovery changes only the marker.** WOM binds the surrounding body
  and restores only the exact omission-marker token. If unrelated body content
  differs, the item is left unchanged for review.
- **Locator sidecars are read within a fixed safety bound.** Oversized,
  changing, linked, reparse-point, or non-regular sidecars fail closed without
  being loaded as trusted recovery evidence. Occurrence anchors are diagnostic
  hints only: v0.4.8 does not yet support a verified occurrence-recovery
  receipt, so an anchor alone never proves that an omitted occurrence was
  recovered.
- **Existing intake evidence can produce one exact capture selection.** The
  selection is create-only, bound to an existing canonical intake record, and
  requires a separate native decision before a later capture. Legacy unbound
  selection approval remains closed.
- **Local object-storage setup can be registered without contacting storage.**
  The writer records only exact versioned local metadata and its receipt. It
  does not create a bucket, read a credential, upload, copy, sync, or claim that
  remote storage has been verified.
- **Strict duplicate pairs can be reconciled without discarding evidence.**
  When one canonical local definition and one matching external prehashed
  definition pass every exact check, WOM keeps one canonical manifest row while
  preserving both definitions and their provenance in private evidence.
  Ambiguous groups remain review-only. A native-approved revert restores the
  exact original whole-manifest bytes. The same revert can recover one
  unambiguous interrupted write recorded before or after receipt publication;
  WOM revalidates the original approval, preserves the source journal, and
  records separate authenticated terminal-compensation evidence that blocks
  the old forward operation from running again. If revert stops in
  `finalization_pending`, run `--revert --resume --reviewed-by` with the same
  reviewer label. WOM finds and reauthenticates the existing `started` or
  `succeeded` claim without another native approval window. A `started` claim
  resumes the writer idempotently; a `succeeded` claim runs only the finalizer.
  The claim reaches `succeeded` before terminal finalization, and resume does
  not write the manifest again. If the first revert stops with an unknown-state
  result, JSON returns the fixed safe action
  `rerun_duplicate_revert_resume_with_same_reviewer` and text tells the person
  to rerun `--resume` with the same reviewer label. The guidance exposes no
  private value, id, or path and is not repeated for a failed resume attempt.
- **Relationship rejection is honestly scoped.** The parser advertises the
  exact local rejection path only; unsupported acceptance remains closed.

## Human and privacy boundary

Counts, hashes, source bindings, current-state checks, and effect verification
belong to WOM. Ordinary approval does not require a person to copy or compare a
digest. Optional digest arguments remain available only for expert drift
binding.

Normal output and public artifacts contain no private title, body, locator,
provider value, credential, local absolute path, or archive payload. Release
verification calls no provider, reads no credential value, and writes no
client archive.

## Client execution boundary

Publishing or installing v0.4.8 does not repair a client archive. The client
must first run the released build in that project's isolated runtime and then
choose the project-scoped recovery operation, or explicitly delegate that
operation. A product release proves that the recovery path exists; only its
durable receipt and independent read-back prove that a particular archive was
changed.

## Install contract

After the matching GitHub Release exists and lists the wheel, install the exact
public artifact in an isolated tool or project runtime:

```powershell
uv tool install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.8/wom_kit-0.4.8-py3-none-any.whl"
archive --version
```

The new process must report exactly `archive 0.4.8`. The versioned URL alone is
not proof that the release asset exists.
