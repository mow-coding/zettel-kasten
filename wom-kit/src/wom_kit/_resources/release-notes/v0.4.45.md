# WOM-kit v0.4.45 — A short rulebook for the helper AI

Beta letters now mostly report that the helper AI working in a customer's archive (Claude or Codex) breaks a WOM rule, not that a command is blocked. A review of letters 150 to 173 found about thirty cases. The most common were:

- hand-editing files, drafts or the runtime
- running an approval in the background or killing it, and repeating resumes
- using a different `archive` than the project launcher
- approving a preview that still listed blockers
- reusing another conversation's session references
- backing up or uploading every session's work
- a bare reviewer name
- old external numbering in new notes
- letter numbering and fidelity

The guidance itself was long, and in places contradicted its own rules. Installing the tool alone does not change a customer archive; use the reviewed `project-version-update` flow for a project.

## What changed

- The helper-AI skill (`SKILL.md`) now starts with twelve short core rules, then a table of which command to use for which intent. Every command in the table is checked against the CLI.
- Rarely needed detail moved into focused references: credentials and session grants, long operations and updates, developer letters, and models and reasoning levels.
- Two contradictions are fixed:
  - Unpublished drafts are revised with `draft-revision-write`, never edited by hand.
  - "Carry established state" never covers session grants or another conversation's session references.
- `wom-kit/docs/ai-guidance-scenarios.md` turns eighteen real letter cases into scenarios for checking an AI or a guidance change by hand.

## Which model and reasoning level

This is a recommendation, not a benchmark. No letter compared models, and none could state the reasoning level used.

- For any approval, update, recovery, cleanup, backup, credential or provider task, use the provider's strongest available model with high reasoning.
- Small or fast models are for read-only work only.
- Keep one task per session, and re-run `ai-start-here` after the chat is compacted or reset.

## After updating

A project gets the new skill through the reviewed `project-version-update` flow or `runtime-skill-install`. Ask your AI to re-read the skill at the start of its next session.

## Install after publication

Use the exact public release asset after its hash and size are reported:

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0445-$womBootstrapNonce"
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.45/wom_kit-0.4.45-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require `archive 0.4.45` from a new process, then follow the reviewed `project-version-update` flow for an existing project. A bootstrap installation alone does not update its pinned runtime.
