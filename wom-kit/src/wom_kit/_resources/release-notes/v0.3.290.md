# WOM-kit v0.3.290: Edge Writer Entity-Type Enforcement

Release date: 2026-07-30

## What Changed

v0.3.290 closes a write-safety gap in the existing generic `zettel-edge`
writer.

Previously, the writer verified that an edge type ID was active and that its
source and target records resolved, but it did not enforce the active type
record's declared endpoint entity types. That meant a relationship intended
for `Zettel -> Zettel` could reach preflight with a manifested
`OriginalObject` target.

The shared single-edge gate now enforces the complete active registry contract
before either a source zettel or edge receipt can be written.

## Endpoint Contract

The writer uses these entity types:

```text
source zet             -> Zettel
resolved zet target    -> Zettel
manifested objet target -> OriginalObject
```

The selected active `types.yml` record must contain non-empty `from` and `to`
lists of safe entity-type strings. The source entity type must appear in
`from`, and the resolved target entity type must appear in `to`.

Examples from the existing vocabulary:

```text
continues      Zettel -> Zettel
embed          Zettel -> OriginalObject
format_variant Zettel -> Zettel | OriginalObject
```

Accordingly, `continues` cannot target an objet, `embed` cannot target a zet,
and `format_variant` continues to accept either reviewed target kind.

## Fail-Closed Registry Handling

When an archive vendors `zettel-kasten/types.yml`, that local registry remains
authoritative. The packaged WOM-kit registry is used only when the local file
is absent.

The write path fails closed if the selected record is missing a usable
endpoint contract, including missing, malformed, or empty `from`/`to` lists.
It does not silently substitute the packaged definition for an invalid local
one.

Failures return bounded machine states and endpoint-type facts. The new
`entity_type_contract` field and its new fixed blockers copy no target
content, zettel titles or bodies, registry payloads, provider values, paths,
or raw exception text. Existing safe result fields remain unchanged: they can
include a source archive-relative path, a target ref, the fixed object-manifest
path, and deterministic receipt paths.

## Batch Behavior

`zettel-edge-batch` already delegates policy-writable rows to the single-edge
preflight. It now inherits this endpoint-type enforcement:

- an incompatible or malformed row cannot become an approved write;
- no per-edge receipt is created for that row;
- no batch receipt claims that row was written; and
- the endpoint-type decision remains deterministic and content-free, while
  the existing safe result fields remain available.

The existing manual-only `format_variant` policy is unchanged. Batch plans
still route every `format_variant` row to human review instead of writing it.

## Compatibility

No archive migration is required. Existing edge vocabulary and already-written
edges are not changed or scanned. The fix applies when a new single or batch
edge write is previewed or approved.

This release does not:

- activate or redefine `sequence`;
- add or modify an edge vocabulary record;
- infer a relationship from content or metadata;
- add a provider, Notion, AI, or MCP writer;
- migrate or repair historical edges;
- broaden batch auto-write policy; or
- operate on a beta tester's private archive.

## Verification

Release verification is planned against:

- incompatible `continues` and `embed` endpoint pairs in dry-run and approve;
- unchanged valid `format_variant` zettel and objet targets;
- malformed, missing, and empty registry endpoint lists;
- archive-local registry authority and packaged fallback;
- single and batch no-write/no-receipt guarantees;
- bounded output without private content or path echo;
- existing edge, batch, format-variant, documentation, and resource checks;
- the complete source test suite; and
- an exact clean wheel with four entrypoints, onboarding, and strict Doctor.

No final test count, wheel SHA-256, remote CI result, tag, GitHub Release,
public artifact result, or beta validation is claimed before later evidence
exists.
