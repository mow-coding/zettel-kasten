# WOM-kit v0.3.308

Letter 115 reference, locator, and table completion.

## Added

- added one full-fragment digest for each paired `<file ...></file>` reference,
  so one reviewed manifest row binds one verified manifested objet;
- added reviewed `zettel_edge` binding for self-closing `mention-page` and
  manifested-objet binding for self-closing `unknown:audio`;
- added dedupe-only `external-locator-deactivate-plan` and
  `external-locator-deactivate`, requiring both the target and the active
  coordinate-compatible locator to keep;
- added `inactive` locator status, content-free recovery counts, exact
  lock-and-replan approval, prior-record snapshot, receipt, and ordinary
  exact-byte locator revert compatibility; and
- added strict self-closing date rendering plus safe balanced span/inline
  preservation inside imported tables, including GFM pipe escaping.

## Safety boundary

- nonempty or malformed paired files, repeated identity-free unknown-audio
  placeholders, paired page-mention labels, and duplicate binding rows remain
  fail-closed;
- table scripts, inputs, block content, unsafe attributes or URLs, comments,
  unbalanced markup, malformed/non-standalone structure, and table-cell
  references remain unchanged and blocked;
- fenced or inline code, declarations, CDATA/PI, escaped examples, raw code
  elements, and Markdown link destinations/titles are protected rather than
  interpreted as live migration markup;
- locator deactivation never deletes or reorders a row, never chooses a keeper,
  never crosses occurrence anchors, never drops a reviewed coordinate, and
  refuses a target already referenced from canonical body content;
- inactive locators cannot satisfy a new markup binding;
- stale plans, changed bytes, invalid reviewers, conflicts, and ambiguity write
  no files;
- locator receipts, record paths, snapshots, and record identity are validated
  before revert, corrupt pre-existing snapshots block forward writes, and
  handled record/receipt failures roll back byte-for-byte;
- existing locator records and receipts remain readable, and schema upgrades
  happen only on an approved locator write; and
- no provider/network call, credential access, canonical beta write, MCP
  writer, archive migration, or UI change is introduced.

## Compatibility

Additive CLI and fail-closed normalization behavior. Existing v0.3.307 archives
require no migration.
