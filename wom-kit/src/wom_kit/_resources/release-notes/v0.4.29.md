# WOM-kit v0.4.29 — Object-Storage Offload (OB-02)

v0.4.29 builds the second half of the long-requested "upload the originals,
then free local disk" feature: the way out, on top of the v0.4.28 way back.
`archive object-storage-offload` removes the local file of an objet only
after, in the same approved execution, a full authenticated GET reproduced
the object id, the local bytes re-hashed to it, and every retention predicate
passed; the manifest row keeps its local location marked `offloaded`, the
remote object is never deleted, and `object-storage-restore` reverses it.
Acceptance row OB-02 (planned for v0.4.23 by the 2026-09-04 decision log,
pushed aside by the hotfix train) moves to development verified.

Publishing or installing this release does not read or modify a client
archive. A client chooses when to run the exact public bootstrap and one
reviewed `project-version-update` to the public wheel
`wom_kit-0.4.29-py3-none-any.whl`. The release is not evidence that a client
result was repaired; that requires the client-run result and a new-process
verification.

## Conditional public artifact contract

Use this bootstrap only after the exact GitHub Release exists and lists the
wheel. The versioned URL alone is not proof that the asset is public.

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0429-$womBootstrapNonce"
if (Test-Path -LiteralPath $womBootstrapRoot) {
  throw "WOM bootstrap path must be new."
}
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.29/wom_kit-0.4.29-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require exactly `archive 0.4.29` from a new process. Installing this external
bootstrap does not replace a shared PATH tool or silently update any project.

## What changes

1. **`object-storage-offload` (alias `objet-storage-offload`).** Dry-run
   scans `objects/manifests/files.jsonl` and every inbox draft, hashes local
   candidates, calls no provider, reads no credential value and echoes counts
   and `plan_sha256` only. A candidate needs a WOM-verified `wom_uploaded`
   location for the requested `--provider-kind` / `--store-ref` (a v0.4.13
   preservation receipt alone can be restored from, never offloaded from),
   capture provenance, an `available` local file that hashes to the object
   id on a reparse-free path with a usable identity, no inbox draft that
   references it or was created from it (private fidelity receipts are
   read), and the operator's `--min-age-days` (default 30) and
   `--min-size-bytes` (default 0) filters; `--only` bypasses the two filters,
   never the safety predicates. Every exclusion is counted; an unreadable
   draft or fidelity receipt blocks the whole plan.
2. **One dialog, one full GET per object, two local hashes, one bound
   delete.** `--approve --reviewed-by <id> --expected-manifest-sha256
   <plan_sha256>` opens one native dialog (`오브제 로컬 바이트 비우기`,
   always-dialog, never grantable to a session permission mode). Per object:
   local re-hash; `HeadObject` then the full `GetObject` re-hash; a second
   local re-hash with identity capture; an execution-bound atomic proof
   marker; the handle-bound compare-and-delete; one immutable receipt
   (`receipts/providers/object-storage-offload/`, schema
   `wom-kit/object-storage-offload-receipt/v0.1`: `bytes_offloaded` or
   `review_required` with `remote_absent` / `remote_size_mismatch` /
   `remote_checksum_mismatch`, in which case the file is kept). One final
   manifest projection flips each removed object's local location to
   `availability: offloaded` with `offload_receipt_ref` and `offloaded_at`;
   bytes a capture re-materialised before the projection keep their row
   `available` and are counted.
3. **Interruption-safe.** A crash after the delete but before the receipt is
   recovered from the marker on resume without a second download; a marker of
   another execution or a torn marker never authorises a removal; a file that
   is absent without a marker of this execution refuses rather than
   receipting a deletion WOM did not perform; a resumed plan re-checks the
   draft predicates and refuses if a new draft references an object not yet
   removed.
4. **Every reader understands the tombstone.** Doctor reports an offloaded
   location as INFO `local_object_offloaded` (a `--strict` run stays green;
   the byte summary carries `offloaded_local_reference_count`) and warns
   `local_object_offloaded_but_present` when bytes exist under it;
   `backup-evidence` counts `offloaded_local_location_object_count` and
   `remote_only_object_count`; `staged-cleanup-check` defers the staged copy
   with `objet_bytes_offloaded_remote_only_restore_before_cleanup`;
   `resolve-objet-ref` sets `local_offloaded` and `restore_workflow` and
   prints `offloaded; run object-storage-restore`; the upload planner reports
   `offloaded_object_skipped_restore_before_upload` instead of blocking the
   store.
5. **Windows-only apply, by design.** The removal uses the codebase's
   handle-bound compare-and-delete primitive, which never mutates on POSIX;
   a plan is inspectable everywhere and approval is refused elsewhere with
   `object_storage_offload_platform_unsupported`.
6. **Never.** No `PutObject`, no `DeleteObject` (unreachable from the offload
   module), no manifest location removal, no provider body, URL, key or path
   in any result or receipt.

## Compatibility and privacy

- Existing plans, claims, receipts, journals and schema ids keep their exact
  bytes and validators. New: the receipt schema
  `object-storage-offload-receipt-v0.1`, the approval kind
  `object_storage_bytes_offload`, the Doctor codes `local_object_offloaded` /
  `local_object_offloaded_but_present` and summary counter, the
  backup-evidence counters, the staged-cleanup reason code and the additive
  resolver and upload-planner keys.
- The `offloaded` local-location availability (with `offload_receipt_ref`,
  `offloaded_at`) that v0.4.28 already read is now written; the
  object-manifest schema leaves `availability` free, so no schema change.
- No path, label, reviewer id, remote key, URL, draft content or archive
  content is introduced into results, diagnostics, tests or release
  artifacts.

## Verification boundary

The release candidate must pass the focused object-storage, Doctor,
staged-cleanup, backup-evidence, approval, resolver, privacy,
package-resource, installed-wheel and full supported-platform CI checks; the
offload execution cohort runs on the Windows shards only. The exact reviewed
merge commit must be tagged, and the public wheel must be downloaded
anonymously, rehashed, installed in a fresh CPython 3.12 environment and
checked in a new process. Those steps prove the public artifact; they do not
prove any client result. OB-02 closes for the client only on the client's
own offload run, and only after a restore has been exercised on the same
archive.
