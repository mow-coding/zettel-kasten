# WOM-kit v0.4.52 — large-activity performance and verification closure (letters 174-176)

This release finishes the implementable work that beta letters 174, 175 and 176 left open after v0.4.51. Installing the tool alone does not change a customer archive; every write still goes through the reviewed approval path.

## Large activities finish in realistic time (A14)

Every index-bound command scans the zet tree twice to bind the index to the live files. The scan no longer opens each zet file: on Windows it reads each directory's file ids in one call and cross-checks a fixed sample of entries against `os.lstat`, falling back to the per-file path on any difference. On the 23,000-object, 8,616-zet synthetic archive the installed official launcher measured, against public v0.4.47: `zettel-edge --dry-run` repeat p95 2.524 s to 0.881 s (65 %), `zettel-objet-link --dry-run` 2.717 s to 1.212 s (55 %), `exact-approval-claims --status all` 2.335 s to 0.891 s (62 %). Approval waiting, actual writes and remote transfer were not measured, and no customer PC was timed.

## A registered objet is found by its original filename (A17)

`source-intake-batch --stage-external` prepares one private name intake per staged copy. After capture, `objet-source-metadata-write --intake-batch <intake-execution-sha256>` writes every prepared name under one approval; `index` then `find-objet` locates the objet by its original filename (Windows only, like the single-row writer). Filenames never reach receipts, the object manifest or public results.

## The helper-AI guidance names only real commands (A13)

The installed-wheel gate reads the packaged runtime skill from the isolated wheel and proves that every command it names, and every invocation `ai-start-here` recommends, exists in the installed parser and capabilities manifest of the same version.

## Read, checkpoint and hold surfaces

- `read-zettel` overview edge previews carry the linked zet's title from the archive index, or an exact reason (`objet_has_no_human_label`, `target_not_indexed`, `target_redacted`, `index_missing`, ...).
- `session-handoff-checkpoint` returns `inbox_attention` and, when unpublished drafts exist, says that the checkpoint did not publish them.
- `draft-disposition --approve` reaches the dialog; its approval context carried unsorted review codes and refused before the dialog.
- A blocked `git-backup` plan reports its changes as not observed (`change_summary.count` null) with a content-free blocking role and size bucket, instead of zero changes.
- The runtime skill's `create-draft` example carries every flag its own contract requires, and the publish row names `zet-quality-check`.

## Verification items S2-U01..U25

Twenty-five verification items from the 2026-09-28 audit now have synthetic tests on the example archive (`tests/test_s2_verification_*.py`); the gaps they found are recorded in `docs/archive-infra-decision-log-2026-09-29-s2-verification.md`. No canonical hold command exists yet; the two-count index discrepancy stays an unconfirmed observation.

## Boundaries

Everything above was validated with synthetic data, an injected approval dialog and the example archive. Real provider accounts, the physical Windows dialog and customers' own runs are not confirmed.

## Install after publication

Use the exact public release asset after its hash and size are reported:

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0452-$womBootstrapNonce"
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.52/wom_kit-0.4.52-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require `archive 0.4.52` from a new process, then follow the reviewed `project-version-update` flow for an existing project.
