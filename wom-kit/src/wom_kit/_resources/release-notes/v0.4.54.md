# WOM-kit v0.4.54 — delivered letters deleted, private Git remotes read, old index copies removed

This release carries the owner's 2026-09-30 correction and finishes the items of beta letter 177 that v0.4.53 left open and answers beta letter 178, which reported that the customer could not update past v0.4.52. Installing the tool alone does not change a customer archive; every write still goes through the reviewed approval path.

## An update that did not finish its result delivery no longer blocks the next update (letter 178)

Letter 178 reported that an approved update to v0.4.52 succeeded but left `post_update_attention_required` with an unacknowledged result delivery, and that the v0.4.53 preview then stopped with `project_version_update_terminal_cleanup_outcome_unknown`. Reproduced through the real CLI: one unrelated operation journal that fails the strict reader (for example a torn last line from a killed process) made the delivery re-check fail silently. Such journals are now skipped (they cannot carry the proof a delivery needs, so no check is weakened). An unacknowledged delivery names `result_delivery_failure_code`; a delivery left pending is named in the next preview with the exact command; every advised resume line is complete (`archive project-version-update <archive-root> --resume --affirm-external-writers-quiescent --format json`); and an `outcome_unknown` result now names its `cause_code` and a names-free `residue_inventory`. For a project already in this state: run that resume command once with the project's current launcher, then preview again.

## A letter names the AI, model and reasoning level that wrote it (letter 178)

A letter request now requires an `author` block (`ai_product`, `model`, `reasoning_level`, `source`), written as the first line of the environment section. Placeholders such as `미수집` are refused (`feedback_body_author_unconfirmed`) unless the person could not tell either, and the refusal says to ask the person. The guidance states that the person sees only `전달 전` and `전달 완료`; there is no further registration step.

## Delivered letters are deleted, not moved

Letters 164 and 168 asked for delivered letters to stop taking space on the PC. v0.4.36 read that as "move them to a folder outside the archive", so they stayed on the same disk. The owner corrected this: cleaning up delivered or resolved letters means deleting them. `operator-feedback-delete <archive-root> --dry-run` lists the delivered, acknowledged and resolved letters, their receipt counts and the bytes to be freed, without titles or paths; `--approve --reviewed-by <person:...> --expected-plan-sha256 <plan_sha256>` deletes them in one approval (one window, or the session grant). The letter, its body receipts and its revision snapshots are removed for good, and the record keeps only one line: the letter number, `status: deleted` and the date, so numbering, the ledger (`deleted` count) and `operator-feedback-body-check` (`deleted_record`) keep working. Letters not yet delivered are never touched. Letters that an older WOM moved out are deleted too when their folder is named with `--moved-folder`; a copy edited by hand and files WOM did not write are left alone. The move command `operator-feedback-archive` is removed.

## The general Git backup preview reads private remotes

The letter's "remote reference not observable" is explained: `git-backup-plan` read the remote without a login by default, which cannot see a private backup repository. It now uses the Git login already saved on the PC (`--credential-mode stored`, the same as the session backup and the writer); WOM never asks for, shows or stores it. `--credential-mode anonymous` remains for public repositories. When the remote still cannot be read, the plan names the next step.

## Old index copies no longer pile up

Every index run kept a new copy in `db/search-snapshots` (a full copy of the index) and in the relation, title and finder snapshot folders, and nothing deleted the old ones. After each run WOM now deletes older copies; the current one, the newest other one and anything younger than an hour stay. A copy that an earlier backup had committed to Git becomes a small deletion that the next backup records.

## Boundaries

Everything above was validated with synthetic archives and an injected approval window. Deletion is permanent and WOM cannot restore a deleted letter; Git history or backups made earlier still hold old files. No real private Git remote was queried, and the customer's own run is not confirmed.

## Install after publication

Use the exact public release asset after its hash and size are reported:

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0454-$womBootstrapNonce"
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.54/wom_kit-0.4.54-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require `archive 0.4.54` from a new process, then follow the reviewed `project-version-update` flow for an existing project.
