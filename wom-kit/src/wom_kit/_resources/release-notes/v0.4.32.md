# WOM-kit v0.4.32 — Beta letter 164 first half: finalize scanner, probe failure kinds, Git backup attention, permission preview

v0.4.32 answers the four bounded read-side findings of beta letter 164: the
`exact-approval-claim-finalize` receipt scan reads every receipt as a byte
stream and separates an oversize file from an unreadable one, so a large
Doctor receipt no longer blocks the close of a reviewed started claim; a
`project-version-update` snapshot that is unavailable names which Git probe
failed and how (timeout, exhausted probe budget, exit code, ...); session
start, backup evidence and work-session create/claim results say how much
local work Git does not yet hold — counts and days only; and
`set-permission-mode --dry-run` previews a permission grant without opening
a dialog.

Publishing or installing this release does not read or modify a client
archive. A client chooses when to run the exact public bootstrap and one
reviewed `project-version-update` to the public wheel
`wom_kit-0.4.32-py3-none-any.whl`. The release is not evidence that a client
result was repaired; that requires the client-run result and a new-process
verification.

## Conditional public artifact contract

Use this bootstrap only after the exact GitHub Release exists and lists the
wheel. The versioned URL alone is not proof that the asset is public.

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0432-$womBootstrapNonce"
if (Test-Path -LiteralPath $womBootstrapRoot) {
  throw "WOM bootstrap path must be new."
}
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.32/wom_kit-0.4.32-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require exactly `archive 0.4.32` from a new process. Installing this external
bootstrap does not replace a shared PATH tool or silently update any project.

## What changes

1. **Finalize receipt scanner (letter 164 ②).** `scan_receipt_references`
   streams every `*.json` regular file under the scan roots in 1 MiB chunks
   with a 64-byte overlap and searches for the `approval_<32 hex>` token; it
   no longer parses JSON, so a malformed or large receipt is scanned instead
   of counted as unreadable. The per-file ceiling is 256 MiB (was 2 MiB) and
   the file cap 500,000 (was 50,000). `write_evidence` gains `scan_method:
   byte_stream_search`, `oversize_skipped_count`,
   `oversize_skipped_receipt_paths`, `unreadable_receipt_paths` and
   `oversize_ceiling_bytes`; the plan reports `paths_echoed` and names the
   incomplete-scan step in `next_safe_actions`. Only an I/O failure or a
   file above the ceiling makes the scan incomplete, and the scan still
   fails closed on that.
2. **Probe failure kinds (⑤).** The capped Git runner records the fixed kind
   of its last failure (`argument_invalid`, `launch_failed`,
   `stream_unavailable`, `timeout`, `output_cap_exceeded`,
   `stream_read_failed`, `stdin_write_failed`; the observation adds
   `probe_budget_exhausted`). The snapshot observation returns `probes`
   (`probe`, `available`, `return_code`, `failure_kind` — never output) and
   the update preflight attaches `checks.git_transaction_snapshot.detail`
   (`observation_reason_code`, `probes`, `output_echoed: false`) when that
   check is `unavailable` or `failed`. Check states and reason codes are
   unchanged.
3. **Git backup attention (⑥).** New block `wom-kit/git-backup-attention/v1`:
   `uncommitted_change_count` (with `untracked_count` /
   `tracked_change_count`), `last_commit_age_days`, `upstream_state`,
   `ahead_count` / `behind_count`, `remote_tip_age_days`, fixed `attention`
   codes (`uncommitted_changes_present`, `commits_not_pushed`,
   `upstream_missing`, `remote_tip_older_than_7_days`,
   `last_commit_older_than_7_days`, `head_unborn`,
   `uncommitted_change_count_unavailable`), `review_recommended`, a
   `human_summary` of numbers, the per-probe list and
   `next_command` (`git-backup-plan --dry-run`). Local Git only, under one
   8-second budget with the safety flags of `git-backup-plan`; fail-quiet
   (`unavailable`, `git_unavailable`, `not_a_repository`). Attached to
   `ai-start-here` (`git_backup_attention`, `summary.git_backup_attention_state`,
   `summary.uncommitted_change_count`, a warning and a next step when
   review is recommended, Markdown section `Git Backup Attention`),
   `backup-evidence` (`lanes.github.local_repository_attention`,
   `local_commit_inspected` / `closed_actions.git_repository_inspected`
   true, warning and next action; lane status unchanged) and the
   `work-session` create / claim envelopes (`git_backup_attention` next to
   `inbox_attention`). No path, branch name, remote URL, subject or hash is
   returned (`paths_branches_or_messages_echoed: false`).
4. **Permission-mode preview (⑦).** `work-session --action
   set-permission-mode --dry-run` (no `--approve` / `--apply` / `--resume` /
   `--review-original`) resolves to the read-only mode
   `permission_mode_preview` and returns
   `wom-kit/work-session-permission-preview/v1`: `would_set`,
   `permission_modes`, `grantable_operations`, `always_dialog_operations`,
   `session_state_read: false`, `native_approval_required_for_write: true`
   and, on refusal, the fixed `reason_code` with its positional
   `reason_detail`. No dialog, no session read, no write.

## Carried to v0.4.33 and v0.4.34

v0.4.33: `object-storage-upload` reopened under the exact approval contract
(letter 164 ①) with `writer_unavailable` reported first, `--local-bytes-only`,
`--progress` and byte-external exclusion before the manifest compare (③),
store-ref label validation (④), and a select-all group convenience for
`git-backup-reconcile-plan --approve` (the existing one-approval commit+push
route). v0.4.34: archival of delivered feedback letters, receipts and
requests outside the archive (⑧) and same-generation index participation
for approved writes (8b, confirmed by ⑨). The writer-session coverage
targets for restore, offload and claim finalize move to v0.4.33.

## Compatibility and privacy

- Additive keys only: `git_backup_attention` on three results,
  `local_repository_attention` and `git_paths_branches_or_messages_echoed`
  on backup-evidence, `detail` on the `git_transaction_snapshot` check,
  `probes` on the snapshot observation, the new `write_evidence` fields; one
  new read-only work-session mode and one new result schema
  (`wom-kit/work-session-permission-preview/v1`). No new command, alias or
  packaged schema file.
- Behaviour changes to note: a finalize plan that was blocked by
  `exact_approval_claim_evidence_scan_incomplete` on a large receipt now
  scans it; `backup-evidence` now inspects the local repository
  (`closed_actions.git_repository_inspected: true`) but never the network.
- No path, branch, remote URL, commit subject, reviewer id, draft content or
  archive content is introduced into results, receipts, tests or release
  artifacts.

## Verification boundary

The release candidate must pass the v0.4.32, v0.4.31 and v0.4.30 test
modules, the update-preflight, capped-runner, backup-evidence, start-here and
work-session cohorts, the pin sweep and the full supported-platform CI. The
exact reviewed merge commit must be tagged, and the public wheel must be
downloaded anonymously, rehashed, installed in a fresh CPython 3.12
environment and checked in a new process. Those steps prove the public
artifact; they do not prove any client result.
