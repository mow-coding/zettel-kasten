## 이전 기록과의 관계

이날 앞선 운영 논의는 특정 다음 버전의 프로세스 릴리스로 표현했다. 사용자는 이후 현재 목적을
더 넓은 개발 방식 설계로 교정했고, 최종적으로 문서 작성 계획의 실행을 요청했다.
앞선 릴리스 인계는 역사적 작업 맥락이며 DP-01을 덮어쓰지 않는다.
과거 특정 통합 작업의 중간 베타 금지는 그 작업에 한정한다. AI 교대와 현재 베타 정책의 일반 금지로 사용하지 않는다.

## 구현과 검증의 구분

이번 변경은 개발 안내·양식·운영 정책과 로컬 기록이다. 제품 API·CLI·MCP·고객 UI를 변경하지 않는다.
사례 대입은 작성자의 문서 검토다. 독립 검토, 실제 AI 교대, 제품 실행, 공개 wheel 또는 고객 확인을 대신하지 않는다.
운영 문서의 공개·커밋 상태와 검증 결과는 현재 작업표에서 확인하며 추정하지 않는다.

완료 후 사용자의 품질 확인 요청에 따라 별도 컨텍스트에서 독립 문서 검토를 추가했다.
실질적 모순·차단 문제를 발견하지 못했으며 실제 제공자 교대 시험은 여전히 미실행이다.
사용자의 기존 CI 질문에는 읽기 전용 조회와 실패 원인 대조로 답했고, 문서 완료를 제품 출시 승인이나 검사 통과로 취급하지 않았다.

## 문서 단계 이후의 범위 재확인

- **DP-11 — 사용자 확정 / 현재 적용:** 사용자는 운영 문서 정리 후 기존 릴리스 작업의 재개를 지시했고, CI 완료 후 다음 절차를 이어가라고 재확인했다. DP-01의 문서 전용 제한은 당시 단계에 한정된다. 수정 후보의 CI를 확인한 뒤 기존 검증·출시 절차를 순서대로 수행한다. 문서 공개와 후속 자동화 구현의 완료를 주장하지 않는다.
- **DP-12 — 접수 분류 / 현재 적용:** 후속 보고는 기존 문의에 연결하고 성공한 후속 실행, 에이전트 사용 오류, 미확인 제품 문제를 구분한다. 피드백 편지 초안과 미발행 zet 초안은 별개 기능이다. 정확한 프로젝트 자료 집합 선택과 원격 전송 장애도 별개다. 공식 경로를 먼저 확인하고 합성 재현으로 판단한다. 고객 원문과 접수 연결표는 로컬에만 둔다.
- **DP-13 — 기존 사용자 결정 유지:** 이전 버전 보고서가 승인창 예외를 정상이라고 해석해도 최신 사용자 결정의 변경으로 간주하지 않는다. 전체 액세스의 임의 제외 목록을 복원하지 않으며 만료 정책과 영구 승인을 혼동하지 않는다.

- **DP-14 — 사용자 요청에 따른 이번 출시 전용 후속 확인:** CI가 끝나면 나머지 출시를 이어가라는 지시를 현재 대화의 예약 확인으로 연결했다. 같은 작업을 중복 시작하지 않고 변경 없는 대기는 알리지 않으며, 해당 출시의 증거·답장·정리까지 마치면 비활성화한다. 상시 베타 배포나 제품 CI 자동화의 도입 완료와 구분한다.

- **DP-15 — 이번 출시 종료 / 정리 예외 인계:** v0.4.36 공개 파일의 exact-tag 검사·익명 검증·두 새 설치와 증거 PR 병합을 완료했다. 작업 소유 브랜치와 격리 작업공간을 정리하고 기존 운영 문서는 보존했다. 자동 승인 검토가 삭제를 거부한 검증용 임시 환경 등은 정리 완료로 표시하지 않고 로컬 작업표에 위치·사유를 남긴다. 완료된 출시에 대한 반복 확인은 종료하며 고객 수용·로컬 성능 원인·신규 피드백·운영 자동화 구현은 별도 후속 상태로 유지한다.

- **DP-16 — 답장 안내의 혼동 교정:** 사용자가 여러 문의자의 답장을 구분하기 어렵다고 알려 왔다. 답장 전달 시 대응 원문과 처리 상태를 함께 명시하며, 이미 출시한 별도 문의의 답장을 후속 보고의 해결 답장으로 안내하지 않는다. 실제 수신자 신원은 확인된 자료 없이 추정하지 않는다. 문의별 매핑과 원문 연결은 비공개 접수 기록에 남겼다.

- **DP-17 — 사용자 승인 대조 / 실행 오류와 제품 개선 분리:** 문의 원문·출시·고객 결과를 대조하여 성공한 하위 경로, 고객 확인 대기, 미완료, 조사 전을 구분한다. 부분 검사 성공을 전체 운영 준수나 문의 해결로 보고하지 않는다. 기존 원장·본문 바인딩·전달 상태 기능의 미사용과 자동 식별자 발급·정식 전달 준비 판정의 추가 필요는 별도로 조사한다. 개발진 접수는 실제 열람 근거로 기록하며 식별자 누락과 미열람의 인과를 추정하지 않는다. 후속 개선은 새 승인창을 추가하는 근거가 아니며 전체 액세스 결정을 유지한다. 원문·수신자 연결·상세 대장은 비공개로 유지한다. 이번 대조는 제품 구현·새 출시가 아니다.

- **DP-18 — 신규 범위 문제 접수 / 조사 착수:** 승인창 없는 실행의 성공과 데이터 대상 범위의 적절성은 별개다. 현재 작업이 포함된 전체 목록을 현재 작업만의 목록이라고 보고하지 않는다. 세션·명시 목록의 선택 계약, 공유 객체, 부분 실행의 중단 후 새 계획 전환을 합성 자료로 조사한다. 이미 발생한 외부 효과를 무효과 종결로 취급하지 않고 근거를 보존한다. 전체 액세스에 임의 승인창 예외를 추가하지 않는다. 문의별 성공 범위와 후속 문제는 비공개 대장에 연결한다.

- **DP-19 — 사용자 확정 / 범위 수정 구현:** 조사에 그치지 말고 즉시 구현한다는 지시와, 기본은 현재 세션이되 사용자가 다른 세션의 일도 명시적으로 위임하면 함께 처리할 수 있어야 한다는 추가 결정을 반영했다. 정확한 세션·객체 목록·전체 명시 선택을 허용하며 승인창 예외를 추가하지 않는다. 별도 작업공간에서 수정·로컬 검증·PR을 만들었으며 전체 CI·공개출시·고객 수용은 독립된 미완료 단계로 기록한다.


- **DP-20 — 사용자 재지시 / 현재 작업에 운영 개선 적용:** 합의한 운영 개선을 문서 작성으로 끝내고 매번 다음으로 미루는 것은 요청 불이행이다. 이번 작업에서 CI 분류·정확한 검증 재사용·베타 설치와 갱신·순차 공개·증거·접수 폼을 구현하고 실제 실행 근거로 완료를 판단한다. 진행 중인 제품 검사는 보존하며 고객 전달과 운영 적용을 각각 끝까지 추적한다.
- **DP-21 — 위임 범위 내 구현 선택:** 태그와 wheel에 같은 정규 베타 표기를 사용한다. GitHub run number로 구분하고 생성 커밋은 main의 검증된 소스를 부모로 둔다. 안정판 최신 검색은 베타를 제외한다. 새 승인창이나 전체 액세스 예외를 추가하지 않는다.

- **DP-22 — 원격 실패에 따른 검증 교정:** 베타의 실제 복구 여정 완료와 최종 wheel 검증 통과는 별개다. 최종 증거 보존 경계에도 동일한 정규 베타 버전을 적용하되 잘못된 버전과 불완전 증거는 거부한다. 구식 CI 환경변수명 검사 대신 현재 필수 결과 집계 계약을 확인한다. 실패한 후보를 병합하거나 성공으로 표시하지 않고 원인 수정 후 새 후보를 검증한다.
- **DP-23 — 실제 배포 입력 검증:** Windows 작업 파일과 Git 저장본의 줄바꿈 차이를 고려하여 리소스 지문은 Git에 저장될 실제 원본·미러 바이트와 대조한다. 로컬 동기화 성공만으로 커밋 입력의 일치를 단정하지 않는다.

- **DP-24 — 회귀 기대값 교정과 검사 보존:** 베타 지원으로 달라진 안내 문구의 기대값을 수정하되 잘못된 메타데이터 거부와 개인정보 비노출 검사는 유지한다. 이미 진행 중인 플랫폼 결과를 수집한 뒤 필요한 수정을 함께 올려 반복 취소를 줄인다. 실패 결과를 통과로 재분류하지 않는다.

- **DP-25 — 사용자 재지시 / 이번 PR에 증분 검증 적용:** 문서 전용 단축만으로 변경 영향별 재검사 합의를 이행했다고 하지 않는다. 동일 제품·검사 실행 입력의 완료 베이스라인을 대조하여 기대 문구 수정에 해당하는 검사와 미도달 검사만 다시 실행한다. 실패·취소·누락을 성공으로 바꾸지 않으며 실제 증분 실행을 완료 조건에 포함한다. 변경 없는 설치 파일은 현재 후보의 통과 및 출처 대조 후 재사용한다.

## DP26 — 원격 로그 도구 차이로 생긴 중복 검사 교정

원격 gh의 ANSI 로그 출력 거부를 실제 오류로 확인했다. 증거 바이트를 바꾸지 않고 명시된 raw 출력 옵션으로 읽기를 재시도한다. 실패 원인은 숨기지 않으며 잘못 선택된 중복 전체 실행은 취소하고 새 후보의 실제 증분 통과를 확인한다.

## DP27 — draft 공개 복구와 배포 도구 전용 검사

실제 자동 배포의 draft 조회404를 교정하고 검증된 자산으로 공개 단계만 재개한다. 인증 목록의 유일한 numeric release ID로 draft를 조회한다. 배포 도구 전용 변경은 제품 실행 계약 불변을 확인하고 Linux/Windows 도구 회귀와 빠른 gate를 수행한다. 설치 성공, 공개 성공, 익명 새 설치 성공을 구분한다. 상세: [공개 복구 기록](../../meeting-minutes/2026-09-22-beta-publication-recovery.md).
