# WOM 설계 철학 구현 근거

상태: v0.4.45 후보에서 다시 검토한 v0.3.252 공개 추적성 점검
날짜: 2026-09-16

## 목적

WOM의 설계 철학은 설득력 있는 글에만 머물면 안 됩니다. 이 문서는 핵심
원칙마다 실제로 적용하는 실행 표면, 그 원칙을 지키는 회귀 테스트, 그리고
WOM이 아직 정직하게 증명할 수 없는 경계를 연결합니다.

근거는 의도적으로 세 층으로 나눕니다.

1. **공학적 구현**: 공개 릴리스에 명령, 스키마, 영수증, AI 운영 규칙 또는
   결정론적 검사가 있습니다.
2. **실사용 검증**: 실제 아카이브에서 그 장치가 유용한 의미를 보존하는지는
   사람과 운영 AI가 계속 시험해야 합니다.
3. **외부 서비스별 미래 작업**: 원격 작업이나 완료 상태를 주장하려면 해당
   외부 서비스에 맞는 별도 계약이 필요합니다.

공학 검사를 통과했다고 다른 두 층까지 자동으로 충족되는 것은 아닙니다.

WOM은 지속되는 맥락과 근거를 기록하지만 호스트 세션 생명주기를 통제한다고 주장하지 않습니다. |

HEAD와 전체 GET 재해시 및 영수증은 기록된 작업의 정확한 오브제 하나만 증명하며 현재 전체 보관함 백업 완료를 증명하지 않습니다. |
| 쓰기는 사람 검토, 출처, 명시적 승인 경계를 요구합니다. | 지원되는 정확한 작업 흐름은 Windows 기본 확인창, 인증된 일회용 `started` 기록, 쓰기 직전 재검증, 작업 흐름의 최종 판정을 사용합니다. v0.4.14는 사람이 대상을 알아볼 수 있도록 현재 SHA 결속 계획에서 얻은 제한된 파일명·제목·요지·역할·연결 대상을 보여줄 수 있습니다. v0.4.15는 live lock과 인증된 sealed plan에서 중단된 update의 정확한 문맥을 복원하고, 호출자 identifier나 두 번째 결정 없이 checkpoint-valid claim 하나만 인정하며 정합될 때까지 일반 writer를 막습니다. lock 상태의 유일한 예외는 별도로 exact 승인된 create-only operator feedback body 보존이고, metadata를 고치거나 `version-update.lock`을 바꿀 수 없습니다. 안전하지 않은 선택 정보는 생략하며 영구 권한으로 기록하지 않습니다. 완전한 작업별 결속이 없는 경로는 미리보기·계획·감사 전용이거나 사용 불가 상태로 남습니다. | exact-human 작업 흐름 테스트, 인증된 update resume·긴급 feedback guard 테스트, 개인정보를 걸러내는 대상 미리보기 테스트, CLI 도움말·서비스 fail-closed 테스트. | WOM은 명령 경계를 검증할 수 있지만, 사람이 모든 의미상 결과를 이해했다고 추론할 수는 없습니다. resume는 이미 승인된 정확한 문맥만 재사용하며 새 target 권한을 만들지 않습니다. 미리보기 단서나 과거 승인 영수증은 현재 쓰기 권한이 아닙니다. |
| AI 생성 문서와 대화에서 나온 작업은 증발하면 안 됩니다. | `ai-artifact-inventory`가 로컬 AI 산출물을 분류하고, 작업기록이 미완료 작업을 남기며, `session-handoff-checkpoint`는 지속 기록 근거가 없거나 낡으면 깨끗한 인수인계를 막습니다. | AI 산출물 목록과 세션 인수인계 CLI 테스트. | 도구는 채팅을 자동 수집하거나 어떤 생성 문서를 보존해야 하는지 대신 결정하지 않습니다. 사람과 AI의 검토가 계속 필요합니다. |
| AI 운영은 필요한 것부터 단계적으로 읽고 사람에게 쉬운 말로 설명해야 합니다. | 배포되는 Agent Skill은 짧은 시작 문서, 목표별 참고문서, 기계 판독형 기능 목록, 사람말 응답 계약과 용어 안내를 제공합니다. 승인 화면에서는 개수·해시·대상 상태를 WOM이 검증하고, 사람은 쉽게 설명된 작업을 지금 할지만 결정합니다. 안전한 로컬 전용 단서는 영수증이나 공개 출력에 남기지 않으면서 대상을 알아보게 돕습니다. | runtime skill 패키지 검사, 기능표 테스트, 승인 미리보기 개인정보 테스트, 문서 계약 테스트. | 쉬운 설명과 좋은 판단은 AI 지침 수준의 동작입니다. WOM은 모든 모델 답변의 품질을 결정론적으로 검사할 수 없으며, 안전하지 않아 생략한 단서를 비공개 맥락 노출로 대신해서는 안 됩니다. |

v0.4.36은 사람에게 한 약속을 지킵니다. 2026-09-17에 사용자가 설계한 스위치는 그가 말한 그대로를 뜻하고, 멈춘
writer는 왜 멈췄는지 말하며, 전달이 끝난 편지는 애초에 제 것이 아니었던 아카이브를 떠날 수 있습니다.

v0.4.35는 미러에 한 약속을 지킵니다. 공개 기록이 한 사람을 지키려 과거를 바꿔야 했을 때, 업데이터는 그것을
고정 코드로 말하고 사람이 확인한 뒤에만 움직이는 법을 배웠습니다.

v0.4.34는 내어 준 신뢰에 얼굴과 시계를 줍니다. 사람이 한 대화에 준 승인은 이제 어느 대화가 쓰고 있는지와
언제 끝나는지를 알고, 아카이브는 누구도 열쇠를 못 찾았기를 바라는 대신 클레임에 그것을 적습니다.

v0.4.33은 닫았던 손으로 문을 다시 엽니다. 사람이 기다려 온 업로드는 새 장치가 아니라 아카이브가 이미
믿던 두 가지 — 보존 PUT과 채택 투영 — 를 창 하나 아래 합친 것이어서, 아카이브가 거기서 배우는 것은
이미 검증할 줄 알던 바로 그것입니다.

v0.4.32는 침묵이 말하게 합니다. 세션 시작은 사람의 작업 중 Git이 아직 갖지 않은 양을 말하고, 막힌
닫기는 읽지 못한 파일을 말하며, 잃어버린 스냅샷은 어느 프로브가 왜 실패했는지 말하고, 승인 요청은 창이
결정을 묻기 전에 미리 확인할 수 있습니다. 도구가 증명할 수 없는 것을 이제 숫자로, 읽어서는 안 될 것을
읽지 않고, 분명하게 말합니다.

v0.4.31은 거절이 가르치게 합니다. 막힌 초안은 빠진 옵션의 이름을 말하고, 경고는 어느 행을 읽었는지
말하며, 실패한 업데이트는 자기 계열과 앞을 막고 있는 것의 모양을 말하고, 낡은 인덱스를 건드릴 쓰기는
누군가에게 승인을 묻기 전에 그렇게 말합니다. 사람은 다음 단계를 코드를 뒤져서가 아니라 거절 그
자체에서 배웁니다.

v0.4.30은 거절이 일어나는 그 순간에 정직하게 합니다. 진행할 수 없는 발행은 1회용 claim을 잡기
전에 그렇게 말하고, 실패는 두루뭉술한 단어 대신 고정된 원인을 이름 붙이며, 이전 실패가 열어 둔
클레임은 검토한 사람이 보고 닫을 수 있고, 영수증은 정확히 무엇을 확인했는지 적습니다. 일어나지
않은 일에 대한 근거는 검색한 범위를 넘어 주장하지 않습니다.

v0.4.29는 로컬 권위가 자기 조건으로 놓아주게 합니다. 원격 사본을 통째로 다시 읽어 증명하고,
로컬 바이트를 두 번 증명하고, 아직 끝나지 않은 생각이 그 바이트에 기대지 않음을 확인한 뒤에야
로컬 사본을 지우며, manifest에는 이름 붙고 영수증 달린 되돌릴 수 있는 표시가 남습니다. 용량을
비우는 일은 돌아오는 길이 이미 열린 상태에서 사람이 내리는 결정이지, 조용한 손실이 아닙니다.

v0.4.28은 백업 계층을 로컬 권위에 종속시킵니다. 원격 사본은 통째로 내려받아 오브제 id를
재현할 때만 인정되고, 검증된 바이트는 새 파일로만 로컬 오브제 저장소에 돌아오며(기존 파일
위에 덮지 않음), 원격 오브제는 절대 지우지 않습니다. 로컬이 정본이고 클라우드는 돌아오는
길이며, 나가는 길보다 돌아오는 길이 먼저 생겼습니다.

v0.4.27은 거절을 유익하게 만들되 유출로 만들지 않습니다. 거절된 입력은 그 위치와 썼어야 할
고정 어휘로 이름 붙이지, 입력한 값을 되풀이하지 않으며, 사용법 실수는 조용한 종료가 아니라
고정 코드로 남습니다.

v0.4.26은 사람이 살펴보는 단계를 정직하게 유지합니다. 사람이 보겠다고 한 대상
목록이 이제 실제로 열리고, 창이 아직 확인하지 않은 페이지는 읽을 수는 있어도 승인할
수는 없으므로, 자세히 본다는 이유로 내리려던 결정을 잃지 않습니다.

v0.4.25는 기록된 사실을 그것을 써야 하는 코드가 읽을 수 있게 유지합니다. update
사전 검사가 적어 둔 위치는 사람이 지정한 root 기준으로 참이었고, 이제 모든 소비자가
다른 root를 추측하는 대신 그대로 읽으므로, archive root에서 내린 승인은 존중되고 멈춘
트랜잭션은 새 결정을 지어내지 않고도 풀립니다.

v0.4.24는 그 경계를 쓰기마다가 아니라 세션마다 한 번 사람이 정하게 합니다. 승인
모드는 claim한 세션에 기록된 사람의 결정이고, 모드가 허용한 쓰기도 여전히 자기
몫의 1회용 claim을 남기며, 그 claim은 실제 승인 창이 아니라 세션의 모드로 발급됐다고
스스로 말하므로, 기록은 승인 창 없는 쓰기를 사람이 있었다는 증거로 내세우지 않습니다.

v0.4.23은 같은 경계를 두 경우로 넓힙니다. 바이너리 원본은 기계적 비교를 주장하지
않은 채 바이트 동일성으로 요약·파생 초안을 뒷받침할 수 있고, 초안은 사람이 승인하는
바로 그 계획에 내용 없는 소유 사실을 고정해 claim한 작업 세션에 귀속되므로, 영수증은
라벨이나 경로를 드러내지 않고도 어느 세션이 썼는지 말합니다.

v0.4.22는 같은 경계를 실패 경로에서도 정직하게 유지합니다. 사람이 승인한 뒤에
실패한 project update는 이제 어떤 고정 gate가 거부했고 어느 단계에서 멈췄는지를
텍스트·경로·메시지 없이 말하고, 아무것도 쓰지 않아 `started`로 남은 claim은
journal이 그 사실을 증명하는 동안에만 운영자가 닫을 수 있으며, 기존의 claim 없는
취소가 예약을 풉니다. 느린 디스크는 더 이상 잘못 설정된 origin으로 보고되지
않습니다.

v0.4.21은 승인 경계를 정직하게 유지하면서 v0.4.0 compound 폐쇄가 가져간
writer들을 되돌려 줍니다. 초안 버리기와 복원, 엣지·발행·퇴역·되돌리기 배치,
의미 개정 쌍은 다른 모든 v0.4 writer와 같은 작업별 정확 사람 승인으로 다시
열립니다. 새 비공개 preflight, 정확한 계획의 내용 없는 binding, native
대화상자 하나, 첫 바이트가 바뀌기 전에 다시 검증되는 일회용 인증 claim
하나입니다. 배치는 모든 항목의 자기 binding을 덮는 대화상자 하나이고, 각
항목 쓰기는 배치 승인이 자신을 덮는다고 가정하지 않고 새 binding이 승인된
항목임을 증명합니다. 세 단계 오브제 반입은 앞 단계가 쓸 바이트로 모든
단계를 미리 계획해 승인 한 번으로 실행되며, 앞 단계 쓰기 뒤의 실패는 숨기거나
거짓 깨끗한 상태로 되돌리지 않고 쓰인 경로와 함께 partial로 보고합니다.

v0.4.20은 정직성을 WOM 자신의 이전 쓰기에도 적용합니다. 이전 `zettel-edge`
재작성이 구분 줄을 지운 초안은 사람이 망가뜨린 것처럼 거부하지 않고 정규화한
뒤 경고로 보고하며, 근거 원본을 asset으로 연결한 것을 비공개 권한 노출로
보고하지 않습니다. 차단된 초안 승격은 재사용 가능한 승인 값을 돌려주는 대신
이유를 말합니다. archive 쓰기는 작업 세션 identity를 가질 수 있고, 세션의 Git
backup은 head·index·worktree 증거로 그 세션에 귀속할 수 있는 것만 commit하며
나머지는 주장하지 않고 `ownership_unverified`로 남깁니다. writer-session
coverage gate는 통합·대기·예외 승인 경로의 정확한 개수를 출력하므로, parser보다
먼저 어떤 문서도 모든 writer를 다 덮었다고 주장할 수 없습니다.

v0.4.19는 같은 정직성 원칙을 기계 관찰에도 적용합니다. 읽을 수 없거나 앞
단계 때문에 실행하지 못한 검사를 확인된 불일치·부재·성공으로 표시하지 않습니다.
updater 준비는 개인정보가 없는 고정 필드별로 다시 검증하고, parser 안내부터 실제
dispatch까지 하나의 capability 결정을 공유합니다. 따라서 AI는 사람에게 hash·path·
비공개 machine state를 해석하라고 떠넘기지 않고 실패, 미실행, 검증 불가를 구분해
설명할 수 있습니다.

v0.4.18은 사람 경계를 단순 방어가 아니라 실제로 끝나는 흐름으로 유지합니다.
fresh preview와 approval은 같은 기계 분류를 사용하고, project가 지나간 완료된
원본을 포함한 exact terminal control 이력은 identifier 없는 복구로 이어집니다. WOM이 비공개 파일 집합·identity·hash·archive
identity·cleanup authority를 검증하므로 사람이 filesystem forensic이나 기계 개수
재현을 하지 않습니다. WOM이 만든 exact control 이력만 project-domain write나 새
approval 권한 없이 canonical proof 이력으로 정합할 수 있습니다. 약하거나 변경·
혼합·unsafe한 근거는 계속 멈춥니다. 따라서 안전은 지원되지 않은 effect를 거부하는
것과 충분한 근거가 있을 때 evidence-bound 복구를 결정론적으로 끝내는 것을 모두
뜻합니다.

v0.4.16은 cleanup 전에 인증된 update 사실을 비공개 durable terminal handoff로
보존하고, 나중에 결속된 동일 output을 재사용하기 전 정확한 succeeded claim과
postimage를 다시 인증합니다. 불변 journal과 `active` -> `display-pending` ->
`consumed` handoff는 cleanup·독립 resource close·durable output 사실을 구분합니다.
consumed는 이력이고 acknowledgement는 사람이나 AI가 실제로 봤다는 증거가
아닙니다. exact하고 완전한 legacy residue는 복구할 수 있지만 cleanup proof만으로
과거 success를 주장하거나 cleanup·handoff·automatic retry 권한을 만들 수 없습니다.
따라서 보고 단계가 실패해도 durable 근거를 잃지 않으면서 모든 후속 control
단계가 성공했다고 과장하지 않습니다.

## 현재 공학적 결론

공개 v0.4.36 구현에는 메멘토 문제를 다루는 구체적이고 회귀 테스트된 장치가
있습니다. 첫 읽기 재구성, 아티팩트 우선 추론, 검토된 수정과 복구, 지속되는
세션 인수인계, 정직한 로컬 백업 근거는 단순한 로드맵 문구가 아닙니다.

그렇다고 WOM이 완성됐다는 증거는 아닙니다. 남은 경계는 주로 실증 또는 외부
서비스별 작업입니다.

- 실제 말뭉치가 변할 때 초록 데이터가 의미상 계속 유용한지 시험해야 합니다.
- 세션 인수인계가 사람이 정말 중요하게 여긴 결정을 보존하는지 시험해야 합니다.
- 수정과 복원 흐름은 실제 사용 관찰을 계속 받아야 합니다.
- GitHub와 외부 DB 완료를 주장하려면 외부 서비스별 근거 계약이 필요합니다.
- 지금 원격 오브제가 존재하는지 확인하려면 로컬 영수증만이 아니라 실제 외부
  서비스 검증이 필요합니다.
- WOM을 공개하거나 설치했다고 클라이언트 아카이브에 복구가 적용되는 것은
  아닙니다. 그 아카이브에서 별도 승인 실행, 지속 영수증, 독립 사후 검증을
  마쳐야 합니다.

이것들은 숨겨진 구현 주장이 아니라 명시된 검증 경계입니다.
