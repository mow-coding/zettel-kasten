현재 실행 단계: 사용자 재지적으로 운영 자동화 구현을 재개했다. 아래 최초 문서 작업의 범위는 역사적 기록이다. P1 구현 후보와 실제 실행 근거를 구분하며, P2~P5는 설치·갱신·다운로드 증거까지 확보해야 완료한다.

# 개발 운영 개선 도입 계획과 점검

기준일: 2026-09-21. 목표는 AI 교대 시 맥락 손실과 반복 작업을 줄이는 것이다.
최초 문서 단계는 개발 문서를 작성하고 연결하는 작업이었다. 아래 과거 범위 설명은 당시 기록이며, 현재는 사용자 재지시에 따라 운영 자동화를 구현·검증 중이다. WOM 버전 번호를 올리거나 제품 기능·CI·배포 설정을 변경하지 않는다.
추가 요청에 따라 사용자가 지정한 개발 폴더의 이상 항목을 확인하고, 불필요함이 확인된 빈 폴더만 정리한다.
공개 레포에서 협업 방식을 찾을 수 있도록 README에 연결하고 공개·비공개 자료 구분을 문서화한다.

## 1. 단계별 결과와 완료 조건

| 단계 | 결과물 | 완료 조건 | 이번 작업 상태 |
|---|---|---|---|
| P0 규칙과 인수인계 | 공통 규칙, 두 AI 시작 안내, 현재 작업표·접수 양식, 회의록·결정 로그 | 두 시작 안내가 같은 규칙을 연결하고 현재 범위·결정·다음 행동을 찾을 수 있음 | 문서 작성·사례 대입·로컬 문서 검사 완료; 실제 AI 교대는 후속 확인 |
| P1 CI 분류 | 문서 전용 분기와 정확한 결과 집계 | 문서만 변경/실행 영향 변경/실패/취소/허용 생략/알 수 없는 경로를 구분하고 기존 필수 검사를 유지 | 구현/실행 검증 진행 중; 완료 아님 |
| P2 베타 배포 | main 커밋별 wheel과 prerelease | 버전·updater·공급 잠금·새 설치·갱신·재시도가 함께 통과; 안정판 채널 유지 | 코드 구현 후보; 실제 원격 실행 검증 전 |
| P3 안정판 절차 연결 | 병합과 출시 구분, 준비 여부 기록 | P2 베타를 안정판 검증으로 오인하지 않고 정확한 출시물 검증; 주간 검토 결과 기록 | 정책 문서만 작성; 자동화 없음 |
| P4 증거 자동 수집 | 공통 기계 증거와 읽기 쉬운 요약 | 소스·검사·배포물·공개 확인의 대응, 누락·실패·재시도 사례 확인 | 코드 구현 후보; 실제 원격 실행 검증 전 |
| P5 공개 접수 폼 | 정제된 보고용 이슈 폼과 추적 항목 | 비공개 원문 없이 합성 재현을 접수하고 기존 항목·PR·배포·고객 확인과 연결 | GitHub 폼 구현 후보; 공개 전 |

P1 → P2 → P3 → P4 → P5 순서로 후속 구현한다. P3의 문서상 판단 기준과 P5의 수동 접수 양식은 지금 사용할 수 있다.
후속 단계는 각각 범위·변경 파일·검증 방법을 정한 작업표에서 시작한다. 이 표만 보고 보류된 릴리스를 재개하지 않는다.
기존 릴리스 브랜치의 제품 변경과 운영 문서 변경을 하나의 버전 작업으로 섞지 않는다.

현재 root `AGENTS.md`는 저장소에서 무시되는 로컬 시작 안내이고, `CLAUDE.md`와 공통 규칙은 공개 가능한 개발 문서다.
최초 문서 단계에서는 파일만 작성했다. 현재 단계에서는 실제 적용을 위해 검증 후 공개 PR과 병합까지 진행하며, 공개 전에는 새 checkout에서 읽을 수 있다고 보고하지 않는다.
문서 공개 작업 시 정확한 파일 목록과 개인정보 검토를 거쳐 공유할 시작 안내를 포함하고,
로컬 현재 작업표·원본 인수인계는 공개 대상에서 제외한다. 어떤 문서가 자동으로 AI 컨텍스트에 주입됐는지까지 보장하지 않는다.

별도 AI가 실제 인수한 시험, 제품 명령 실행, 고객 환경 검증을 수행한 결과가 아니다.

## 3. 문서 검증 방법

- 기존 공개 링크 검사로 공개 문서 간 연결을 확인한다. 무시된 로컬 문서는 별도로 파일 존재와 연결을 확인한다.
- 기존 개인정보 검사와 변경 파일 직접 검토를 함께 수행한다. 공개 대상에는 실제 계정 경로·고객 식별자가 없어야 한다.
- 한국어 제품 용어 검사를 수행한다. 문서의 기술 명칭과 사용자에게 보이는 용어를 혼동하지 않는다.
- 두 시작 안내 → 공통 규칙 → 현재 작업표/양식 경로를 따라 읽어 범위와 다음 행동이 일치하는지 확인한다.
- Git diff로 제품 소스·테스트·workflow·버전 파일이 바뀌지 않았음을 확인한다. 원격 CI 조작은 수행하지 않는다.

검사 결과는 이번 로컬 회의록과 현재 작업표에 기록한다. 검사 실패는 기존 문제인지 이번 변경인지 나누어 보고하며 숨기지 않는다.

2026-09-21 실행 결과: 공개 링크·개인정보·한국어 제품 용어 검사 모두 통과(exit 0).
공개 후보 12개와 로컬 6개 문서의 별도 내용·연결 검사 발견 0건, Git diff 공백 검사 통과.
HEAD와 index를 유지했고 제품 소스·테스트·도구·workflow·버전 변경은 없었다.
공개 개인정보 검사 결과는 `PRIV000`, 발견 0건이며 자동 검사만으로 모든 문맥상 식별 가능성이 제거된다고 보장하지 않는다.

같은 날 완료 후 별도 검토 컨텍스트에서 문서 15개를 읽고 사용자 결정·입구 연결·공개 경계·미구현 표시를 검토했다.
실질적인 모순이나 차단 문제는 발견하지 못했다. 이는 독립 문서 검토이며 실제 Claude↔Codex 작업 인수 시험은 아니다.

## 4. 다음 실제 작업에서 측정할 것

첫 실제 AI 교대 때 인수자가 최신 결정·미완료 항목·진행 중 검사·다음 행동을 사용자 재설명 없이 찾아 기록한다.
관련 작업을 진행하는 주에 재조사와 중복 검사 이유, 공개 후 추가 차단, 고객 확인 상태를 함께 검토한다.
개선이 없으면 규칙 미준수·발견 실패·규칙 결함으로 나누어 해당 문서 또는 검증을 수정한다.
운영 부담을 늘리는 항목은 실제 사용 근거에 따라 줄인다. 특정 수치나 결함 0건을 미리 보장하지 않는다.
