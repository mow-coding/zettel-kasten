# WOM-kit v0.4.63 — hard-linked files, secret config files, and a plain "is it done?"

This answers beta letter 182. Two activity folders still held five PDFs that were hard links of each other, so one file had two names and there were ten paths. `activity-cleanup` refused them, two configuration files had no clear route, and the person had to ask several times whether the folders could be deleted. Installing the tool alone does not change a customer archive.

## Hard-linked files

A file with several names can now be cleaned up when every one of its names is in the request.

- List each name as its own item, with the same role and disposition. `fsutil hardlink list <path>` shows the names.
- The body is preserved once. Each name is then removed with a check of the exact file and the expected number of names, before and after.
- If only some names are selected, the plan says so with counts: how many names the file has, how many are selected, how many more are inside the selected folders, and how many are outside them.
- A name outside the selected folders keeps the file held. Nothing overrides that, because another activity may use it.
- A name added after planning stops the cleanup of that file and both names stay.
- Reclaimed space counts each file once.

## Secret configuration files

A real secret file has its own role, `secret_config`. It is never uploaded. It can be kept, or deleted after the person confirms for that file that its secret values are kept elsewhere. An example file without secret values is an ordinary source file. WOM does not judge by file name and does not scan for secrets.

## Is it done?

The result and `--status` now answer two questions separately: are the selected items done, and are the folders empty. They include plain sentences and count leftovers as files and as paths, for example five files under ten paths.

## Boundaries

Verified with synthetic files and the real command on Windows, and on Linux for the shared parts. The customer's own folders are not verified until they run this version.

## Install after publication

Use the exact public release asset after its hash and size are reported:

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0463-$womBootstrapNonce"
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.63/wom_kit-0.4.63-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require `archive 0.4.63` from a new process, then follow the reviewed `project-version-update` flow for an existing project.
