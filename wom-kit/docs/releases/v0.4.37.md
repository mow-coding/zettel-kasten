# WOM-kit v0.4.37 — Session-scoped object storage and explicit delegation

Object-storage upload, restore and offload now default to the current session's
provable capture set. A missing session or missing attribution never selects
the entire archive. Explicit `--captured-by-session`, `--object-list`, `--only`
and `--all-sessions` selectors support work delegated across sessions.

Selection is bound into the exact plan digest and retained in resume controls.
A retained plan never silently gains objects from a later session. Older captures,
objects merely viewed in a session, and captures without joined approval evidence
require an explicit object list. Session attribution is not exclusive ownership.

A partially completed upload can use `--abandon-started-upload` with its original
resume identifiers and execution digest. This preserves existing remote effects,
checkpoints and receipts; it does not roll them back or label them complete.
A new narrow plan checks existing remote content before deciding whether to PUT.

Progress distinguishes selected objects from the final manifest projection step.
Existing allow_all no-dialog behavior remains unchanged. Explicit all-session
scope is required to resume a legacy archive-wide plan; abandoning it adds no PUT.

## Install after publication

The following URL is conditional until the release and wheel are public.
Publishing or installing this release does not read or modify a client archive.
Client acceptance requires the client-run result and a new-process verification.

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0437-$womBootstrapNonce"
if (Test-Path -LiteralPath $womBootstrapRoot) {
  throw "WOM bootstrap path must be new."
}
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.37/wom_kit-0.4.37-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require exactly `archive 0.4.37` from a new process. Then use that external
bootstrap for the documented `project-version-update` workflow. Installing a
bootstrap alone does not update the project's pinned runtime.

## Scope and recovery instructions

See [the selection and interrupted-upload guide](https://github.com/mow-coding/zettel-kasten/blob/v0.4.37/wom-kit/docs/object-storage-session-scope.md).
Run the chosen scope in dry-run first and check its object count before execution.
Do not resume an old archive-wide upload to finish only a narrow session's objects.

## Remaining work

This release does not claim to resolve every feedback item or prove client-side
recovery. Tiered development CI, opt-in beta delivery and retained-wheel evidence are
included in this candidate; their operational verification is reported separately.
Formal feedback workflow enforcement remains separate work. Validation uses synthetic archives and storage doubles;
real customer data and cloud objects are not development test fixtures.
