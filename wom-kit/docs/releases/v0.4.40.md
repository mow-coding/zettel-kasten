# WOM-kit v0.4.40 — Closed writers: reopened or removed

v0.4.0 fixed 58 writers closed until each had an operation-specific exact human approval. Beta letters kept reporting commands they needed but could not run. This release goes through all 58: 27 run again under the exact approval contract (plus two new batch commands), 12 that no customer path needs are removed, and the remaining 19 stay closed until their design is finished. Installing the tool alone does not change a customer archive; use the reviewed `project-version-update` flow for a project.

## Reopened under exact approval

Each reopened writer uses the existing broker: one native dialog, or none under a valid `limited`/`allow_all` session grant. The approval binds the exact effect set the writer's own preview computed, and the writer re-derives it and refuses any drift before writing. A declined dialog writes nothing; a run with nothing to write opens no dialog.

- Receipt reconcile (letters 147, 148, 156): `remint-reconcile`, `retire-draft-reconcile`, and new `remint-reconcile-batch` / `retire-draft-reconcile-batch` repair every drifted receipt under one approval.
- Scratch cleanup: `ai-scratch-gc` (only what one zet references) and `zet-catalog-pass-cleanup`; `activity-cleanup` now also covers in-archive AI scratch.
- `markup-normalization`, `-revert`, `-recovery` (letters 115-117, 142) and `zettel-objet-link-revert` (136, 159).
- `principal-register` / `principal-unregister` and the four activity-group membership writers (102, 104, 112).
- `restore-drill` (so `--require-restore-drill` preflights can pass), `repair-gitignore`, `identity-reconcile`.
- `zet-title-remap-recover` / `zet-title-remap-revert-recover`, the only way to finish or roll back a legacy interrupted title-remap journal.
- Nested `derive-text capture` for existing objets (033-036), with a `plan_sha256` preview and `--expected-plan-sha256`.
- `saved-view-write` / `saved-view-revert` (147), `objet-source-metadata-write` (105), `external-locator-deactivate` (116).
- `project-bytecode-repair` and `project-version-update-collision --action preserve-relocate` (129); their approval is recorded in the project's archive.
- `zet-revision-restore-proposal-from-snapshot`, which gained `--reviewed-by`.

## Still closed

Nineteen commands remain fixed closed, plus one conditional migration scope. Five belong to the ZET sharing and ownership design planned for v0.5 and keep their dry-run previews: `delegate-zet`, `transfer-ownership`, `quarantine-foreign-block`, `record-quarantine-decision`, `github-repo`. The others: `add-source`, `credential-lifecycle`, two IMAP writers, `import-external`, `legacy-coordination-cleanup`, `notion-objet-link-convert`, `prehashed-objet-ledger`, `tiro-lossless-recovery-fetch-run`, `notion-page-recovery`, `notion-recover`, `onboard`, `runtime-skill-install` / `-uninstall`; `migrate` stays open only for `notion-source-properties`. Their designs are the next work. Validation used synthetic development data; a customer update and successful use must be confirmed separately.

## Install after publication

Use the exact public release asset after its hash and size are reported:

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0440-$womBootstrapNonce"
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.40/wom_kit-0.4.40-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require `archive 0.4.40` from a new process, then follow the reviewed `project-version-update` flow for an existing project. A bootstrap installation alone does not update its pinned runtime.
