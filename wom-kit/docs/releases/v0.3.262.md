# v0.3.262 - Identifier-Title Census

An import can faithfully copy a source title that was itself a page id. Nothing
is lost and every byte is correct, but the archive stops being browsable by
title and title search no longer reaches those zets. v0.3.262 adds a read-only
census that tells an archive owner whether this happened and to how many zets.

## What Changed

- New read-only CLI `archive zet-title-readiness <archive-root> --dry-run`,
  with aliases `title-readiness` and `zet-title-check`. It reads canonical
  frontmatter only, writes nothing, and calls no provider.
- The report separates two signals rather than merging them into one verdict:
  - `title_matches_external_id` — the title equals this record's own imported
    identifier after case folding and separator removal. Provable from the zet
    alone.
  - `title_is_identifier_shaped` — the title is a bare hexadecimal run of at
    least 16 characters. A shape heuristic, not proof.
- Output carries a partition of the zets the census saw (`counts`), how often
  each rule fired (`signal_counts`), a bounded attention list, and the usual
  snapshot and scan evidence. The two are kept apart because one zet can trip
  both rules: the signal numbers overlap and do not sum to a count of zets, so
  `attention.total_count` is the per-zet number.
- The verdict covers only what was judged. A zet whose frontmatter could not be
  read, or whose title was absent or suppressed by the catalog as private or
  unsafe, is counted in its own bucket and blocks a `ready` verdict rather than
  being scored as human-readable.
- The provenance-bound signal consults the project's registered provider
  page-reference key vocabulary (`page_id`, `notion_page_id`, `external_id`,
  `block_id`, and the rest, plus any `*_page_id` suffix) rather than a
  hand-written pair, and reports which keys it compared.

## Why It Matters

The condition is invisible to every existing check. The frontmatter schema
accepts any string as a title, and the promotion checklist's
"understandable title" rule scores a 32-character hex string as specific
because it is long and contains no generic words. An archive can therefore hold
thousands of unbrowsable titles and report itself healthy.

Separating the two signals matters because only the first one tells you what the
title was supposed to be. A provenance-bound match points at a source record
that still holds the human-readable name; a shape-only match does not.

## Privacy Boundary

The report never echoes a title value or an imported identifier value. That rule
is consistent across every read-only surface in this project, and a census of bad
titles is where it is hardest to keep — because the house mints a zet's id, and
therefore its filename, from its title. An attention row's own `path` and
`zettel_id` can then carry the very value the report is withholding.

Both fields are gated. A reference whose comparison form reproduces the title —
whole, or as a prefix of identifier length, which is what survives the mint's
32-character slug truncation — is emitted as `null` with a `discloses_title`
reason, and `attention.paths_withheld_count` and `zettel_ids_withheld_count`
report how often that happened. The gate is title-relative rather than
shape-based on purpose: importer-minted names like
`zet_import_<system>_<digest16>` carry a hex run that digests the source record
and cannot disclose a title, so they stay visible and the report stays actionable
for the imported population it exists for.

`privacy_guards.title_values_echoed` and `external_id_values_echoed` are derived
from what each emitted row actually carries rather than asserted as literals, so
they cannot disagree with the payload if a gate ever stops firing. The
regressions mint their fixtures the way `make_zettel_id` names them — including
the truncated-slug route and the bare-identifier-as-draft-id route — so the
no-echo property is tested against the real derivation rather than a hand-picked
filename that closes the channel by construction.

Redacted zets are excluded rather than judged: they expose no title to assess,
and their content is deliberately suppressed.

## Compatibility And Migration

- No archive, zettel, index, receipt, or schema migration is required.
- Nothing about minting, promotion, search, or the generated index changes. No
  existing command changes behavior, and no title is proposed or rewritten.
- The command requires `--dry-run` and returns exit 1 without it. A
  `needs_attention` state is a finding, not a command failure, and still exits
  0.

## What This Release Deliberately Does Not Do

It does not propose replacement titles, rewrite anything, read zet bodies, or
consult any source export. A reviewed bulk retitle is a separate
approval-gated flow with its own preview, exact-hash binding, receipts, and
revert path, and it will be staged across its own releases the way the abstract
backfill family was.

It also does not tighten the promotion checklist. Making an identifier-shaped
title fail that machine-inferred item would block minting such zets outright,
which is a behavior change that deserves its own release and its own decision
rather than riding along with a census.

## Provenance And Verification

The condition was reported by a pilot archive where one import batch carried
page ids in the title position for thousands of records, while the
human-readable names lived in a source property the importer did not carry
over. This release answers only the first question that situation raises: how
many, and which ones are provably identifiers.

Local verification covers the two-signal separation and their overlap, the
no-false-positive case for short hex-looking words, the no-echo privacy
guarantee against title-derived filenames and ids, the converse case that a
reference which cannot disclose the title is still reported, refusal to claim
readiness over zets the census could not judge, redacted exclusion, and the
read-only gate — alongside the full WOM-kit suite, the four hygiene checkers,
and packaged resource synchronization.

A pre-release adversarial review across privacy, detection, and scope lenses
found the path/id echo, the readiness over-assertion, the overlapping counters,
the dead facet key, and the missing result envelope described above. Each is
fixed here rather than documented as a known limitation.
