# WOM-kit v0.4.36 — Beta letter 168: grants without dialogs, the upload writer names its cause, delivered letters leave the archive

v0.4.36 answers beta letter 168 and corrects a deviation from the user's
2026-09-17 decision. A session permission mode now works the way the
desktop apps' "allow all" works: no operation kind keeps a dialog of its own.
The object-storage upload writer names why it stopped, refuses its two silent
gates before the dialog, and closes its claim when it provably wrote nothing.
Delivered feedback letters can leave the archive for an operator-designated
folder, leaving a content-free stub.

Publishing or installing this release does not read or modify a client
archive. A client chooses when to run the exact public bootstrap and one
reviewed `project-version-update` to the public wheel
`wom_kit-0.4.36-py3-none-any.whl`. The release is not evidence that a client
result was repaired; that requires the client-run result and a new-process
verification.

## Conditional public artifact contract

Use this bootstrap only after the exact GitHub Release exists and lists the
wheel. The versioned URL alone is not proof that the asset is public.

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0436-$womBootstrapNonce"
if (Test-Path -LiteralPath $womBootstrapRoot) {
  throw "WOM bootstrap path must be new."
}
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.36/wom_kit-0.4.36-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require exactly `archive 0.4.36` from a new process. Installing this external
bootstrap does not replace a shared PATH tool or silently update any project.

## What changes

1. **Grants without dialogs (letter 168 ⑥; the 2026-09-17 decision restored).**
   `always_dialog_operations` is empty: `allow_all` covers every operation
   kind — project update, remote storage, recovery, deletion, session
   control, claim finalization, feedback archival — and `limited` covers the
   kinds chosen at grant time. The only dialog-only action is the grant
   itself (`set-permission-mode`; a grant cannot mint, extend or replace
   itself); the dry-run names it (`dialog_only_actions`,
   `dialog_only_reason`) and the allow_all dialog line states the scope. The
   grant also stands in for an explicit original re-review. Presenter
   binding, the time box, revocation and the claim's mechanism record are
   unchanged.
2. **The upload writer names its cause (letter 168 ①, requests 1-3).** The
   broker's cause allowlist now names the object-storage and exact-operation
   error classes; the exact runner carries the adapter's fixed code as
   `cause_code`; the upload envelope carries `cause_code`, `cause_stage`,
   an honest `effects_state`, the claim next steps and a `progress_summary`;
   `--progress-log <file>` writes every progress publish to a JSONL file.
   The dry-run reports `manifest_index_authority` and
   `credential_refs_present`; the approve refuses before the dialog with
   `archive_index_rebuild_required` or
   `object_storage_upload_credential_ref_unresolved` and reuses the one
   resolved transport. A failure before the first checkpoint closes the
   claim as failed (`exact_human_approval_writer_refused`,
   `effects_state: refused_before_effects`); a failure after the first
   checkpoint keeps the started claim and the resume path.
   `store_setup_missing` results list `registered_store_refs` and say the
   registration receipt's `account_ref` is the label to use (letter 168 ②).
3. **Delivered-feedback archival (letters 164 ⑧ / 168 request 8).**
   `operator-feedback-archive <root> --destination <absolute folder outside
   the archive> --dry-run` plans (counts, ids, digests; the path is never
   echoed, only its SHA-256); `--approve --reviewed-by <person:...>
   --expected-plan-sha256 <plan_sha256>` copies each delivered /
   acknowledged / resolved letter and its body receipts to
   `<destination>/<feedback_id>/`, verifies every copy byte for byte,
   rewrites the record as a content-free `archived` stub (`archived_at`,
   `archived_from_status`, `body_sha256`, `body_utf8_bytes`,
   `receipt_count`, `destination_sha256`, `archived_body_relative`), removes
   the archive copies and writes one receipt naming the claim.
   `operator-feedback-body-check` reports an archived id as `archived_stub`;
   the ledger counts `archived`. Grantable.
4. **Finalize re-scan (letter 168 ③).** The receipt inventory fingerprint is
   bound into the plan digest; the approve re-scans only when it changed
   (`approve_rescans_receipts`, `evidence_inventory_fingerprint`); the
   receipt records `scan_method`.
5. **Preview request shape (letter 168 ④).** `set-permission-mode --dry-run`
   accepts the approve request as is; a refused shape names
   `required_keys` / `optional_keys`.
6. **Revise path (letter 168 request 9).** `operator-feedback-compose
   --approve` creates the draft record by default
   (`--no-create-draft-record` opts out); step 1 of the announced path says
   `--feedback-ref` must equal the body's `feedback-body-sha256:<sha>`.
7. **Inventory.** 61 approval-available, 59 fixed-closed, 202 not-exposed;
   the coverage manifest routes the broker writers through the environment
   grant (`route: environment`).

## For the client

Grant once (`set-permission-mode --approve`, allow_all or limited with the
kinds you want, `grant_hours`); after that the update, the upload, restore,
offload, finalize and archival open no dialog in that conversation. For the
upload: run `--dry-run` and read `manifest_index_authority` and
`credential_refs_present` before `--approve`; on a failure the envelope now
names `cause_code`. For the letters: `operator-feedback-archive <root>
--destination <parent of archive>/ops-feedback-archive --dry-run`, then
`--approve`.

## Compatibility and privacy

- New command `operator-feedback-archive`; new operation kind
  `operator_feedback_archive`; new broker code
  `exact_human_approval_writer_refused`; new upload code
  `object_storage_upload_credential_ref_unresolved`; new result fields named
  above; `always_dialog_operations` is now `[]`. The finalize receipt schema
  gains an optional `scan_method`.
- No path, title, body text, credential value or reviewer id is echoed; the
  archival destination appears only as a SHA-256.

## Verification boundary

The release candidate must pass `test_v0436_letter168`, the permission,
broker, runner, object-storage and claims cohorts, the inventory pins and the
full supported-platform CI. The exact reviewed merge commit must be tagged,
and the public wheel must be downloaded anonymously, rehashed, installed in a
fresh CPython 3.12 environment and checked in a new process. Those steps
prove the public artifact; they do not prove any client result.
