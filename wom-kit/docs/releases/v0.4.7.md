# WOM-kit v0.4.7 — Receipt-Bound Local Recovery

v0.4.7 turns single Objet capture plus the local object-link, edge-revert,
locator, omission-marker, and title
recovery planners into usable field-scoped writers. It reuses the existing
command families and `ExactOperationManifest v1`; it does not add another
top-level command or make ambiguous evidence authoritative.

## What changed

- `objet-capture --exact-local` replaces the persistent enablement marker for
  one selected capture with a native, selection-digest-bound approval. The
  ordinary unbound approval path remains fixed closed.
- `revert-edge --exact-local` binds the original edge receipt, current source
  zettel digest, and exact edge removal before changing only that relationship.
- `zettel-objet-link --capture-receipt` can now durably classify the complete
  capture population and apply only unique source-identity links. An absent
  target is recorded as `no_target`; captured objects are never re-imported.
- `external-locator-record` can build one batch from a private source mirror
  and markup receipts. Exact locator records and receipt-proven omission
  markers are written together, while unsafe locator values remain review-only.
- `zet-title-remap-write` can audit title receipts and repair only
  source-mirror-confirmed identifier-shaped titles. `zet-title-remap-revert
  --field-local` restores only `frontmatter.title` from an exact receipt
  snapshot, preserving unrelated later body changes.
- Every recovery domain writes a content-free classification ledger, including
  populations where no canonical target exists and no domain field should be
  changed.
- All writers share one native human decision, private approved controls,
  append-only checkpoints, authenticated idempotent resume, field-scoped
  revert, content-free progress, and independent read-back verification.
- Real-scale recovery previews emit counts and manifest digests rather than
  thousands of per-item hash rows; the complete manifest remains privately
  bound to approval and resume controls.

## Human decision and privacy boundary

WOM computes counts, hashes, archive identity, source bindings, and exact field
effects. The person chooses only the plain native action or cancel; they do not
have to count records or compare digests. A manifest identifier is required
only for exceptional resume or revert so WOM can reload the already approved
private control without asking for the source evidence again.

Dry-run and release verification read no credential value, call no provider,
and write no client archive file. Private paths, page identifiers, titles,
locators, filenames, and payloads are absent from public results, documentation,
wheel resources, and release assets.

## Full-scale private acceptance evidence

On a private read-only acceptance archive, the released planners reproduced
the complete capture, locator, marker, title-receipt, and identifier-title
populations; every item became either an exact field effect or an explicit
review/no-target classification. The combined manifests remained within their
release performance and size bounds.

Exact client totals, identifiers, paths, hashes, and source values remain only
in ignored-local acceptance records. No client manifest was approved or
applied during release preparation.

## Client execution boundary

Publishing v0.4.7 does not modify a client archive. Actual recovery happens
only when the client updates that project to the released build and runs the
project-scoped command, or explicitly delegates that operation. A feedback
letter is not resolved merely because this product release exists.

## Install contract

After the matching GitHub Release exists, install the exact public artifact in
an isolated tool or project runtime:

```powershell
uv tool install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.7/wom_kit-0.4.7-py3-none-any.whl"
archive --version
```

The version check must report `archive 0.4.7`. The versioned URL alone is not
proof that the release asset exists.
