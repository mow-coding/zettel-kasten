# WOM-kit v0.4.2 — Read-Only Git Backup Planning

v0.4.2 adds a privacy-preserving foundation for reviewing a large mixed Git
worktree before any commit or push is considered. It introduces two CLI-only
read-only commands: `git-backup-plan` and `git-backup-reconcile-plan`.

This release does not add a Git writer. It does not add, reset, checkout,
commit, merge, rebase, delete, fetch, pull, push, or change a remote ref. It is
only the planning and reconciliation portion of Letter 139; the requested
end-to-end remote backup remains incomplete.

This source note is not release evidence. The versioned install URL below is
usable only after the `v0.4.2` tag, public GitHub Release, exact wheel asset,
successful required CI, anonymous asset retrieval, and independent fresh
install verification all exist for the same commit.

## New Read-Only Commands

Create the first observation with:

```powershell
archive git-backup-plan <archive-root> `
  --remote origin `
  --dry-run `
  --format json
```

After a human reviews that result, repeat the same target and bounds with its
exact plan digest:

```powershell
archive git-backup-reconcile-plan <archive-root> `
  --remote origin `
  --expected-plan-sha256 sha256:<64-lowercase-hex> `
  --dry-run `
  --format json
```

`--branch <branch-name>` can explicitly reaffirm the currently checked-out
symbolic branch. Selecting a different branch blocks because the current
index and worktree belong to the checked-out branch.
`--max-changes` and `--max-changed-bytes` can tighten or, within hard shipped
caps, expand the bounded observation. Exceeding a limit blocks instead of
silently returning a partial plan.

Both commands always report:

```json
{
  "ready_for_write": false,
  "writer_available": false,
  "would_change": []
}
```

There is no `--approve` form and no MCP Git writer. A returned
`plan_sha256` is an opaque comparison digest, not an approval token.
`--expected-plan-sha256` is required for reconciliation. Optional
`--expected-hidden-effect-set-sha256`, `--expected-local-head-oid`, and
`--expected-remote-oid` bind those exact reviewed fields too; any supplied
mismatch blocks.

## Stable Git Observation

The planner uses Git's porcelain v2 NUL-delimited status contract so record
boundaries and rename pairs are not guessed through line-oriented parsing.
Unsupported unsafe names, including control characters, block instead of
being normalized. It binds the checked-out symbolic target ref and exact local
commit, index, tracked tree, staged/unstaged/untracked and conflict state,
ignored exclusions, bounded current/preimage evidence, relevant Git
configuration state, receipt inventory, session-handoff context, and one
exact remote-ref result into the plan. An unborn branch blocks in v0.4.2.

Important local, evidence, handoff, and remote inputs are observed again
before the plan closes. Drift blocks the result rather than combining two
different repository moments.

The response does not return private paths, file bodies, archive identity, an
absolute local path, commit messages, the configured remote URL, credentials,
raw Git failures, or raw receipt/handoff contents. Change entries use opaque
ordinal references. Ignored items remain exclusions only; v0.4.2 does not call
them disposable or safe to delete.

## Fail-Closed Boundaries

The commands stop on unsupported or ambiguous repository states, including
detached/invalid refs, unusual repository layouts, unsupported object state,
active Git operations or locks, split/sparse/partial state, unsafe path or
index forms, tracked symlinks/Git links/submodules, malformed output or remote
configuration, changing observations, and exceeded resource limits.

Any repository-controlled `.gitattributes` in the worktree, index, or
`.git/info/attributes` also blocks v0.4.2. Git may invoke configured content
filters while inspecting status, so this release does not attempt to classify
an attributes file as harmless. Do not delete or disable `.gitattributes` as a
workaround; support for a proven inert subset remains future work.

The remote query allows only anonymous HTTPS and requests one exact branch ref
with `git ls-remote --refs --exit-code` in a contained process tree.
Interactive prompts and credential helpers are disabled. SSH/scp-like,
userinfo-bearing, private, or authenticated remotes fail closed and may report
unavailable even when a human can access them through another Git client. Do
not place a token in the URL to bypass this boundary. A matching result is Git
transport evidence at one moment, not provider-API confirmation of repository
visibility, ownership, branch protection, durability, or push completion.

Historical receipts and session handoff may be bound as context evidence, but
they are not guessed into file provenance and do not authorize a future
writer.

## Reconciliation Meaning

`git-backup-reconcile-plan` re-runs the complete bounded observation. Exact
relation states are `equal`, `local_ahead`, `remote_ahead`, `diverged`,
`remote_branch_missing`, `remote_oid_not_available_locally`, and
`not_computed`. An unavailable remote observation blocks and leaves the
relation `not_computed`. The command does not fetch an unavailable object or
repair any state.

If the expected digest no longer matches, stop and review the new plan. Do not
replace the digest automatically and claim that the old review still applies.

## Public Release Privacy Gate

The maintainer-side public privacy check now inspects both the exact regular
file blobs staged in the Git index and the separately observed worktree. All
tracked regular files are scanned regardless of filename extension; sensitive
untracked text candidates are scanned too. This prevents a staged secret from
being hidden by later cleaning or deleting only its worktree copy.

The check uses bounded file, total-byte, Git-output, and runtime budgets. It
rejects symlink, reparse, non-plain, changing-index, and changing-file states,
and its diagnostics contain only fixed codes, safe relative paths, types, and
counts. They never print a matched token, phrase, local path value, URL,
exception, or Git error. This is a fail-closed release guard for recognizable
secret and local-path shapes, not proof that every possible secret format is
absent; provider secret scanning and human review remain separate checks.

## Unchanged v0.4.1 Authority

The v0.4.1 exact-human `zettel-objet-link` apply remains available with its own
operation-specific boundary. Link revert, Objet capture, project update, and
all other fixed-closed writers remain closed. The Git planner inherits none of
the link writer's authority.

## Upgrade

After the matching public Release actually lists the exact wheel, replace an
existing isolated `uv tool` installation with:

```powershell
uv tool install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.2/wom_kit-0.4.2-py3-none-any.whl"
archive --version
```

Close older WOM processes first and require exactly `archive 0.4.2` from a new
process. This replaces only the isolated global CLI selected by `PATH`. It
does not update a project-local source mirror, project pin, archive content,
or AI-host Agent Skill installation.
