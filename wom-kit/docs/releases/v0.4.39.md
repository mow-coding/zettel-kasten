# WOM-kit v0.4.39 — Letter 173: reliable activity cleanup and one deliverable letter

This release answers the first four parts of beta letter 173 and a request about how feedback letters are prepared. Installing the tool alone does not change a customer archive; use the reviewed `project-version-update` flow for a project.

## Activity cleanup keeps its reviewed plan

On Windows a folder can report a different size (for example 0 or 4096 bytes) without any change to its contents. `activity-cleanup` included folder sizes and folder times in its plan fingerprint, so an approval after a clean preview failed with `activity_cleanup_plan_changed`. The fingerprint now omits folder size and time only. New, removed or changed files, file hashes, identities and times still change the plan, and the protections for links, Git history, worktrees and secret configuration are unchanged.

A refusal before approval starts (a changed plan, a missing reviewer or an unsupported platform) now reports `effects_state: none` instead of `unknown`. Previews and approvals print content-free stages, counts and heartbeats on stderr by default (`--no-progress` turns them off) and accept `--progress-log` outside the archive.

## Git backup names its cause

`git-backup-plan` no longer refuses a `.gitattributes` file that lives in an ignored folder containing no tracked and no committable untracked files, because such a file cannot change anything Git would commit. Attribute files that can reach committable paths, tracked or root-level attribute files, and `.git/info/attributes` still block before any filter runs. The session backup route now reports the fixed cause (for example `repository_attributes_not_supported`) with a next action instead of only `work_session_git_unavailable`.

## One deliverable feedback letter

When a person asks for a letter to the developers, the operator prepares one letter ready to read and deliver. The person sees two states: before delivery (`전달 전`) and delivered (`전달 완료`); developer receipt stays a separate later state. A new letter may omit `feedback_id` and receives the next standard number. The single approval of `operator-feedback-compose` writes the letter, its receipt and its record; a valid session grant covers it without a dialog. The route no longer contains a command-less review stop, and operators should not create separate review copies. `operator-feedback-ledger` shows both states and the next number.

Session-close scope for one activity (letter 173 part D) is not in this release. Validation used synthetic development data; a customer update and successful use must be confirmed separately.

## Install after publication

Use the exact public release asset after its hash and size are reported:

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0439-$womBootstrapNonce"
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.39/wom_kit-0.4.39-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require `archive 0.4.39` from a new process, then follow the reviewed `project-version-update` flow for an existing project. A bootstrap installation alone does not update its pinned runtime.
