# WOM-kit v0.3.319 — Native Credential Popup And Causal Evidence

Release date: 2026-08-14

This source checkpoint incorporates Letter 132 operator feedback. Local source,
unit tests, synthetic Win32 seams, and rendered-window inspection do not prove
merge, external CI, exact tag, GitHub Release publication, wheel publication,
fresh installation, live credential registration, provider acceptance, durable
store persistence, or missing-source recovery.

## Final operator-facing change

The terminal-based credential-entry prototypes were withdrawn after repeated
human failures and unreadable Korean UI. Production `credential-adopt` now uses
one separate, Unicode native Windows popup in an isolated spawned child. The
parent waits and never receives the raw value. The child opens no command-line
secret channel; the value never enters AI chat, argv, environment variables,
ordinary stdin, logs, plaintext files, result JSON, or IPC.

The popup title is `WOM · 안전한 자격 증명 입력`. A standard single-line Windows
EDIT control retains ordinary keyboard editing, `Ctrl+V`, `Shift+Insert`, and a
fixed Paste/Clear-only context menu. WOM never calls a clipboard-read API. The
EDIT is password-styled as a fallback, but an opaque fixed-text sibling covers
the complete input rectangle and says
`입력 내용과 길이는 화면에 표시되지 않습니다.` No character, mask glyph, caret
movement, count, or length is rendered. Copy and cut are blocked. The Confirm
button remains disabled while input is empty; Cancel, X, and Escape return
pre-store cancellation.

The popup uses the current DPI-aware system message font, per-monitor-v2
geometry, measured wrapped paragraphs, owner centering, and a modal message
loop with dialog-key handling. It disables IME for the token field and proves
the association absent before showing the window. All owned mutable UTF-16 and
UTF-8 buffers are wiped. The native EDIT text and undo state are cleared before
window destruction, and cleanup ambiguity wipes any otherwise-returnable
secret before a content-free failure is raised.

## Synthetic acceptance is not registration

The popup accepts an exact closed enum, never a caller string:

- `CredentialPopupInputIntent.live_registration` displays the top banner
  `실제 자격 증명 등록` and is the only production `credential-adopt` route.
- `CredentialPopupInputIntent.synthetic_acceptance` displays
  `합성 입력 테스트 · 실제 키 입력 금지`, warns
  `경고: 실제 자격 증명은 절대 입력하거나 붙여넣지 마세요.`, and permits only the
  public fixed challenge `WOM-INPUT-ACCEPTANCE-0319`.

Missing, plain-string, or unknown intent fails before owner lookup, popup show,
focus, credential-store access, or provider access. The source-tree acceptance
tool keeps its historical filename
`tools/check_windows_credential_console_host.py`, but its contract is now
`wom-kit/windows-credential-popup-acceptance/v0.1` and its Codex route is
`codex_desktop_native_popup`. It never requests a PAT, writes a credential,
calls a provider, or returns the synthetic value. Its JSON exposes only strict
booleans and one fixed content-free classification.

The pre-intent popup exercise received one complete non-empty line but did not
match the fixed challenge. The operator then clarified that an actual secret
had been entered because the old harness copy did not make the boundary
unmistakable. That value was not logged, returned to the parent, stored, or sent
to a provider; the child buffer was wiped. This human synthetic row is failed
evidence, not a synthetic pass and not a live registration. It will not be
repeated as a prerequisite for this recovery. The helper remains available only
for optional future acceptance. Production registration remains `not_performed`.

## Spawn containment and result evidence

The spawned popup child calls the child-only detach boundary before popup,
native-facade, store, provider, or archive work. Only after that succeeds does
it send the fixed acknowledgement `popup_child_detached`. Failure to send the
acknowledgement blocks all live work.

The parent holds a narrow Python `SIGINT` and Windows `SIGBREAK` ignore lease
only across `Process.start()` and the exact local start proof, restores both
original handlers before receiving, and accepts only the strict sequence
acknowledgement → final mapping → terminal pipe EOF. A normal start additionally
requires unbounded join. An exceptional start cannot be projected as safe
pre-start merely because public process fields are empty. No exception text or
secret crosses the pipe.

The child `wom-credential-secure-intake-result/v0.3` and parent
`wom-credential-workflow-result/v0.3` expose only these causal facts:

- `credential_input_received`;
- `complete_line_received`;
- `temporary_store_write_attempted`;
- `provider_request_attempted`.

Unknown child state projects four nulls. `provider_auth_rejected` requires an
actual provider request. Complete malformed, control-containing,
provider-shape-invalid, over-limit, or locally oversized input uses
`credential_input_invalid_for_provider` before store/provider work. A post-input
native cleanup failure uses `credential_input_boundary_failed` with operator
action `repair_secure_input_boundary_and_create_a_new_plan`, preserving truthful
`1000` or `1100` evidence while store and provider remain false. A temporary
store write without a transport crossing uses `provider_request_not_attempted`.
Rollback may report `deleted` only after an exact post-delete absence probe.

## Render and automated evidence

The first small screenshot after the DPI change was invalid: a DPI-unaware
capture process allocated a 660×470 bitmap for a 1155×823 per-monitor-v2 popup
at 168 DPI. A corrected capture proved the small image was the exact upper-left
crop of the full window. The full image showed every Korean and ASCII paragraph,
opaque overlay, status row, and button without overlap or clipping.

Automated popup, secure-intake, workflow, privacy, and release tests validate
the closed intent enum, exact banners, geometry at common Windows DPI values,
message routing, child containment, causal evidence, and buffer wiping. They do
not prove that a human used the fixed challenge, that an actual PAT was
registered, or that a provider/store transaction succeeded.

## Manual popup acceptance

The human-only source-tree command uses the fixed public challenge and must run
without a real PAT:

```powershell
python -B wom-kit/tools/check_windows_credential_console_host.py --host-family codex_desktop --launch-route codex_desktop_native_popup --gesture direct_keyboard_typing --format json
```

The person must first attest that this is synthetic-only, then confirm the
separate popup, the synthetic intent banner/warning, the designated whole-line
gesture, complete value-and-length opacity, the empty/non-empty Confirm gate,
normal closure, and legible Korean. A passing injected unit test is never
physical human evidence.

## Bounded post-acceptance homework

This checklist is homework, not evidence that live enrollment or recovery has
run or succeeded. The failed synthetic row is not repeated as a prerequisite.
Begin only after the published v0.3.319 runtime is verified in a new process,
the user deliberately chooses actual registration, and the popup's blue banner
says `실제 자격 증명 등록`.

All angle-bracket values are placeholders for the operator's reviewed local
session. Never put a real PAT in a command, chat, document, environment,
ordinary stdin, or plaintext file. The synthetic acceptance tool must never
receive it. Enter it only in the production popup whose top banner says
`실제 자격 증명 등록`.

### Step 1 — Pre-enrollment authenticated list

```powershell
archive credential-secure-list <archive-root> --verify --format json
```

Continue only from the expected absent state. An existing authenticated,
duplicate, unreadable, or unexpected row stops the homework for human review.

### Step 2 — New adoption dry-run and one digest-bound approval

Discard old adoption digests and create one fresh plan. This first-enrollment
homework does not add `--replace-existing`:

```powershell
archive credential-adopt <archive-root> --account-label <public-safe-account-label> --workspace-label <public-safe-workspace-label> --purpose notion-page-recovery --task-summary "<public-safe-task-summary>" --connection-reason "<public-safe-connection-reason>" --reviewed-anchor-page-id <reviewed-anchor-uuid> --interactive --dry-run --format json
```

After human review, repeat exactly the same public-safe fields and approve only
the new digest once:

```powershell
archive credential-adopt <archive-root> --account-label <public-safe-account-label> --workspace-label <public-safe-workspace-label> --purpose notion-page-recovery --task-summary "<public-safe-task-summary>" --connection-reason "<public-safe-connection-reason>" --reviewed-anchor-page-id <reviewed-anchor-uuid> --interactive --expected-request-sha256 <fresh-request-sha256> --approve --format json
```

Verify the popup banner says `실제 자격 증명 등록` before entering an actual
credential. Do not retry automatically. Continue only when the result itself
reports `accepted: true`, `persisted: true`, and all four new-intake causal
booleans as exact `true`; otherwise stop for review.

### Step 3 — Post-enrollment authenticated list

```powershell
archive credential-secure-list <archive-root> --verify --format json
```

Continue only when the authenticated content-free list verifies the expected
active/current registration. Missing or unauthenticated state is a stop
condition, not permission to repeat enrollment.

### Step 4 — Missing-source recovery dry-run

```powershell
archive notion-page-recovery-plan <archive-root> --request <archive-relative-reviewed-recovery-request.json> --max-items 5 --offset 0 --dry-run --format json
```

The request placeholder is an archive-relative ignored-local reviewed request
under `profiles/local/notion-page-recovery/`. This command resolves no provider
credential, makes no Notion request, and writes no recovery evidence. Stop
after reviewing this bounded plan; it does not authorize recovery approval or
claim that a missing source was recovered.

## Upgrade

After, and only after, the exact v0.3.319 GitHub Release lists the verified
`wom_kit-0.3.319-py3-none-any.whl`, start a new process and confirm:

```powershell
archive --version
```

Discard older credential-adoption dry-run digests and create a new plan under
the verified runtime. The upgrade itself does not rewrite a canonical zet,
object store, Notion page, authenticated receipt, or saved credential.

Matching authenticated credentials remain eligible for no-prompt reuse after
exact receipt, store, fingerprint, provider, and reviewed-anchor validation.
Only first enrollment or a separately reviewed `--replace-existing` request
opens the production native registration popup.
