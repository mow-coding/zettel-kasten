# WOM-kit v0.3.303

v0.3.303 follows the v0.3.302 saved-view release with a system-level artifact
lifecycle checkpoint. It makes unresolved local material visible before any
future cleanup design.

## Added

- CLI-only `archive artifact-lifecycle-inventory <archive-root> --dry-run`;
- fixed coverage for scratch, AI staging, capture staging, drafts, workpacks,
  exact generated-index files, local content-addressed object bytes, and local
  derived-text bytes;
- independent per-root 1-100,000 entry ceilings, content-free stable refs,
  complete/truncated coverage, and metadata snapshot digest;
- fail-closed unreadable, special-file, symbolic-link, Windows reparse-point,
  entry-limit, and changed-during-scan handling;
- descriptor-verified, bounded object-manifest inspection that rejects
  duplicate JSON keys and duplicate object ids, plus
  `unmanifested_local_object_candidate` reconciliation without reading or
  hashing object bytes;
- descriptor-verified, bounded, duplicate-key-free and alias-free workpack
  `package.yml` expiry classification without inferring deletion permission;
- presence-only handling for a non-canonical in-root `objets/` marker, without
  enumerating original-bearing children;
- Draft 2020-12 result schema, runtime action routing v0.12, generated-archive
  AI guidance, public documentation, and focused privacy/authority tests.

## Safety Boundary

The inventory reads no ordinary artifact body, object byte, sibling
`-objets` store, secret store, or provider state. It writes and deletes
nothing, creates or changes no zet, has no MCP mutation surface, and grants no
cleanup authority. Age, expiry, class, missing manifest identity, or an empty
reference count is never enough to delete data.

The command does not perform an unconstrained whole-archive sweep. A complete
result proves only its declared fixed local scope at that time. Unknown archive
locations, remote provider residue, legal retention status, semantic value,
and object-byte integrity remain separate boundaries.

## Compatibility

Additive. Existing v0.3.302 archives require no migration.

## Verification Contract

Release acceptance requires focused privacy, limit, link/reparse, manifest,
workpack, concurrency, CLI, and schema tests; the complete platform matrix;
release-readiness and packaged-resource checks; an exact-tag wheel; and one
anonymous fresh install before public completion is claimed.
