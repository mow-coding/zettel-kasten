# WOM-kit v0.3.269

Release date: 2026-07-28

v0.3.269 closes the write gap in the reviewed identifier-title repair flow.
It adds approval-gated `archive zet-title-remap-write` and alias
`title-remap-write`.

## What Changed

- The existing private proposal, `zet-title-remap-plan` digest, and a new
  write-plan candidate digest must all match.
- Approval additionally requires a safe reviewer id and
  `--affirm-titles-reviewed`.
- The complete plan and every named canonical file are revalidated under a
  common title-remap writer lock immediately before mutation.
- Exactly one top-level scalar `title` is replaced. BOM state, newline style,
  all other frontmatter semantics, body bytes, and `updated_at` are preserved.
- Complete prior canonical bytes are content-addressed and verified before the
  first write. Missing object-manifest entries are appended as one locked
  batch.
- A private create-new receipt records participant paths and before/after
  file/title hashes plus unchanged body hashes, but no old title, new title, or
  body text.
- A normal runtime failure restores all attempted canonical files to their
  exact original bytes and removes partial transaction state only after
  verification.
- A real hard exit leaves a private transaction journal, common write lock,
  and verified prior-byte snapshots so the mixed state is explainable.
- Repeating an already completed proposal verifies its receipt, current after
  hashes, and prior snapshots, then returns `already_applied` without writing.

## Safe Operating Sequence

```powershell
archive zet-title-remap-plan <archive-root> `
  --proposal .wom-scratch/title-remap/<private>.jsonl `
  --max-items 5000 `
  --dry-run `
  --format json

archive zet-title-remap-write <archive-root> `
  --proposal .wom-scratch/title-remap/<private>.jsonl `
  --expected-proposal-sha256 sha256:<proposal-digest> `
  --expected-plan-digest sha256:<plan-digest> `
  --max-items 5000 `
  --dry-run `
  --format json
```

Only after human review, bind the returned `write_plan_digest` and add
`--approve`, `--reviewed-by person:<reviewer-id>`, and
`--affirm-titles-reviewed`.

## Privacy And Scope

The CLI never echoes proposed or existing title text, title hashes, zet ids,
zet paths, reviewer ids, snapshot paths, provider URLs, or absolute local
paths. The proposal and retained hard-exit journal remain private working
material.

This release does not add an MCP write method and does not call a provider or
model. It also does not implement archive-wide title receipt audit, automatic
hard-exit recovery, or approved revert. Retained journal/lock evidence must not
be deleted or hand-edited until that later recovery track is available.

No archive-wide migration is required. Existing zets and v0.3.268 proposals
remain readable. An older WOM-kit can read the unchanged canonical Markdown
after a successful write, but it does not understand the new title-remap
receipt or transaction evidence.
