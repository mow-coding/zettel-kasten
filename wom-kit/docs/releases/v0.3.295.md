# WOM-kit v0.3.295: Private Objet Metadata And Safe Labels

Release date: 2026-08-01

## What Changed

v0.3.295 publishes the contract needed to connect a person's remembered
source filename to a SHA-256 objet without changing object identity or leaking
private names onto generic surfaces.

It adds:

- `private-objet-source-metadata-v0.1.schema.json`;
- `objet-safe-label-projection-v0.1.schema.json`;
- a pure in-memory normalization, validation, projection, and ambiguity
  reference module; and
- pinned Unicode 17 case-fold, whitespace, and bidi-control tables.

## Identity And Privacy

SHA-256 remains the object identity. Original, decoded, and normalized names
are provenance-bound aliases only. Matching or colliding aliases never rename
bytes, merge objects, or prove equality.

Private and restricted projections may select a reviewed, source-bound, or
generic label. Equal-priority distinct values remain ambiguous. The
`public_generic` schema branch has no free-form label, filename, source ID,
path, provider locator, secret, or private collision field; it can return only
a closed generic family.

## Deterministic Unicode Profile

NFC/NFD normalization uses `unicodedata2==17.0.1` and requires
`unidata_version == "17.0.0"`. Full case folding uses the 1,585 official
non-Turkic Unicode 17 C/F mappings, while fixed whitespace and bidi-control
sets come from Unicode 17 `PropList.txt`.

Encoded components are decoded exactly once with strict UTF-8. Malformed
escapes, a BOM, residual triplets, separators, controls, unsafe path segments,
and derived-name overflow fail closed without reflecting private input.

Canonical-caseless and separator-folded values are search aliases, not display
names or identity. Exhaustive Unicode 17 evidence bounds a 512-scalar
filename/stem search key at 2,048 scalars; no truncation is allowed.

## Evidence Boundaries

v0.1 keeps MIME, extension, size, registry, and confusable evidence separate.
It does not use OS MIME inference or claim that source-declared MIME proves
object bytes, registry status, or extension agreement.

The runtime validator has no `jsonschema` dependency. CI uses the pinned Draft
2020-12 implementation only as a test oracle, with content-free failure
adaptation.

## Compatibility

This release adds no CLI command, MCP tool, database schema, migration, writer,
index, finder, provider call, external scan, or object-byte access.

The existing checked-layer rediscovery plan keeps
`private_original_name_metadata` non-complete. Its reason now says that the
schema and pure normalization contract exist, but the approved writer,
receipt-bound index, and private query do not.

## Package And Verification Boundary

The package resource manifest adds exactly the two schemas and replaces the
current release note. Official Unicode source fixtures remain test-only; the
derived immutable Python table is a normal wheel module.

Release verification checks both the `unicodedata2` distribution version and
Unicode data version in an isolated installed-wheel environment, runs
`pip check`, preserves the four existing entrypoints, and compares the exact
CLI, MCP input-schema, and database source sets with v0.3.294.

## Deferred Work

Approval writing/recovery, receipt-bound indexing, private finding, and
coverage-versus-integrity reporting remain separate v0.3.296-v0.3.299
releases. This release alone does not make a remembered filename searchable in
a real archive.
