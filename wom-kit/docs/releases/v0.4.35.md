# WOM-kit v0.4.35 — Beta letter 167: the updater and a rewritten origin main

v0.4.35 is a hotfix. The public repository's history was rewritten on
2026-09-20 to purge private identifiers; a source mirror that had fetched
the earlier `main` can no longer fast-forward, so `project-version-update`
— whose fetch is deliberately non-forced — refused the client's update and
said only "fetch failed" and "tag missing". This release makes the refusal
say why and adds one reviewed way to accept the rewrite.

Publishing or installing this release does not read or modify a client
archive. A client chooses when to run the exact public bootstrap and one
reviewed `project-version-update` to the public wheel
`wom_kit-0.4.35-py3-none-any.whl`. The release is not evidence that a client
result was repaired; that requires the client-run result and a new-process
verification.

## Conditional public artifact contract

Use this bootstrap only after the exact GitHub Release exists and lists the
wheel. The versioned URL alone is not proof that the asset is public.

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0435-$womBootstrapNonce"
if (Test-Path -LiteralPath $womBootstrapRoot) {
  throw "WOM bootstrap path must be new."
}
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.35/wom_kit-0.4.35-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require exactly `archive 0.4.35` from a new process. Installing this external
bootstrap does not replace a shared PATH tool or silently update any project.

## What changes

1. **A failed fetch is diagnosed.** The result's `fetch` block carries
   `rejection_kind` (`non_fast_forward`, `remote_unreachable`,
   `target_tag_missing_on_remote` or `ref_update_rejected`),
   `remote_reachable`, `target_tag_on_remote`, `origin_main_before_fetch`,
   `origin_main_remote_sha` and `origin_main_rewritten`. The diagnosis reads
   the remote once and checks ancestry against the objects the rejected
   fetch left behind (else against the exact tag fetched into a private
   probe ref that is removed again); it writes no `refs/tags` or
   `refs/remotes` ref, captures no stderr and echoes no URL, path or
   credential. A rewritten `main` adds a blocker that names the flag below
   and a next step.
2. **`--affirm-origin-main-rewritten`.** With `--approve` (and the usual
   `--reviewed-by` / `--affirm-external-writers-quiescent`) the one fetch
   uses `+refs/heads/main:refs/remotes/origin/main`; the tag refspec is
   never forced and the fetch stays atomic and `--no-tags`. The dry-run and
   the result report `fetch.main_ref_forced_update_affirmed`; the result
   reports `origin_main_before_fetch` / `origin_main_after_fetch` and
   `origin_main_rewrite_accepted`; the warning `origin_main_rewrite_affirmed`
   is bound into the approval context. Every later verification is
   unchanged.

## For the client

From the v0.4.35 bootstrap: `project-version-update <root> --target v0.4.35
--dry-run --affirm-origin-main-rewritten`, then the same with `--approve
--reviewed-by <actor> --affirm-external-writers-quiescent`. v0.4.35 carries
v0.4.32, v0.4.33 and v0.4.34.

## Compatibility and privacy

- New flag `project-version-update --affirm-origin-main-rewritten`; new
  result fields under `fetch`; new bound warning `origin_main_rewrite_affirmed`;
  new blocker text naming the flag. No schema string changes.
- No stderr, remote URL, path, reviewer id or credential value is echoed;
  commit ids are public.

## Verification boundary

The release candidate must pass `test_v0435_letter167`, the project-update
cohorts, the inventory pins and the full supported-platform CI. The exact
reviewed merge commit must be tagged, and the public wheel must be
downloaded anonymously, rehashed, installed in a fresh CPython 3.12
environment and checked in a new process. Those steps prove the public
artifact; they do not prove any client result.
