# WOM-kit v0.3.268

Release date: 2026-07-28

## Usable Title Remap Diagnostics

This release applies real-use feedback from a 2,743-row title remap proposal.
The read-only plan remains read-only, but its blocked rows are now actionable.

## What Changed

`archive zet-title-remap-plan` now:

- prints an allowlisted fixed code and safe explanation for proposal path and
  size errors instead of discarding the explanation;
- accepts replacement titles through 2,000 Unicode characters rather than 200;
- reports `title_contains_line_break` separately from
  `title_contains_non_normalized_whitespace`;
- publishes the exact normalization contract without changing a title;
- reports fixed `matched_safety_rules` without matched values;
- allows ordinary public HTTP/HTTPS citation URLs with
  `title_contains_public_web_url` as a warning;
- keeps local absolute paths, private provider URLs, credential
  assignments/private keys, and token-shaped values blocked;
- no longer treats bare topic words such as `password` as secrets;
- documents the existing `basis: human_written` fallback when no trustworthy
  automatic source title exists.

The proposal schema id remains
`wom-kit/zet-title-remap-proposal/v0.1`. Raising `title.maxLength` from 200 to
2,000 is a backward-compatible relaxation.

## Exact Whitespace Contract

The command performs no automatic normalization. A proposal title must be one
line, use only U+0020 SPACE as whitespace, and contain no leading, trailing, or
consecutive spaces. The operator reviews any normalization against the source
before resubmitting.

## Privacy And Safety

The result still emits no current or proposed title, title digest, exact title
length, zettel id/path, proposal filename, provider URL, matched substring,
body, or absolute local path. A fixed safety rule name explains the category
without revealing the private value.

Archive-root and unexpected failures keep the generic redacted CLI message
because their underlying exceptions may contain local absolute paths. Only the
fixed proposal-input error allowlist is printed.

## Human-Written Fallback

When the source title is missing, still identifier-shaped, or genuinely too
vague, a human may write a specific replacement and set
`basis: human_written`. The human refreshes the expected canonical file hash,
reruns the complete plan, and reviews all remaining warnings and blockers.
WOM does not invent the title.

## What Is Still Not Implemented

This release does not change canonical zets. Approved title writes, immutable
receipts, interruption recovery, receipt audit, and approved revert remain the
next release track.
