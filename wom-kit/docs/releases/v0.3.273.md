# v0.3.273 - Read-Only Completed Title Revert Plan

v0.3.273 adds a CLI-only read-only plan for compensating one completed
title-remap receipt.

```text
archive zet-title-remap-revert-plan <archive-root> --receipt <archive-relative-receipt> --expected-receipt-sha256 sha256:<digest> --dry-run
```

## What Changed

- Added `archive zet-title-remap-revert-plan` and alias
  `title-remap-revert-plan`.
- Bind one archive-relative immutable source receipt to its exact reviewed
  SHA-256 without echoing its private path.
- Rerun the complete bounded title receipt, journal, snapshot, current-state,
  and common-lock audit; require it to be healthy, complete, and clean.
- Verify every current canonical participant at the source receipt's applied
  whole-file, title, and body hashes.
- Re-verify every content-addressed prior-byte object and manifest record.
- Prove privately that each source receipt is an exact title-only transition:
  applying the current title to the prior bytes must recreate the current
  whole file exactly.
- Bind the source receipt, original write evidence, history-audit digest, exact
  applied-to-prior transitions, and future revert-receipt location into one
  plan digest.
- Block on current-state drift, snapshot drift, receipt-hash mismatch,
  duplicate participants, retained transaction evidence, or an existing
  unsupported revert receipt.

## Privacy And Scope

The plan echoes no title text/hash/length, body text, zet id/path, proposal
SHA, reviewer id, private evidence path, provider value, secret, or absolute
local path. It calls no provider or model and exposes no MCP method.

The source receipt and snapshots remain immutable. This release writes and deletes nothing
and does not implement approved completed-title revert. A
later approval-gated writer must rerun and bind this plan, serialize with the
title writer, use crash-recovery evidence, and append a separate immutable
revert receipt.
