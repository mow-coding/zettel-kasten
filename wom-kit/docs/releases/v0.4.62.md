# WOM-kit v0.4.62 — faster remote cleanup, and progress you can read

This is the second part of the answer to beta letter 181. Deleting 80 remote temporaries took about 14 minutes. A cleanup of 28 small files took about 26 minutes while the provider needed only 25 seconds. And `operation-control` showed only "starting" and a sequence number while the work ran. Installing the tool alone does not change a customer archive.

## Remote cleanup

`object-storage-cleanup` used to re-run its archive-wide reference scan, under the writer lock, for every key it deleted. Two things change:

- One scan now protects a group of up to 16 keys. Each key still goes through the same steps: proof, delete intent, delete, an absence check, and the final record. If you cancel, keys that were never attempted are released.
- The scan still reads and hashes every file. It no longer re-parses bytes that have not changed.

On a synthetic archive at the customer's scale, 80 keys took about 8 seconds instead of about 269.

## Cleanup items

The manifest is still read in full with the same safety checks. Lines whose bytes did not change are no longer strictly re-validated. On the same synthetic archive, manifest parsing fell from 53 to 33.5 seconds for three items, and the whole cleanup became about 10% faster. The customer's archive spent more time in intake and child steps than the synthetic one. The `work_timing` breakdown in the result will show where the rest goes.

A shortcut that would trust file timestamps for approval records was tested and not shipped.

## Progress

While a long command runs, `operation-control` status now shows how many of the current stage's items are done, for example `progress: {"current": 12, "total": 28}`. activity-cleanup and object-storage-cleanup report their stages and counts to it. If no count is available, `progress` is `null`. Operation journals move to format v0.3, and older journals can still be read.

## Boundaries

All speed figures come from a synthetic archive. The customer's own timings and run are not verified.

## Install after publication

Use the exact public release asset after its hash and size are reported:

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0462-$womBootstrapNonce"
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.62/wom_kit-0.4.62-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require `archive 0.4.62` from a new process, then follow the reviewed `project-version-update` flow for an existing project.
