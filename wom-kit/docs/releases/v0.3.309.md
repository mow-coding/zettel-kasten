# WOM-kit v0.3.309

Letter 116 occurrence, reviewed navigation, and generated-TOC completion.

Status: v0.3.309 implementation and release scope. This source note does not
replace independent CI, exact-tag, GitHub Release, or wheel evidence.

## Added

- binding-manifest v0.2 adds optional, 1-based `occurrence_index` selection for
  a same-digest reference sequence within one zettel;
- repeated same-digest references require complete source-order coverage, while
  the legacy `v0.1` manifest remains readable at its unique-only boundary;
- `zettel_reference` provides a reviewed, navigation-only `wom-zettel:` link
  for a self-closing page mention and does not create an edge; and
- one exact `<unknown:table_of_contents/>` at the immutable original body's
  first nonempty line can be removed, while generated navigation is not materialized.

## Safety boundary

- occurrence indexes are per zettel and per exact digest, not global line
  numbers; mixed, duplicate, missing, out-of-range, stale, and unused selectors
  remain fail-closed;
- a direct zettel target must be unique, readable, schema-valid, canonical, in
  the same archive, different from the source, and valid again at apply time;
- `zettel_reference` is not a relation claim and changes no edge or target zet;
- TOC attributes, alternate spelling or spacing, repetition, later placement,
  indentation, BOM/trailing whitespace, protected code/comment/link/raw-HTML
  contexts, and coexistence with another blocker remain fail-closed;
- bare `callout` and `database`, plus `unknown:synced_block`,
  `unknown:transclusion_reference`, `unknown:transclusion_container`,
  `unknown:column_list`, `unknown:column`, `unknown:link_preview`, and
  `unknown:unsupported`, remain fail-closed because identity or required child
  semantics are absent or unverified; existing paired
  `<synced_block>`/`<synced_block_reference>` inner preservation and
  `<column>/<columns>` structural normalization remain supported;
- blocked zettels remain byte-identical under `--only-ready`, and approved
  writes retain the existing lock, fresh-plan, snapshots, recovery, receipt,
  and exact-byte revert boundaries; and
- there is no provider/network call, credential read, live Notion lookup,
  object-body read, MCP writer, UI change, or canonical beta write.

## Read-only evidence

The reviewed beta snapshot contained 139 exact single TOC placeholders at the
original first nonempty body line: 114 ready and 25 blocked by another
whole-zettel safety rule. The census was read-only and is not an approved apply
or migration receipt.

## Compatibility

Additive manifest v0.2 read support with legacy v0.1 unique-only reads. Existing
unambiguous manifests remain readable. There is no archive migration and no new
CLI command; the change uses the existing markup plan, apply, recovery, and
revert lifecycle.

## Release evidence boundary

Source documentation and local implementation checks are not release proof.
Tag identity, synchronized packaged resources, release CI, wheel inspection,
fresh isolated installation, and the public GitHub artifact remain separate
gates.
