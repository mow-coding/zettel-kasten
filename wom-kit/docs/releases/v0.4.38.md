# WOM-kit v0.4.38 — Finish a reviewed activity

This release combines the two activity-completion reports in one installation. It remains a release candidate until the tagged wheel, public download and fresh installation checks succeed. Installing the tool alone does not change a customer archive.

## Unpublished zet and session scope

`draft-revision-plan` and `draft-revision-write` revise an unpublished inbox zet without creating a replacement ID or publishing it automatically. The original body and creation receipt remain available, and the new body must pass source fidelity and quality checks before a separate mint. Published zets continue to use canonical revision commands. This does not revise a feedback letter that has already been delivered.

`object-storage-scope-list` writes a private exact object list for the current work session or explicitly named other sessions and lists. Authenticated intake, creation, revision, mint and link records contribute only objects used in that session. Search and reading do not assign ownership. Historical activity without trustworthy evidence remains unattributed.

## Preserve, then clean up

The offload default is `--min-age-days 0`, meaning no date filter. An explicitly supplied positive age filter still works and reports its exclusions. Upload returns the exact completed object list for a separate offload command; upload itself does not remove local bytes.

Remote preservation compares the full downloaded body with its object SHA-256 and size, and binds a strong ETag from that response. A later conditional HEAD may reuse proof of the same generation. Weak or missing ETags require another body check. Local bytes need not be restored for staging cleanup when a current remote proof exists.

`activity-cleanup` accepts a private request naming exact files, their role and reason, and the external roots to consider. It inventories Git history, changed and untracked files, secret configuration candidates and linked worktrees. The Windows writer uses official intake, upload, remote verification and offload before deleting a preserved file; explicitly disposable temporary files have a separate reason. Every file has a recoverable state. Changed, new, locked, unverified and unclassified files remain. Directories are removed only after they become empty. Git's read-only object files use Windows' handle-bound disposition with an explicit read-only flag. A valid full-access session opens no extra operation dialog. Other systems support planning but refuse deletion before effects.

## Clarity and performance

Progress logs gain collision-safe names. Error results distinguish a missing credential reference, an unset referenced value, incompatible resume options, missing approval flags and unknown option names without echoing private values. Draft/intake output labels object IDs separately from plan fingerprints.

Quality warnings name the relevant field and table. A directly authored table does not require a fictitious source-row mapping; transcribed and mixed tables do. WOM does not mark a review complete automatically.

Upload, offload and backup status separate local-only, recorded remote and pending offload bytes. R2 Standard cost planning separates monthly storage and request estimates, cites its source and assumptions, and never assumes unused account free quota. Incomplete inventory has no total-cost claim. The project-installed launcher uses verified derived startup caches; the installed wheel and its source remain the package authority.

See the [activity guide](https://github.com/mow-coding/zettel-kasten/blob/v0.4.38/wom-kit/docs/activity-completion.md) for the private request shape and command order. The release uses synthetic development data; customer update and successful use must be confirmed separately.

## Install after publication

Use the exact public release asset after its hash and size are reported:

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0438-$womBootstrapNonce"
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.38/wom_kit-0.4.38-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require `archive 0.4.38` from a new process, then follow the reviewed `project-version-update` flow for an existing project. A bootstrap installation alone does not update its pinned runtime.
