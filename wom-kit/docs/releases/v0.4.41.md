# WOM-kit v0.4.41 — New archives, working Notion recovery, and trash cleanup

v0.4.40 left 19 writers closed until their design was finished. This release finishes most of them. A new user can create an archive again, Notion page recovery works end to end with an adopted credential, recovered pages can move to the Notion trash, and relation accept, external import and credential lifecycle run again. Every writer uses the exact approval contract: one native dialog, or none under a valid `limited`/`allow_all` session grant, bound to the plan its own preview computed. Installing the tool alone does not change a customer archive; use the reviewed `project-version-update` flow for a project.

## New archives (letter 102)

- `onboard --dry-run` prints a `plan_sha256`; `onboard --approve --reviewed-by <you>` creates the archive after one dialog. A new archive has no work session, so the dialog always opens. If the approval record cannot be written, the target folder is returned to absent or empty. Strict Doctor runs and `receipts/onboarding/` records the plan.
- `init --approve` is the same operation. `setup-windows.ps1 -ApproveOnboarding` approves with the Windows `archive` command after the Docker dry-run; Linux and macOS have no approval dialog yet and stop after the dry-run.
- `runtime-skill-install` / `-uninstall --approve --archive-root <archive>` (letters 100-105): the approval is recorded in that archive.

## Notion recovery and trash cleanup (letters 116-119, 142, 148, 156)

- `credential-lifecycle --approve` records the workspace default for an adopted credential. This is what makes an adopted credential usable for recovery; it was closed until now, so recovery could not run for customers.
- `notion-page-recovery-request-build` builds the reviewed request from a private page list; `notion-page-recovery --approve` runs any self-consistent request.
- New `notion-page-trash --dry-run|--approve [--restore]` moves verified-recovered pages to the Notion trash, never a permanent delete; `--restore` moves the pages it trashed back. A page edited in the minute its recovery completed or later is skipped. Each PATCH is journaled and a rerun resumes. The token needs Notion's "Update content" capability.
- `legacy-coordination-cleanup --destination` retires the old `.mow-harness` folder by moving it whole; nothing is deleted.

## More writers reopened

- `relation-candidate-decide --decision accept` (letter 108): one approval covers the edge and the judgment record.
- `import-external --approve` (letter 141): the approval binds the exact items, their source digests and the receipt; a changed export is refused before any dialog.
- `prehashed-objet-ledger --approve` (letters 038-039, 164, 168): records the reviewed prehashed ledger; an invalid ledger is refused before any dialog.
- `notion-objet-link-convert --approve` (feature request 34): one approval covers the converted embed edges.
- `tiro-lossless-recovery-fetch-run --approve` (feature request 13), `add-source --approve` and `imap-mailbox-adapter-manifest-write --approve` run again, each bound to the plan its preview printed.

## Still closed

Eight commands stay fixed closed because they need an owner decision or their own design: the five ZET sharing and ownership commands planned for v0.5 (`delegate-zet`, `transfer-ownership`, `quarantine-foreign-block`, `record-quarantine-decision`, `github-repo`), `imap-mailbox-header-metadata-scan` (its legacy approval receipt no longer exists), the legacy `notion-recover` (use `credential-adopt` and `notion-page-recovery`), and `operation-control`. `wom-kit/docs/closed-command-tracker.md` lists each one. Validation used synthetic development data; a customer update and successful use must be confirmed separately.

## Install after publication

Use the exact public release asset after its hash and size are reported:

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0441-$womBootstrapNonce"
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.41/wom_kit-0.4.41-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require `archive 0.4.41` from a new process, then follow the reviewed `project-version-update` flow for an existing project. A bootstrap installation alone does not update its pinned runtime.
