# WOM-kit v0.4.6 — Exact R2 Bytes Preservation and Formal Adoption

v0.4.6 reopens two bounded R2 recovery modes inside the existing
`object-storage-adopt-existing` command family. It does not reopen the legacy
compound adopt writer and it never treats a copied byte as proof of formal
adoption.

## What changed

- `--preserve-local-only` hashes every selected local-only Objet, binds the
  exact source byte and content-addressed remote key to `ExactOperationManifest
  v1`, and performs PUT only after the operation-specific native approval.
  Existing and newly uploaded bytes require HEAD plus a complete GET rehash.
- Successful emergency copies receive immutable `bytes_preserved` receipts.
  They do not add `wom_uploaded` locations and do not satisfy formal-adoption
  skip logic.
- `--formal-adoption` binds the exact key map, conflict classification, remote
  HEAD evidence, immutable per-object receipts, and one final central-manifest
  projection. It performs zero PUT calls and never auto-merges conflicting
  definitions.
- Both writers share archive-wide locking, append-only checkpoints, exact
  resume, bounded content-free progress, and independent verification. Dry-run
  performs no provider call, credential-value read, or write.
- CLI help and machine capability inventory distinguish these two exact modes
  from the still-closed legacy approval path.

## Full-scale private acceptance evidence

On a full-scale private acceptance snapshot, the released planners accounted
for every manifest row, bound the complete local-only preservation set, kept
all conflicting definitions review-only, and maintained separate
manifest-scope and officially deduplicated remote-evidence metrics. The plan
completed within its release performance budget.

The result was reproduced without provider calls, credential-value reads, or
writes. Exact client counts, object identifiers, keys, digests, and paths
remain only in private acceptance records. They are machine-computed evidence,
not values a person must count.

## Human and client boundary

WOM verifies counts, hashes, source drift, target bindings, provider evidence,
checkpoints, and receipts. The person sees the plain effect and chooses only
the operation-specific action or safe cancel.

Publishing v0.4.6 does not upload client bytes or rewrite a client manifest.
Actual client application happens only when the client runs the project-scoped
released command or explicitly delegates that operation. Until then, the
recovery remains released and verified but not applied.

## Install contract

After the matching GitHub Release exists, install the exact public artifact in
an isolated tool or project runtime:

```powershell
uv tool install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.6/wom_kit-0.4.6-py3-none-any.whl"
archive --version
```

The version check must report `archive 0.4.6`. The versioned URL alone is not
proof that the release asset exists.
