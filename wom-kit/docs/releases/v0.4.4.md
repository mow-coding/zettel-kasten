# WOM-kit v0.4.4 — Human-Centered Execution Confirmation

v0.4.4 corrects a P0 usability flaw in the v0.4.3 native approval surface.
WOM now keeps machine verification and the human decision as two distinct
responsibilities: WOM verifies the complete manifest, counts, hashes, current
canonical state, drift, and post-write evidence; the person decides only
whether to perform the clearly described operation now.

## One real human decision

The primary Windows Task Dialog now provides:

- one operation-specific question in ordinary language;
- one short explanation of the exact effect and what remains untouched;
- one specific action button such as `복구 실행`, `백업 실행`, or
  `업데이트 실행`; and
- a safe cancel path that performs no change.

The dialog no longer asks the person to tick a checkbox claiming that machine
digests or internal review codes were inspected. SHA-256 bindings, warning
codes, and the reviewer label remain available under collapsed technical
details and in durable receipts. They are evidence WOM verifies, not homework
for the operator.

Letter 138 therefore tells the person only that the verified Notion source-
property recovery will update the owned `source_properties` field for exact
matches while leaving unmapped or review-required pages untouched. Any count,
hash, completeness, target-state, or drift mismatch blocks the writer
automatically before mutation.

## Safety and compatibility

This release does not weaken `ExactOperationManifest v1`, expected-byte compare-
and-swap, one-use authenticated claims, writer revalidation, checkpoints,
independent verification, or field-scoped revert. It changes the human surface,
not the machine safety boundary.

New claims record the explicit action-button mechanism. Authenticated v0.4.3
checkbox-and-button claims remain readable only so an interrupted operation can
resume with the same evidence; new approvals do not recreate the old burden.
Private paths, titles, bodies, source values, credentials, and provider data are
not accepted by the dialog API and are absent from both primary and technical
detail surfaces.

Publishing this wheel is not by itself proof that any client archive was changed. A
private client archive remains unchanged until the client runs the released
project-scoped command or explicitly delegates that operation, and completion
still requires durable receipts plus independent verification.

## Install contract

After the matching GitHub Release exists and lists the wheel, install the exact
public artifact in an isolated tool or project runtime:

```powershell
uv tool install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.4/wom_kit-0.4.4-py3-none-any.whl"
archive --version
```

The version check must report `archive 0.4.4`. The versioned URL alone is not
proof that the release asset exists.
