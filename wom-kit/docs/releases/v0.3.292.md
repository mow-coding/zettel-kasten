# WOM-kit v0.3.292: Objet Tie-Count Consistency

Release date: 2026-07-31

## What Changed

v0.3.292 makes the existing overview and catalog objet tie count agree with
canonical structured edge relationships.

Before this release, `zettel-objet-links` could discover an objet target in a
zettel edge while `tie_summary.referenced_objets_count` remained zero. The
link preview scans valid frontmatter and body, but the tie summary used a
narrow frontmatter collector that did not include structured edge targets.

The tie summary now recognizes distinct object IDs from:

- the existing `assets`, `source_refs`, and `source_intake` frontmatter
  structures; and
- canonical edge target fields named exactly `target`, `target_id`, and
  `zettel_id`.

## Exact Target Contract

An edge target contributes only when its complete string value is a
`sha256:<64 hex>` or `objet:sha256:<64 hex>` identifier:

```text
sha256:<64 hexadecimal characters>
objet:sha256:<64 hexadecimal characters>
```

Both forms normalize to lowercase `sha256:<64 hex>`. Repeated occurrences and
aliases count once per digest.

The implementation does not recursively search arbitrary edge metadata.
Values found only in `ref`, `object_id`, `target_object_id`, `edge_id`,
receipts, provenance, URLs, paths, nested metadata, partial digests, suffixed
digests, or zettel targets do not count as structured objet relationships.

Direct edge targets that contain an object-ID marker but do not completely
match the accepted canonical forms are rendered as the fixed
`<redacted-reference>` placeholder in overview and catalog previews. This
includes partial, suffixed, URL/path-contained, uppercase-prefix, and
non-string target values. It prevents a rejected target from being excluded
from the count while still being echoed by the neighboring preview. Valid
object IDs, valid zettel targets, and ordinary safe labels remain visible.

## Two Deliberately Different Counts

The two public counts answer different questions:

```text
tie_summary.referenced_objets_count
  = distinct structured frontmatter objet relationships

zettel-objet-links.count
  = distinct objet IDs discovered across valid frontmatter and body
```

A zettel with structured objet A and B plus body-only objet C therefore has
overview and catalog tie count 2, while `zettel-objet-links.count` is 3.
Catalog output remains `body_read: false`; it does not read or echo the body to
produce its count.

## Privacy Boundary

Redacted overview and catalog surfaces return zero ties, empty edges, and
`body_read: false` before inspecting or exposing private relationship
existence. The new count copies no title, body text, frontmatter value, digest,
path, provider value, or secret into a redacted result.

## Compatibility

No archive migration is required. This release changes no archive schema and
rewrites no zettel.

It adds no command, MCP tool, writer, migration, index rebuild, provider call,
object download, object upload, archive mutation, or beta-archive operation.
`collect_referenced_objets()` retains its prior behavior for block headers,
source-map preservation, and cleanup safety.

## Verification

Release verification is planned against:

- alias normalization and deduplication across every accepted structured
  source;
- malformed, partial, suffixed, nested, URL/path-contained, zettel, and
  non-target edge values, including serialized preview non-echo;
- redacted zero-count and no-private-echo behavior;
- the mixed structured-A/B plus body-only-C scope boundary;
- capability-document contracts and deterministic packaged resources;
- release-readiness and diff checks;
- the complete source suite after rebasing onto the exact public v0.3.291
  predecessor; and
- an exact clean wheel plus PR, main, tag, GitHub Release, anonymous download,
  digest, and fresh-install evidence.

No final test count, wheel SHA-256, remote CI result, tag, GitHub Release,
public artifact result, or beta semantic validation is claimed before that
evidence exists.
