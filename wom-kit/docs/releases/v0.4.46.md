# WOM-kit v0.4.46 — Git backup survives a briefly held index; writer-session coverage complete

Two maintenance fixes. Installing the tool alone does not change a customer archive; use the reviewed `project-version-update` flow for a project.

## Git backup no longer stops when another program briefly holds the Git index

On Windows, a virus scanner or an editor's Git client sometimes opens `.git/index` for a moment. If the backup's exact `git add` ran in that moment, Git stopped at once with "unable to write new index file", and the backup failed with `git_backup_exact_add_failed`. A second Git process holding `index.lock` had the same effect. This was also the recurring hosted-Windows test failure.

- The exact `git add` is now retried up to four times within about four seconds, only for those two fixed conditions.
- Git rolls back its lock in both cases, and adding the same exact paths again gives the same result, so the retry is safe.
- Every other failure stops on the first attempt as before. The commit itself is never retried.
- Git's error text is read only to recognise the condition. It is never shown or stored.

## Writer-session coverage is complete

The coverage list still called 29 writers "pending" session integration. 28 of them already send `--approve` through the approval broker, which since v0.4.36 applies a valid session grant to every kind of operation. They are now recorded as integrated, and a new test traces each command to the broker and proves that nothing on the way forces a dialog. The only forced dialog is creating a new archive, where no grant can exist yet.

`credential-adopt` is recorded as an exception. Its window is where you type the provider secret itself; a grant cannot supply a secret. It is secret entry, not an approval dialog. No command's behaviour changed.

## Install after publication

Use the exact public release asset after its hash and size are reported:

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0446-$womBootstrapNonce"
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.46/wom_kit-0.4.46-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require `archive 0.4.46` from a new process, then follow the reviewed `project-version-update` flow for an existing project. A bootstrap installation alone does not update its pinned runtime.
