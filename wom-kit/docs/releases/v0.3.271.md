# v0.3.271 - Read-Only Title Recovery Decisions

v0.3.271 adds a deterministic, privacy-safe recovery plan for title-remap
transaction journals retained after a hard exit. It does not execute recovery.

## What Changed

- Added CLI-only
  `archive zet-title-remap-recovery-plan <archive-root> --dry-run` and alias
  `title-remap-recovery-plan`.
- Reuses the complete bounded v0.3.270 receipt/journal/lock audit.
- Blocks when the source audit is incomplete or recovery cases are truncated.
- Maps `prepared` to
  `cleanup_unstarted_title_transaction_evidence`.
- Maps `partially_applied` and
  `fully_applied_receipt_missing` to
  `rollback_uncommitted_title_apply_to_before` using already verified
  prior-byte snapshots.
- Maps exactly verified `stale_completed` residue to
  `cleanup_verified_completed_title_evidence`.
- Maps invalid/divergent evidence, invalid snapshots, unverified final
  receipts, and orphaned or invalid common locks to
  `manual_forensic_hold`.
- Distinguishes an absent common lock, which a later executor may reacquire
  after fresh validation and archive-quiescence approval, from an invalid
  present lock, which must be preserved.
- Returns only content-free case SHA-256 handles, counts, fixed codes, source
  audit digest, and complete plan digest.

## Privacy And Write Boundary

The command echoes no title text/hash/length, body text, zet id/path, reviewer,
proposal SHA, evidence path, provider value, secret, or absolute local path.
It calls no provider or model, reads no secret store or environment value,
exposes no MCP method, and writes or deletes nothing.

## Not Yet Implemented

v0.3.271 does not restore canonical bytes, create or remove locks, finalize
receipts, delete journals, resume applies, or revert a completed title change.
A later approval-gated single-case executor remains a separate release, and
approved completed-receipt revert remains a separate design track.
