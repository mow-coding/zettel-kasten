# WOM-kit v0.4.11 — Runtime Truth, Deep Doctor Evidence, and Honest Operator Surfaces

v0.4.11 makes the running project runtime, Doctor evidence, and human-facing
command surfaces agree about what WOM has actually proved. A matching version
number or a successful read-only preview is no longer allowed to stand in for
live process binding or write authority.

## What changed

- **Project runtime alignment is live evidence, not a version-string match.**
  WOM separately verifies the validated installation receipt, a fresh stable hash
  of the installed runtime payload, the installed module inventory, canonical
  launcher bytes, the current executable/module/prefix and isolated Python
  flags, and equality between the project pin and the running version. The
  common write guard uses the same proof. A computer-wide executable that
  merely reports the same version therefore remains
  `project_runtime_mismatch`; the project launcher is the canonical entrypoint.
- **Deep Doctor remains the safe default.**
  Deep mode performs one descriptor-bound stable SHA-256 read for each unique
  objet and rereads current zet text for secret scanning. Operational mode is
  an explicit faster inspection and reports that full byte integrity is not
  verified; `--strict` requires Deep mode. Both modes retain early,
  content-free status and bounded heartbeats.
- **Post-mint byte evolution is accepted only as an exact chronology.**
  Direct zet–objet receipts may explain a historical SHA mismatch only when
  they form one complete, chronological, branch-free, tamper-free chain from
  the mint anchor to the current bytes. Paired canonical/retired findings for
  the same logical mismatch are folded into one diagnostic. Historical local
  recovery can prove an exact `frontmatter.assets` state, but its completion
  chronology is not bound, so that case remains an explicit ERROR rather than
  being softened into success.
- **Native decisions identify their local target in WOM language.**
  Open mint, retirement, edge, and zet–objet approval dialogs use canonical
  `WOM`, `zet`, `오브제`, `발행`, `퇴역`, and `엣지` language and show a small
  local-only target preview derived from the validated plan. `ZET` remains the
  reserved future communication term; it is not substituted into these local
  prompts. Titles, paths, endpoint identities, and relation details are not
  copied into public bindings, receipts, logs, or machine details.
  Unpublished-draft discard remains fixed closed; v0.4.11 does not imply that
  its writer exists.
- **Markdown display no longer turns ordinary ranges into accidental markup.**
  The read-only document view creates a WOM-safe Markdown projection that
  escapes range tildes and unmatched `~~` or `**` while preserving intentional
  strike, bold, inline code, fenced code, indented code, valid link
  destinations and titles, bare URLs, and raw HTML syntax. Canonical zet bytes
  and the body-only read surface remain unchanged.
- **Read-only previews tell the truth before a person invests more work.**
  A shared fixed-close policy keeps revision and discard planning from
  presenting validation digests as approval authority. The self-contained
  check is plainly read-only and works without a redundant `--dry-run` flag.
  Draft creation reports all missing approval prerequisites together, and a
  stale index is described as an index-rebuild requirement rather than as a
  possible duplicate zet. Help, structured status, and the installed wheel are
  checked against the same contract.

## Deliberate limits

The single `zettel-objet-link` path still performs repeated full-tree and full-
manifest authority discovery on a large archive. v0.4.11 does not remove its
identity, duplicate-ID, reparse-point, watcher, or stable-point protections and
does not claim that link latency or incremental index maintenance is solved.
Generation-bound zet and manifest projections, deterministic
`already_present`, writer-wide index lifecycle integration, and distinct stable
failure codes are bounded v0.4.12 work.

An already running older computer-wide executable cannot be intercepted by a
newer project source checkout. Operational Doctor is not byte-integrity proof.
Local-recovery state evidence without bound chronology remains ERROR. Fixed-
closed commands remain closed even when their read-only previews are useful.

## Exact-scale release gate

The v0.4.11 tag and GitHub Release must not be created until the declared
synthetic 22,441-objet / 8,612-zet / 3,345-mint / 3,346-retired fixture proves
both Doctor modes within the release budget, with first status no later than
2 seconds, heartbeat gaps no longer than 10 seconds, no private output, and one
deep hash per unique objet.

The final isolated Windows reference run passed without another Python or
build workload competing for the fixture disk:

- operational: `116.991098s`, first status `0.0s`, maximum heartbeat gap
  `5.0s`, and `0` objet-byte hashes;
- deep: `112.526742s`, first status `0.0s`, maximum heartbeat gap `5.0s`, and
  exactly `22,441` stable hash calls for `22,441` unique objet paths, with a
  maximum of one call per path;
- both modes parsed/scanned each declared manifest stage once, emitted no
  private sentinel, and returned `ok: true`; Deep completion revalidation was
  `current`.

## Client execution boundary

Publishing or installing v0.4.11 does not modify a client archive. Development
uses synthetic archives and isolated installed-wheel checks for release
verification. The specified private Feedback 148 and 149 letters were read
only to scope the work; their bodies and private locations are not copied into
public fixtures or release artifacts. Development does not install the release
into, write, recover, or call a provider for a client archive. After the public
artifact is independently verified, the client updates the intended project's
isolated runtime and runs that project's `.zettel-kasten/bin/archive.cmd`
launcher.

## Install contract

After the matching GitHub Release exists and lists the wheel, install that exact
public artifact in a temporary bootstrap or isolated tool environment:

```powershell
uv tool install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.11/wom_kit-0.4.11-py3-none-any.whl"
archive --version
```

The new process must report exactly `archive 0.4.11`. A version string or URL by
itself is not proof that the release asset was published and verified.
