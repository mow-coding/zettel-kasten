# WOM-kit v0.4.30 — Beta letter 163: mint gate, claim store, audit paging, inbox attention

v0.4.30 answers the core of the client's 2026-09-19 final report (letter
163). A `mint-zet --approve` of a source-fidelity draft no longer fails after
the claim exists: the plan digest is named by the dry-run and checked before
any claim, and a writer failure now names its fixed cause. The `started`
claims such failures left behind can be listed and, after review, closed;
the approval-integrity audit pages per receipt kind; every approved draft
write and session start shows the inbox backlog; `revert-edge` works under
the session permission mode and on inbox drafts; `discard-draft` counts the
edges pointing at the draft; the mint dry-run reports discarded or unknown
edge targets; and `create-draft` blocks a truncated objet reference.

Publishing or installing this release does not read or modify a client
archive. A client chooses when to run the exact public bootstrap and one
reviewed `project-version-update` to the public wheel
`wom_kit-0.4.30-py3-none-any.whl`. The release is not evidence that a client
result was repaired; that requires the client-run result and a new-process
verification.

## Conditional public artifact contract

Use this bootstrap only after the exact GitHub Release exists and lists the
wheel. The versioned URL alone is not proof that the asset is public.

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0430-$womBootstrapNonce"
if (Test-Path -LiteralPath $womBootstrapRoot) {
  throw "WOM bootstrap path must be new."
}
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.30/wom_kit-0.4.30-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require exactly `archive 0.4.30` from a new process. Installing this external
bootstrap does not replace a shared PATH tool or silently update any project.

## What changes

1. **`mint-zet` fidelity gate before the claim (letter 163 ⑤).** The dry-run
   of a source-fidelity draft carries `approval_handoff` (the
   `--expected-source-fidelity-plan-sha256` argument points at
   `/current_source_fidelity_plan_sha256`) and `next_safe_actions`. `--approve`
   compares the argument with the preview before any claim and refuses with
   `mint_source_fidelity_plan_sha256_required`, `_mismatch` or
   `_not_applicable` in `reason_codes`; no orphan claim is created. A failure
   inside the approved writer keeps `mint_service_failed` but adds
   `cause_code` / `cause_stage` (`mint_preflight` or `domain_writer`) and a
   `next_safe_actions` hint; `mint-zet-batch --approve` passes each fidelity
   draft's own digest. The `object_id_only` refusal names the body lines (or
   "in frontmatter") of an incomplete objet reference, never the text. A
   fidelity draft whose body was edited after approval is the warning
   `draft_body_changed_since_approval` (bound into the dialog, so
   `--allow-warnings` is required).
2. **Started-claim listing and finalize (⑥).** `exact-approval-claims`
   (alias `approval-claims`) lists the MAC-verified claim store with fixed
   fields only (`--status`, `--operation`, `--max-claims`); no reviewer id,
   archive id or path is echoed. `exact-approval-claim-finalize --dry-run`
   selects started claims (`--approval-id` or `--all-started`), refuses claims
   younger than `--min-age-minutes` (default 30), `project_version_update`
   claims (use `--resume --abandon-started-approval`) and any claim a receipt
   under the archive names, and prints a `plan_sha256`; `--approve
   --reviewed-by <id> --expected-plan-sha256 <digest>` opens one native
   dialog (`검토 끝난 started 승인 클레임 닫기`, never grantable to a session
   mode), runs under the exact-operation writer lock, re-scans receipts and
   closes each claim as `failed` with
   `operator_closed_started_claim_after_review`, writing one receipt per claim
   (`receipts/exact-human-approvals/claim-finalize/`, schema
   `wom-kit/exact-human-approval-claim-finalize-receipt/v0.1`, write evidence
   declared `receipts_only`). A closed claim is never absence for resume
   discovery.
3. **Audit paging (⑥).** `approval-integrity-audit --kind canonical_mint |
   zettel_edge | retired_draft --offset N` returns a name-ordered page of
   `--max-receipts` receipts with a `page` block (`next_offset`, `exhausted`;
   result schema v0.2). Without `--kind` the v0.1 result and its global cap
   are unchanged.
4. **Inbox attention on write results (⑫).** Approved `mint-zet`,
   `create-draft`, `retire-draft`, their batches and `work-session
   create/claim` carry the `ai-start-here` `inbox_attention` block
   (`unpublished_draft_count`, `oldest_draft_age_days`, `human_summary`);
   dry-run results do not; a counting failure degrades to `status:
   unavailable` and never fails the write.
5. **Edges and drafts (③c, [G], ④c, 11, ⑩).** `revert-edge --approve` takes
   the receipt-bound exact path without `--exact-local` (kept as a no-op), so
   a session grant for `zettel_edge_revert` applies; edge receipts on
   `inbox/` drafts are accepted and a minted source is resolved by id.
   `discard-draft --dry-run` reports `inbound_edge_count` /
   `inbound_edge_scan`, warns `discard_draft_inbound_edges_present` and points
   at `related-zets` (service `plan_sha256` unchanged). The mint dry-run
   reports `edge_target_check` (checked / missing / discarded / index_used)
   with a hint; a gating warning is deferred. `create-draft` blocks
   `draft_body_truncated_objet_reference`.

## Compatibility and privacy

- New commands: `exact-approval-claims` (+ alias), `exact-approval-claim-finalize`;
  new operation kind `exact_approval_claim_finalize` (always-dialog); new
  schemas `approval-integrity-audit-result-v0.2` and
  `exact-human-approval-claim-finalize-receipt-v0.1`; new keys are additive
  on dry-run and write results. The conditional approval scope count drops
  from 11 to 10 (`revert-edge`).
- Behaviour changes to note: a hand-edited fidelity draft now needs
  `--allow-warnings`; batch item failures caused by an OS error report a
  fixed token instead of the error text.
- No path, label, reviewer id, claim reviewer digest, draft content, edge
  type text or archive content is introduced into results, receipts, tests
  or release artifacts.

## Verification boundary

The release candidate must pass the v0.4.30 test modules, the letter-137
audit and revert families, the approval-window and session-mode pins, the
lifecycle batches, the pin sweep and the full supported-platform CI. The
exact reviewed merge commit must be tagged, and the public wheel must be
downloaded anonymously, rehashed, installed in a fresh CPython 3.12
environment and checked in a new process. Those steps prove the public
artifact; they do not prove any client result. Letter 163 closes only on
the client's own runs.
