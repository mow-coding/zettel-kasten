# WOM-kit v0.3.298

Release date: 2026-08-03

## Private exact-indexed objet finder

- Added CLI-only `archive find-objet` for the explicit `private_archive`
  audience. The command is read-only and writes no archive, SQLite, sidecar,
  journal, temporary, receipt, or log file.
- Added separate literal-Unicode and UTF-8 percent-encoded-component query
  profiles, plus argv and bounded stdin transports. No query value is
  reflected, stored, logged, or included in an error.
- Lookup reuses the pinned filename normalizer and performs exact SQLite
  `BINARY` equality against the receipt-bound generated alias index. It
  deduplicates by objet identity and returns only exact-validated stored
  private safe-label projections.
- Added the closed statuses `blocked`, `search_incomplete`,
  `not_found_in_index`, `found`, and `ambiguous`. A
  `not_found_in_index` result proves only that no exact match exists in the
  complete current private index; it is not a global absence claim.
- Added deterministic JSON/text output, fixed serialization fallbacks, exact
  counts and ordering, closed Draft 2020-12 request/result schemas, and
  explicit exit codes: `0` for complete lookup outcomes, `1` for incomplete
  search evidence, and `2` for blocked evidence.
- The finder uses the existing opaque `mode=ro`, `query_only=ON` session and
  one pinned transaction across health, alias lookup, stored projection
  validation, and final snapshot checks. It opens no object bytes and calls no
  provider, network, credential store, external store, or MCP tool.

## Claim boundary

This release adds zero private runtime values to the enumerated public release
surfaces. That narrow evidence does not claim the entire repository is
globally privacy-clean. Existing public privacy cleanup remains the v0.3.302
gate.
