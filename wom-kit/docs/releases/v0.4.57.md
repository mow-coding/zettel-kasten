# WOM-kit v0.4.57 — archived mail as threads

Archived mail is kept as whole `.eml` objets, so every sender, recipient, date and reply header is preserved, but nothing presented a conversation as one. Following the owner's idea, mail can now be read as threads per receiving mailbox account, the way Gmail and other providers show it. Installing the tool alone does not change a customer archive.

## mail-threads

`archive mail-threads <archive-root> --dry-run` reports what a build would produce (counts only). `--build` writes a derived snapshot under `db/mail-threads/<generation>/`: one Markdown record per thread, grouped per mailbox account, listing the participants and every message in date order with its sender, recipients, Cc, date, subject, body text (quoted lines folded; they stay in the objet), attachment names and the mail objet it came from.

- Replies are grouped by the standard Message-ID / In-Reply-To / References headers; mail without them falls back to the same subject (Re:, Fwd:, 답장:, 회신:, 전달: removed) and the same participants. The same message fetched twice is counted once.
- A fetch now records which mailbox account a source reads, privately under `profiles/local/mail-accounts/`; mail fetched earlier is assigned by its own Delivered-To / From / To headers.
- The snapshot is rebuilt from the mail objets and never changes them; old generations are deleted; the folder ignores itself in Git. A conversation worth keeping becomes a zet through the normal draft and mint flow, citing the mail objets. Command output never shows addresses, subjects or bodies.

## Also

The capability documents' version labels that earlier version bumps had rewritten are corrected (operator feedback deletion v0.4.54, system cleanup v0.4.55).

## Boundaries

Validated with synthetic mail (reply chains, a duplicate fetch, mail without threading headers, HTML-only mail, two accounts, an offloaded mail). Real mailboxes from different providers are not yet tested.

## Install after publication

Use the exact public release asset after its hash and size are reported:

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0457-$womBootstrapNonce"
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.57/wom_kit-0.4.57-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require `archive 0.4.57` from a new process, then follow the reviewed `project-version-update` flow for an existing project.
