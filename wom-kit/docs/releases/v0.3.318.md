# WOM-kit v0.3.318

Credential paste guidance, visible receipt, and actionable failure stages.

Status: v0.3.318 implementation and release scope. The source implementation
and local evidence described here are local-only. This note does not prove merge, external CI, exact tag, GitHub Release,
packaged wheel publication, fresh installation, live Notion
credential enrollment, actual physical paste gesture acceptance, beta-client
success, or human acceptance.

## Why this release exists

Letter 131 recorded a real first-enrollment attempt in which the separate black
credential console opened, but the human could not tell whether an invisible
paste had reached WOM. The final `provider_identity_unverified` result also
collapsed several different stages into one code.

The rollback evidence from that attempt matters: WOM had written and then
deleted the temporary exact Credential Manager entry before returning the
provider failure. That means a non-empty value reached the provider-verification
stage. It does not prove which gesture delivered it. v0.3.318 therefore fixes
both the human-visible console feedback and the public stage contract without
adding a clipboard reader or another secret path.

## Masked console interaction

The visible Unicode Windows console now says:

- use `Ctrl+V` or `Shift+Insert`;
- Windows Terminal's default configuration also supports `Ctrl+Shift+V`;
- right-click is host-dependent and may paste, copy, or open a menu; choose
  Paste if a menu appears;
- pasted characters and their length remain hidden; press Enter after pasting;
- during the short prompt `Ctrl+C` is ignored, and empty Enter is the one
  documented cancellation gesture.

When a complete non-empty line arrives, the window displays only:

```text
입력값을 받았습니다. 검증 중입니다.
```

The status remains visible briefly before cleanup. It means only that the
console boundary received a complete line. It does not mean the provider
accepted the credential or that WOM persisted it. The value and its length are
never shown.

WOM uses cooked Unicode console input with echo and virtual-terminal input
disabled. It enables the processed, line, insert, Quick Edit, and extended
input modes required by classic console editing. The prompt temporarily ignores
`Ctrl+C` so the process is not terminated by the default console handler. WOM
detaches the console before restoring any default handler behavior and restores
the prior console mode and code pages. It performs no programmatic clipboard
read.

## Public v0.2 outcomes

The child result envelope is
`wom-credential-secure-intake-result/v0.2`. The adoption workflow envelope is
`wom-credential-workflow-result/v0.2`.

Five fixed public outcomes replace the ambiguous ordinary path:

| Reason code | Stage | Required rollback | Operator meaning |
|---|---|---|---|
| `credential_input_cancelled_or_empty` | before store write | `not_required` | The human submitted an empty line or the intake was cancelled. Create a new plan only when ready. |
| `credential_input_not_received` | before store write | `not_required` | The safe console boundary did not return one complete value. This does not prove which paste gesture worked or failed. Retry a supported method with a new plan. |
| `provider_auth_rejected` | after temporary exact store write | `deleted` or `delete_failed` | Notion rejected the credential. Review the credential before creating a new plan. |
| `provider_identity_endpoint_unavailable` | after temporary exact store write | `deleted` or `delete_failed` | The provider identity service could not be verified. Wait for service recovery, then create a new plan. |
| `reviewed_anchor_inaccessible` | after temporary exact store write | `deleted` or `delete_failed` | The reviewed page could not be verified with this connection. Review page sharing and access before creating a new plan. |

A provider-stage failure cannot claim `not_required`, and a pre-store input
failure cannot claim deletion. `deleted` also requires verified absence of the
exact store entry. A `delete_failed` result takes priority and requires exact
entry cleanup review before any retry. Unknown or custom verifier failures
remain the conservative `provider_identity_unverified` fallback.

These codes and their `operator_action` values contain no PAT, page identifier,
native credential target, private path, provider response, source excerpt, or
derived key. The existing authenticated receipt, exact-store, secret
fingerprint, reviewed-anchor, replacement-plan, and no-prompt reuse boundaries
remain unchanged.

## Evidence and its limits

Focused source/workflow/CLI tests passed 104/104. The latest visible-console
unit set passed 7/7 after immediate wiping of the temporary UTF-16 duplicate was
asserted. The opt-in manual host-check tool has a separate 6/6 unit set.

An actual Windows API canary using only a fixed synthetic value verified:

- input mode `503 -> 499 -> 503`;
- code pages `949 -> 65001 -> 949`;
- `SetConsoleCtrlHandler(TRUE)` only, with no re-enable call while attached;
- successful `FreeConsole` cleanup;
- exact Korean Unicode output without `???`;
- echo and virtual-terminal input disabled;
- the receipt status and dwell;
- no synthetic value reflection in screen, stdout, stderr, or result;
- worker survival after `Ctrl+C`, followed by safe empty-Enter cancellation;
- survival and a public result during a forced cleanup-window race.

This automated evidence drives the console API directly. It does not prove an
actual physical paste gesture under Windows Terminal, classic Console Host,
ConPTY, a remote session, or a customized host.

The opt-in source-tree tool
`wom-kit/tools/check_windows_credential_console_host.py` can record one
human-observed synthetic host attempt. It accepts exact matched host-family and
launch-route pairs plus bounded gesture labels; keeps `automated_win32_boundary_status`
separate from `actual_host_acceptance_status`; uses no real PAT, Credential
Manager entry, provider, private data source, local path, or clipboard API; and
wipes its fixed synthetic buffer. The visible prompt runs in a spawned worker
so the original terminal stays attached; only `(nonempty_bool, exact_bool)`
returns to the parent. For this release-preparation record,
`actual_host_acceptance_status` is `not_performed`.

## Upgrade and compatibility

Start with a new `credential-adopt --dry-run` under the v0.3.318 runtime. Do
not reuse an older request digest. Use the visible console only for first
enrollment or an explicitly reviewed `--replace-existing` operation. A matching
authenticated registration continues to reuse its exact Windows Credential
Manager entry without opening another prompt.

Install only after the exact v0.3.318 GitHub Release exists and lists the
verified `wom_kit-0.3.318-py3-none-any.whl`. Updating source files alone does
not replace an older isolated tool installation. Start a new process and verify
`archive --version` before creating a new plan.

No canonical zet, object store, Notion page, existing authenticated receipt, or
saved credential is rewritten by the upgrade itself. Non-public feedback data
and local locators remain outside the public release.
