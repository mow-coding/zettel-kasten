# WOM-kit v0.4.66 — a conversation's zettel-objet links in its own Git backup

This is the second part of the answer to beta letter 184. A conversation wrote 43 zettel-objet links and could not back them up without mixing in other conversations, because nothing proved the changed zettels were its own. Installing the tool alone does not change a customer archive.

## What a conversation's Git backup now includes

For the conversation whose work-session grant approved the links:

- the changed zettel;
- the link receipt;
- the copy of the zettel taken before the first link;
- the record of which objet the approval linked.

Preview with the same command as before. The result shows `selected_linked_zettel_count` and, if any linked zettel was left out, `linked_zettel_not_selected_count`.

## When a zettel is left out

A zettel is selected only when its pending change is exactly that conversation's links. It stays uncommitted and untouched when:

- it has any other pending edit, made before or after the link;
- another conversation also linked it;
- the link was approved through a window, so the approval carries no conversation mark;
- the saved copy from before the link is missing.

Its link receipt can still be selected.

## How ownership is checked

The approval and the conversation that used it are verified with the archive's own key. The link receipt is not signed, so the zettel change is checked by content: the last committed version must be the recorded "before", the current file the recorded "after", and the only difference the added links. Two receipts that name the same approval prove nothing.

## What stays out

- The objet ledger is one file shared by every conversation. It is backed up only by the archive-wide backup, after the person agrees.
- Receipts of objet registration are not selected yet.
- Objet bytes are never part of a Git backup.

## Boundaries

Verified through the real commands in a temporary Git repository with synthetic files. The customer's archive is not verified.

## Install after publication

Use the exact public release asset after its hash and size are reported:

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0466-$womBootstrapNonce"
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.66/wom_kit-0.4.66-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require `archive 0.4.66` from a new process, then follow the reviewed `project-version-update` flow for an existing project.
