# WOM-kit v0.3.297: Receipt-Bound Private Objet Generated Index

Release date: 2026-08-02

## What Changed

v0.3.297 projects the reviewed v0.3.296 private objet metadata authority into
the existing disposable archive index:

```text
validated private manifest and immutable receipts
  -> exact authority fingerprint
  -> deterministic aliases and audience-safe labels
  -> one public/private SQLite rebuild transaction
  -> content-free private-layer health
```

The generated layer consists of exactly four tables:

- `objet_source_metadata`;
- `objet_name_aliases`;
- `private_objet_label_projections`; and
- the singleton `private_objet_index_metadata`.

The generated database remains a private, disposable cache. The append-only
private manifest and its immutable receipts remain the durable authority.

## Rebuild And Concurrency Boundary

The existing `archive index` command rebuilds both the inherited public tables
and the new private projection in one SQLite transaction and one final commit.
It enables and verifies foreign-key enforcement before the transaction,
validates the exact four-table schema and row-set digests, compares authority
snapshots before and after projection, and inserts the singleton metadata row
last.

On Windows, the rebuild retains the v0.3.296 mutation guard and acquires the
object-manifest persistent lock before the private-metadata persistent lock.
It releases them in reverse order. On non-Windows, it uses exact authority
snapshot A/B comparison without inventing a process-local or lock-file
substitute.

A handled pre-commit failure rolls back and preserves the previous complete
public/private index snapshot. A result, output, or progress failure after a
successful commit returns exit code `1`, but it does not undo or relabel the
committed database. A fresh `archive index-health --dry-run` result is
authoritative.

## Private-Layer Health

The existing `archive index-health` result keeps its 14 inherited top-level
fields and adds one closed 19-key `private_objet_metadata` envelope. It reports
only:

- closed validity, freshness, and index states;
- booleans and bounded counts;
- safe schema/version identifiers; and
- one closed diagnostic code when applicable.

It never emits a private filename, derived label, local path, provider/source
locator, object identifier, receipt, reviewer token, authority fingerprint,
row digest, raw exception, or private canary.

The private health layer distinguishes:

- authority snapshot change;
- authority blocked or invalid;
- database or WAL/SHM projection unavailability;
- whole-index absence;
- missing private tables or singleton;
- present-but-invalid projection;
- valid-but-stale projection;
- exact empty current authority; and
- exact nonempty current authority.

Read inspection uses a pinned `mode=ro` SQLite session with `query_only=ON`.
It does not use `immutable=1`, does not accept a borrowed raw connection, and
does not create a write-capable fallback.

Before opening SQLite, the session compares the database header with the
already-present WAL/SHM pair. A WAL-advertising database without a coherent
pair returns the closed projection-unavailable state before private health or
consumer queries and leaves no new sidecar. An existing coherent
uncheckpointed WAL remains readable.

Schema validation rejects any persisted view or trigger that refers to one of
the private tables, even when the trigger is attached to a public table. When
the stored authority fingerprint matches live authority, health recompiles the
deterministic projection from that authority and exact-compares all rows and
the singleton. Updating rows together with their stored digests therefore
cannot make altered data appear current.

## Compatibility Boundary

This release adds no CLI command, MCP tool, MCP input-schema change, finder,
search result, object-byte read, provider call, credential lookup, external
store scan, or UI surface. The CLI remains at 503 canonical paths and MCP
remains at 121 tools.

Private alias and label rows are generated only from receipt-bound approved
metadata. v0.3.298 will decide how an exact current nonempty projection may be
consumed by the local finder. Until then, the new rows are not a query surface.

## Privacy And Evidence Boundary

Against the sealed v0.3.296 private-policy canary corpus, v0.3.297 adds zero
occurrences across the enumerated public release surfaces. Changed generic
health surfaces also emit zero runtime private canaries or raw private
digests.

Runtime private archive and index artifacts are intentionally private and are
not public release surfaces. This release does not claim that the repository,
wheel, installed package, or historical public tree is globally
privacy-clean. Pre-existing public privacy cleanup remains the v0.3.302
release gate.

Health does not prove objet-byte availability, storage integrity, source
coverage, provider state, remote backup, or external-store completeness.
