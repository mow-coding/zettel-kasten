# WOM-kit v0.3.293: Runtime Guidance Readiness

Release date: 2026-07-31

## What Changed

v0.3.293 adds an explicit, read-only check for whether a Codex repository has
both current WOM runtime Skill material and the legacy repository routing that
an entering AI needs:

```text
archive runtime-guidance-readiness <archive-root> --host codex --scope repo --repo-root <repo-root> --format json
```

The command checks actual local state. Runtime Skill absence and legacy
`AGENTS.md` routing absence have distinct diagnostics. Missing, incomplete,
unreadable, unsafe, or unsupported evidence does not become a false ready
result.

## Explicit Invocation Boundary

Host and scope are required. The only v0.3.293 combination is
`--host codex --scope repo`, and `--repo-root` is required for it. Ordinary
`runtime-context` and `ai-start-here` do not perform this host-specific
inspection. Instead they return:

```text
runtime_guidance_readiness.status: not_checked
runtime_guidance_readiness.host_guidance_consumption: not_proven
```

They also provide the exact explicit check command.

The readiness result redacts local paths, Skill bodies, `AGENTS.md` bodies,
provider values, and secrets. It writes no file, calls no network or provider,
does not access a credential store, does not rewrite `AGENTS.md`, and does not
install a Skill. If the runtime Skill is absent or stale, the only suggested
repair is the exact `runtime-skill-install --dry-run` preview.

Ownership-manifest versions are untrusted local input. The readiness command
and the underlying runtime Skill status surface reuse WOM's exact stable
version policy before projecting `installed_version`. A path-like, sensitive,
partial, prerelease, or otherwise invalid value is never echoed: the public
value is `null`, `installed_version_status` is `invalid_or_untrusted`, and the
Skill state fails closed as `managed_invalid`.

An existing path is not automatically a WOM archive. If `archive.yml` is
missing, unreadable, or lacks a valid archive identity, the command returns a
structured `blocked` result with diagnostic `invalid_archive` and process exit
1. It returns no traceback or absolute path and performs no host/archive write.

File presence and routing anchors do not prove that a host loaded or obeyed
them. Host guidance consumption therefore remains `not_proven`, including
when readiness is otherwise green.

## Operator Feedback Route

Runtime routing now carries one complete, ordered workflow:

1. `operator-feedback-plan --dry-run`
2. `operator-feedback-ledger --dry-run`
3. required human review
4. `operator-feedback-record --dry-run`
5. `operator-feedback-record --approve --reviewed-by <human-actor>`

The route does not read feedback bodies, infer approval, submit externally, or
treat `delivered` as proof of external submission or human receipt. User
knowledge objets are not used as the canonical feedback tracker.

## Compatibility And Verification Boundary

No archive migration is required. No zettel, objet, provider binding, index,
or existing archive `AGENTS.md` is rewritten.
