# WOM-kit v0.4.21 — Reopened Writers And One-Approval Intake

v0.4.21 reopens eight writers that beta letters 157-160 reported as
regressions since the v0.4.0 compound closure, and adds one command that runs
the three-step objet intake under a single exact human approval. Every
reopened write goes through the same operation-specific native approval that
every other v0.4 writer uses: a fresh private preflight, a content-free
binding of the exact plan, one native dialog, and one authenticated one-use
claim that is re-verified before the first byte changes. No new approval
system is introduced and no fixed-closed migration is opened.

Publishing or installing this release does not read or modify a client
archive. A client chooses when to run the exact public bootstrap and one
reviewed `project-version-update` to the public wheel
`wom_kit-0.4.21-py3-none-any.whl`. The release is not evidence that a client
result was repaired; that requires the client-run result and a new-process
verification.

## Conditional public artifact contract

Use this bootstrap only after the exact GitHub Release exists and lists the
wheel. The versioned URL alone is not proof that the asset is public.

```powershell
$womBootstrapNonce = [guid]::NewGuid().ToString("N")
$womBootstrapRoot = Join-Path $env:LOCALAPPDATA "WOM\bootstrap-v0421-$womBootstrapNonce"
if (Test-Path -LiteralPath $womBootstrapRoot) {
  throw "WOM bootstrap path must be new."
}
py -3.12 -m venv $womBootstrapRoot
$womBootstrapPython = (Get-Item -LiteralPath (Join-Path $womBootstrapRoot "Scripts\python.exe")).FullName
& $womBootstrapPython -m pip install "https://github.com/mow-coding/zettel-kasten/releases/download/v0.4.21/wom_kit-0.4.21-py3-none-any.whl"
& "$womBootstrapRoot\Scripts\archive.exe" --version
```

Require exactly `archive 0.4.21` from a new process. Installing this external
bootstrap does not replace a shared PATH tool or silently update any project.

## Reopened writers (letters 157-160)

- `discard-draft` and `discard-draft-restore` accept `--approve` again: the
  discard moves one reviewed draft to its snapshot under exact approval and
  the restore returns the exact snapshot bytes under a second one. Unbound
  service calls and missing reviewers write nothing.
- `zettel-edge-batch`, `mint-zet-batch`, `retire-draft-batch` and
  `revert-batch` accept `--approve` again under one count-first dialog per
  batch. The batch binding covers every item's own single-operation binding;
  the one authenticated claim is re-verified by each item write against the
  batch context, and an item is written only if its fresh binding is an
  approved pair, its exact target is an approved target while only review
  context drifted, or its stable identity is approved and the batch itself
  verified that the only change since the dialog was its own earlier write.
  Each item receipt records which rule matched and the batch receipt embeds
  the batch approval. An empty batch is an
  explicit `nothing_to_write` no-op with no dialog.
- `zet-revision-write` and `zet-revision-restore-write` accept `--approve`
  again. The reviewer's digest protocol (expected proposal and current
  digests, reviewer marker, revision time) is unchanged and is bound into one
  exact approval verified right after the dry-run point against the same
  ready-to-apply document the preview produced; receipts embed the approval
  reference. A reviewer id that is not a safe actor id returns
  `zet_revision_write_reviewer_required`.

## One-approval objet intake (letter 160 ⑦)

`source-intake-chain` takes the same inputs as `source-intake-record` and
`objet-capture-selection` (the reviewed `source-intake --dry-run` plan and one
archive-relative staged path) and replaces the three-dialog
record → selection → capture chain with one exact human approval.

- The dry-run plans all three steps from projected bytes: the intake record's
  receipt bytes are known before they are written, the selection is planned
  from those bytes, and the capture is previewed from the projected selection
  document. It also proves the capture precondition (current archive index)
  so the chain never writes its first two steps into a refused capture.
- The chain is a heterogeneous batch under the same batch authority as the
  reopened batches. Every step re-verifies the chain claim against the chain
  context and proves its fresh binding is an approved item before it writes;
  the record and selection exact-operation receipts bind that claim's
  reference, and the capture receipt carries the chain approval.
- A step failure after an earlier write is reported as `partial` with each
  step's state, the written paths and the single-step command that finishes
  the chain; nothing is rolled back and the claim stays `started` for
  reconciliation. Results list `files_written` (intake receipt, selection,
  capture receipt, object, manifest, index and chain receipt) and never echo
  the staged name, body, operator path or reviewer id.

The parser-derived inventory is 56 approval-available, 60 fixed-closed and

## Compatibility and privacy

- Existing controls, approvals, receipts and schemas keep their exact bytes
  and validators; the operation enum of
  `operation-exact-human-approval-v0.1` and the optional
  `exact_human_approval` object on the discard, batch and revision receipts
  are additive.
- The public projections of reopened writes carry fixed names, counts,
  digests and archive-relative receipt paths, never private values, staged
  names, operator paths or reviewer ids.
- No credential value, provider identifier, archive path, client label or
  target content is introduced into public tests or release artifacts.

## Verification boundary

The release candidate must pass the focused approval, batch, revision,
intake-chain, privacy, package-resource, installed-wheel and full
supported-platform CI checks. The exact reviewed merge commit must be tagged,
and the public wheel must be downloaded anonymously, rehashed, installed in a
fresh CPython 3.12 environment and checked in a new process. Those steps
prove the public artifact; they do not prove any client result.
