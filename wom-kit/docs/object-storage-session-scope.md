# 오브제 작업 범위와 중단된 업로드

상태: 개발 변경. 공개된 버전과 고객 실행 결과는 별도 확인한다.

## 기본과 명시적 위임

업로드·되찾기·비우기는 기본적으로 `WOM_WORK_SESSION_REF`가 가리키는 현재 세션의
반입 근거로 객체를 선택한다. 승인 모드는 창이 필요한지를 정하며 데이터 선택 범위를 확대하지 않는다.
다른 세션의 일도 사용자가 맡길 수 있다. 에이전트는 맡긴 범위를 아래 선택자 중 하나로 표현한다.

| 선택 | 의미 |
|---|---|
| 옵션 없음 / `--this-session` | 현재 프로세스의 세션 참조를 사용. 없거나 근거가 없으면 전체로 확대하지 않고 중단 |
| `--captured-by-session <work_session_ref>` | 사용자가 맡긴 특정 세션의 반입 객체 |
| `--object-list <파일>` | 사용자가 맡긴 정확한 객체 집합. UTF-8, 한 줄에 `sha256:` 객체 ID 하나. 여러 세션의 객체를 함께 선택 가능 |
| `--only <object_id>` | 기존 단건 선택 |
| `--all-sessions` | 사용자가 전체 작업을 맡겼을 때 명시적으로 선택. 다른 세션과 출처 미분류 객체도 포함 가능 |

위 선택자는 서로 섞지 않는다. `--max-objects`는 선택된 집합 안의 처리 상한이며 세션 선택을 대신하지 않는다.
`--local-bytes-only`도 로컬 바이트 유무 조건이지 작업 소유권 조건이 아니다.

자동 세션 선택은 정상 capture 영수증과 인증된 승인 클레임의 세션 제시자 연결에 근거한다.
기록 당시 세션 정보를 남기지 않은 객체, 다른 경로로 만들어진 객체, 단순 조회만 한 객체를
현재 세션이 반입했다고 추정하지 않는다. 이런 과거 자료나 여러 세션을 함께 맡은 경우 정확한 객체 목록을 사용한다.
여러 세션에서 반입·재사용한 동일 객체는 공유 수에 표시한다. 이 선택은 독점 소유권이나 접근 제어를 증명하지 않는다.
비우기는 기존 원격 원본 검증·미발행 초안 보존 조건도 그대로 적용하며 원격 사본은 삭제하지 않는다.

dry-run의 `scope_kind`, `scope_object_count`, `excluded_out_of_scope_count`는 범위 선택 결과다.
`shared_scope_object_count`는 확인한 공유 반입 수이며 전체 사용처 수가 아니다.
실제 처리 대상 수는 업로드/복원/비우기 적격 조건을 거친 수라서 범위 수보다 작을 수 있다.
전체 선택은 `object_storage_all_sessions_explicit` 경고를 표시한다. 다른 세션별 수를 조사하지 않고 추측하지 않는다.

선택 집합과 종류는 계획 지문에 포함하고 재개용 기록에 보존한다. 목록을 바꾸면 새 계획을 검토해야 한다.
재개 도중 환경의 현재 세션이나 목록 파일이 달라져도 이미 승인한 집합을 넓히지 않는다.
과거 범위 없는 전체 계획을 그대로 재개하려면 `--all-sessions`를 명시해야 한다.

## 부분 업로드를 이어가지 않고 끝낼 때

작업이 실제로 멈춘 뒤, 원래 실행의 계획·승인·실행 지문과 검토자 참조를 사용한다.
`object-storage-upload`의 다음 조합으로 먼저 검사하고 동일 선택으로 실행한다.

```text
--expected-manifest-sha256 <원래 계획 지문>
--resume-approval-id <원래 승인 ID>
--resume-execution-sha256 <원래 실행 지문>
--reviewed-by <원래 검토자 참조>
--abandon-started-upload --dry-run
```

기존 명령의 archive와 store 인자를 유지하고, 검사가 통과하면 `--dry-run`을 `--approve`로 바꾼다.
이 경로는 저장소에 접속하지 않고 남은 PUT을 실행하지 않는다. 원래 실행 잠금과 인증된 클레임·체크포인트를
대조한 뒤 해당 started 클레임을 `object_storage_upload_abandoned_with_effects_preserved` 실패 사유로 닫는다.
사본·체크포인트·영수증을 삭제하거나 전송 성공/되돌림을 주장하지 않는다. 새 승인창을 추가하지 않는다.
다른 실행의 체크포인트, 이미 끝난 클레임, 실행 중 잠금은 이 경로로 넘겨짚지 않는다.

그다음 좁힌 새 목록으로 새 계획을 만든다. 원격에 같은 객체가 있으면 새 writer가 크기·해시를 확인한 결과에 따라
재전송을 생략한다. 중단 표시만으로 원격 사본의 정상 상태가 증명되지는 않는다.
쓰기 근거 없는 클레임용 일반 finalize와 부분 효과가 있는 실행의 포기는 서로 다른 절차다.

업로드 진행의 전체 단계 수에는 객체 전송 뒤 저장 목록 투영 단계 하나가 포함된다.
`upload_planned_count`는 객체 수, `execution_step_count`는 이 마지막 단계를 포함한 수다.

## 검증 범위

합성 두 세션·명시 목록·원격 저장소 대역으로 기본 선택, 다른 세션 위임, 범위 밖 바이트 보존,
재개 집합 고정, 부분 효과 보존 후 좁힌 새 계획을 검증한다. 고객 기록이나 실제 클라우드 자산은 테스트에 사용하지 않는다.
모의 승인 창 검사는 실제 고객의 화면 검증과 구분한다.
