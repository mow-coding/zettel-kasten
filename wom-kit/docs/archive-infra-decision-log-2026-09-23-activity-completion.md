# 활동 완료 결정 로그 — 2026-09-23

상태: 사용자 확정, 구현·검증 진행 중. 적용 범위: 활동 종료와 자료 보존 제품 흐름.

- AC-01: 기본 나이 제한 폐지. 0은 날짜 필터 없음이며 날짜 미상도 제외하지 않는다. 명시한 필터는 보존한다.
- AC-02: 세션 범위는 반입과 해당 세션 zet 작업에 실제 사용한 오브제. 단순 열람은 제외, 다른 활동은 명시적 추가.
- AC-03: 미발행 zet 수정은 생성/정본 수정/편지 수정과 구분하며 동일 ID·기존 근거와 이전 본문을 보존한다.
- AC-04: 공식 활동 정리는 외부 파일의 보존·실제 정리·기록까지 담당한다. Windows에서 파일별 실행과 재개를 지원한다. 유효한 전체 액세스에 새 승인 예외를 만들지 않는다.
- AC-05: 원격 전체 바이트 증거와 같은 응답 ETag를 결합한다. 이후 조건부 HEAD로 검증 세대를 확인한다. ETag를 내용 SHA 대신 사용하지 않는다.
- AC-06: 두 피드백을 한 안정판으로 전달하며 설치·공개 검증과 고객 수용을 구분한다.

사용 계약: [활동 완료 안내](activity-completion.md). 자세한 비공개 작업표와 공개 정제 회의록은 각각 별도 보존한다.

- AC-07: 세션 오브제 사용 기록은 성공한 작성기의 실제 반환 근거를 원래 승인에 결합해 MAC으로 인증한다. 유효한 승인 ID만 복사한 임의 영수증은 세션 귀속 증거가 아니다. 옛 미인증 자료는 명시 목록을 사용한다.
- AC-08: 두 큰 Python 모듈의 시작 비용은 검증된 설치 원본에서 만든 deterministic checked-hash 캐시로 줄인다. 실행 시 소스·캐시 지문을 대조하고 전체 설치 검증은 정확한 wheel 원본 및 독립 재컴파일과 비교한다. 도움말 속도만으로 실사용 성능 합격을 주장하지 않는다.
- AC-09: 활동 정리의 하위 업로드·비우기는 원래 manifest·승인·checkpoint를 이어받는다. 후속 목록은 완료한 업로드의 정확한 객체 집합이며 별도 비우기 요청 전에는 삭제하지 않는다.
- AC-10 (위임 범위 내 구현 선택): 세션 사용 근거가 여러 조각이면 전체 조각 수와 ID 목록 지문을 함께 인증한다. 한 조각이 빠지면 부분 목록을 완전한 세션 범위로 사용하지 않는다. 성공 결과의 진단 문장에 나온 ID만으로 오브제 사용을 추정하지 않는다.
- AC-11 (위임 범위 내 구현 선택): Git 내부 읽기 전용 객체도 동일 열린 파일 핸들에서 바이트·파일 정체를 검증한 뒤 Windows `FileDispositionInfoEx`의 읽기 전용 삭제 플래그로 처리한다. 다른 worktree 연결은 정리 직전 다시 확인한다. 선택하지 않은 Git 파일이나 새 파일이 남으면 폴더 전체 완료로 표시하지 않는다. [Windows 삭제 플래그 근거](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddk/ns-ntddk-_file_disposition_information_ex).
- AC-12 (위임 범위 내 구현 선택): 충돌하는 객체 크기나 잘린 목록의 용량은 알려진 바이트 하한만 표시한다. 전체 비용은 미확정으로 표시하며 계정 무료 할당량을 추측해 빼지 않는다. [R2 요금 근거](https://developers.cloudflare.com/r2/pricing/).
- AC-13 (위임 범위 내 출시 선택): 새 기능 네 개에 맞춰 현재 버전 안내, 공급 잠금 및 명령 목록 검사를 같은 후보에서 갱신한다. 과거 릴리스 노트와 기존 잠금 파일은 이력으로 보존한다. 설치 성능은 합성 자료의 공식 런처에서 첫 실행과 이후 반복 새 프로세스를 분리하고, 실제 고객 PC 성능으로 일반화하지 않는다.
